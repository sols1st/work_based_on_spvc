## 先用一分钟看懂当前进度

我们研究的是自动紧急制动：车接近前方障碍物时，控制器根据图像和速度决定加速还是刹车。当前已经完成四件关键工作：

1. 依照原SPVC的截图方式采集并检查了 **24,000张图像**，其中训练和验证图像的DINO特征已缓存。
2. 训练出一套 **32维的共同表示**：真实图像走DINO路径，已知物理距离走小网络`q`路径，两条路径尽量把同一个场景映射到接近的位置。验证集相对表示误差由早期R0的 **78.89%** 降至R2的 **约7.63%**。
3. 用R2表示重新训练PPO控制器。训练图片库回放和30条原截图协议的在线开发轨迹取得了好的控制结果；同时确认图像路径与代理路径仍有动作差。
4. 做了两类安全分析：冻结旧PPO的轨迹屏障评分经过第21步CP校准；第22步采用原SPVC训练流程得到代理路径窄带 **0/69** 硬违反。它们的保证范围不同，尚不能合起来称为真实图像闭环的完整SBC证书。

**第23步精确配对诊断已完成。** 训练集检查371,160个图像/代理配对、验证集检查147,240个配对；两集合中均未发现“旧策略单步安全、新策略单步不安全”的新增案例。第22步更新前后，验证集双路径动作MAE约`0.119587 → 0.119424`。这只是已有图片上的单步开发诊断；下一步仍需同协议在线闭环比较。

## 一、任务到底是什么

AEBS是自动紧急制动系统。当前简化任务只看两个物理量：

- `d`：车辆到障碍物的距离，单位米；
- `v`：车速，单位米/秒。

控制器输出动作`a∈[-3,3]`。在本模型里，正数表示制动，负数表示加速。每隔`0.05`秒更新一次：

```text
下一距离 = 当前距离 − 0.05 × 当前速度
下一速度 = clip(当前速度 − 0.05 × 动作, 0, 3)
```

`clip`表示把速度限制在0到3之间。实验通常从距离15～16米、速度2.5～3米/秒的初始区域出发；一次回合最长400步，相当于20秒。

本任务把 **距离不大于6米、同时速度大于0.5米/秒** 定义为`unsafe`。这是一条实验安全条件，不表示日志里每次`unsafe`都真的发生了实体碰撞。进入目标距离且速度足够低是`success`；停在目标外、跑出建模区域和超时需要分别统计。

CARLA在这条主线中主要提供视觉画面，车辆状态由上述AEBS公式推进。因此，目前还不能说已经验证了CARLA车辆的完整物理系统，更不能直接推广到真实道路。

## 二、目前的完整框架

### 2.1 真正用图像控制时，信息怎样流动

```text
原SPVC方式取得的RGB图像 ─→ 冻结DINO ─→ 384维特征
                                             ↓
                                      学到的投影网络
                                             ↓
                                      32维图像表示 z_img ─┐
                                                           ├→ PPO → 动作a
                                             当前速度v ────┘         ↓
                                                     AEBS状态更新 → 下一状态
```

图中的PPO是强化学习控制器。它学的是“看到这种输入应输出什么动作”。DINO是预先训练的视觉特征提取模型，当前保持冻结；我们训练了它后面的小投影网络，使视觉信息变成对制动控制有用的32个数字。

这里的`latent`就是“网络内部的数字表示”。**32维不是32米，也不是32种人工定义的距离；它是32个共同学习的特征。** PPO还接收一个真实速度值，所以输入总共33维。当前实验没有宣称从单张图像估计出速度。

### 2.2 为什么另外还要有一条物理代理路径

```text
已知物理距离d ─→ 按R2尺度归一化 ─→ 小网络 q ─→ 32维代理表示 z_q
                                                        ↓
                                              同一个PPO，加上速度v
```

训练和验证安全条件时，需要检查很多物理状态。对每个连续的距离都实时生成准确图像、再把大型DINO放进数学验证，当前代价很高。因此用小网络`q`根据距离生成与图像表示接近的代理表示。

`q`只是这条物理代理网络的名字，**不是强化学习里的Q函数**。距离归一化仅为处理输入单位；部署路径的表示仍是32维，没有退回一维距离头。

两条路径共享PPO，但`z_img`与`z_q`不会完全一样。这个差别可能改变动作，所以“代理路径上的屏障检查通过”不能自动证明“真实图像路径安全”。理解这一点，是当前整条研究线的关键。

### 2.3 SBC和CP放在哪里

```text
图像/代理表示 → PPO → 动作 → 下一物理状态
                              │
                              └→ 离线检查屏障函数 B(d,v) 和轨迹分数
                                                        ↓
                                              按指定实验协议做统计校准
```

`B(d,v)`是**SBC候选屏障函数**：它给每个距离和速度状态分配一个数，试图让初始区的数较低、不安全区的数较高，并满足适当的动态条件。这个数不是车辆实时使用的刹车命令，也不天然等于事故概率。

`CP`是**保形预测**：用事先保留的轨迹数据给某个误差或分数设统计阈值。它的结论依赖采样协议与数据独立性。当前系统运行时没有CP模块直接改动作，也没有接入以前试过的QP或safety filter。

### 2.4 两条安全实验分支不能拼成一条已完成证明

```text
共同基础：R2表示 + 原R2-PPO（第09步）
           │
           ├→ 分支A：旧PPO冻结 → 轨迹SBC v1/v2/v3 → 第21步轨迹CP
           │                                      └→ 有条件的400步统计证据
           │
           └→ 分支B：原SPVC交替训练PPO和新SBC → 第22步窄带/宽域检查
                                                     └→ 代理路径的检查结果
```

分支B会更新PPO，因此不能直接把分支A针对旧策略校准出的99%覆盖结论拿来套到第22步策略上。第23步之所以先比较新旧PPO，就是为了搞清楚这种更新对图像控制行为造成了什么变化。

## 三、数据是怎么来的，为什么要重做

原始数据收集方式决定图像里车的大小、位置和背景。曾尝试更换相机/地图采集，结果用户发现近距离车辆构图与原SPVC不一致。当前主线恢复用户认可的`spvc_carla.py`截图方式，只扩展距离和外观，不把不兼容采集混作同一数据集。

现有扩展数据覆盖约2,000条距离记录、4种天气、3种车色，合计 **24,000张图片**。文件审计显示24,000张均能解码，未发现跨集合重复的距离分组。按距离组划分，而不是把同距离不同天气的配对图片随机分到训练和测试两边：

| 数据用途 | 图片数 | 当前使用方式 |
|---|---:|---|
| 训练 | 14,172 | 学投影网络、q网络与PPO |
| 验证 | 4,908 | 选模型和开发诊断 |
| 测试 | 4,920 | 留给最终评价，当前主线未报告最终测试结果 |

同一个距离可以有12种外观，因此24,000张图片不等于24,000个独立物理状态。当前也没有多地图泛化实验。

训练和验证共19,080张图片已通过冻结DINO提取384维特征，保存为H5文件。H5只是方便读取的数据文件格式；384维到32维的“降维”发生在后续学习到的投影网络里。

## 四、表示学习：两条路径怎样逐步变得一致

问题是：图像看上去不同，但车辆离障碍物一样远，两个表示应该尽量接近；距离差很大时又要能区分。若只要求“接近”，网络可能把所有图片映射成同一个常数，所以训练还检查距离信息和不同状态的区分能力。

| 阶段 | 主要改变 | 验证相对latent误差 | 图像辅助距离RMSE |
|---|---|---:|---:|
| R0 | 早期单外观训练 | 78.89% | 2.0669米 |
| R1 | 用全部训练外观参与对齐 | 8.70% | 0.2402米 |
| R2 | 进一步加强同距离不同外观的配对一致性 | 约7.63% | 约0.2138米 |

“相对latent误差”是双路径32维输出差异除以表示本身的变化尺度，**不是安全失败率**。RMSE是辅助任务中距离估计的均方根误差，也不是PPO实际控制误差。

R2整体优于R1：验证集误差的P95由约0.6477降至0.5948。但最坏单样本的latent差由约1.2887升至1.3789；所以平均和大多数样本改善，不代表所有困难场景都改善。

这一阶段解决了“图像与物理代理差太大，PPO和证书无法共用表示”的主要障碍，但没有把两条路径做成数学上完全相等。

### 4.1 相对原cGAN图像生成路线，误差改善在哪里

原SPVC的代理链条需要先用cGAN从物理状态**生成一张图像**，再由旧状态网络读取图像，把信息送给控制器；生成图与真实图不完全一样，读取网络还会引入自己的误差。当前方案不再为代理路径合成整张图片：真实图像经冻结DINO和投影网络得到`z_img`，物理距离经小网络得到`z_q`，训练时直接让两条32维表示接近。通俗地说，原方案要求“先画得像，再读得准”；当前方案直接要求“控制器看到的关键数字尽量一致”。少了一次图像重建，是**可能提高下游控制准确度**的机制，而不是已经自动成立的安全保证。

现有数字分别说明不同事情，不能只看数值大小：

| 方案和测量对象 | 已有结果 | 能说明什么 |
|---|---:|---|
| 原cGAN生成图相对目标图，32×32归一化像素RMSE | `0.03924` | 生成图片与目标图片有误差；这是图像像素单位 |
| 原cGAN生成图经旧状态网络后的距离RMSE | `0.4724米` | 旧代理链条输出距离与标签的差异 |
| 当前R2两条latent路径的验证相对RMSE | `7.63%` | 同一场景的图像表示与物理代理表示差异，不能与像素RMSE直接比 |
| 当前R2图像辅助距离头的验证RMSE | `0.2138米` | 一个与旧距离RMSE**单位相同**的辅助任务读数，数值较小 |

因此，可以说：**当前DINO双路径的表示误差已明显缩小，且现有辅助距离误差数值低于旧cGAN代理链条的距离误差；这支持“有望带来更准确控制输入”的方向。** 但不能写成“`7.63% < 0.03924`，所以DINO一定比cGAN准确”：前者是latent相对误差，后者是像素误差，单位和定义都不同。两个距离RMSE也分别来自**R2验证集4,908张图像**与**原cGAN训练时使用的400张图像**，不是同一测试集上的公平A/B比较。要证明新方法确实比原方案准确，还须在相同图片、状态、控制器和数据划分下，比较共同的距离误差、动作误差以及闭环结果。

上述旧cGAN数字来自[旧图像误差记录](../../artical-F122/results/legacy_cgan_image_error/metrics.json)，R2数字来自[R2表示实验](../../artical-F122/results/dino_expanded_v1/08_R2_group_alignment/metrics.json)。

## 五、PPO控制：从图像库失败到R2控制器

PPO必须适配当前表示。R0、R1、R2的latent坐标不同，把旧PPO直接拿来使用可能产生错误动作，所以表示确定后重新训练了控制器。

### 5.1 为什么曾经出现图像路径失败

训练图片库回放里，系统用**当前距离的标签**从已有图片中找最近的一张，再取它的latent给PPO。R1旧PPO在12种训练外观合计4,800个回放起点里有10次不安全。最近邻图片有时对应略远的距离，使控制器看到的车像“还没那么近”。

为了定位问题，用相邻图片latent做距离插值后，原来的10/4,800降为0/4,800；这说明图片检索误差是重要因素。但插值依赖真实距离标签，不能把它当作实际部署时天然可用的视觉方案。

再做“精确配对单步检查”：把每张图片放在它自己的标注距离上，同时比较图像表示和代理表示给出的动作。这样检索距离误差是0，R1在训练数据上仍有3例“只有图像动作使下一步unsafe”。这表明仅修检索也不足够，还需要关注双路径残差以及PPO在安全边界的动作敏感性。

### 5.2 控制器改进与R2结果

在R1上曾试过用训练集经验表示误差扰动PPO，图片库回放改善，精确配对图像独有失败由3例降到1例，但控制动作并非全部指标改善。这是开发过程中的一次尝试，不是当前最终表示。

R2表示确定后又从头训练适配它的新PPO。已有开发结果显示：

- 代理`q`路径及12种训练外观最近邻回放，各自的400个起点均成功；
- 训练图片的精确配对“图像独有下一步unsafe”降为0；
- 验证图片的双路径动作平均绝对差约0.11959，未发现图像独有下一步unsafe。

“MAE”就是平均绝对误差，此处指两条路径在同一状态下输出的动作平均差。单步配对检查覆盖很多样本，但它不能代替整回合在线闭环结果。验证数据也已参与开发判断，不能再称为完全未触碰的最终测试。

## 六、在线开发轨迹与误差校准

第一次用Town10和`camera.rgb`跑的459条校准轨迹与原训练截图协议不一致，出现182条unsafe、误差半径达到0.3米/秒。项目将其作为**采集协议变化后的失败案例**保存，没有放入当前主结论。

恢复原SPVC全屏截图协议后，30条在线开发轨迹全部成功。这里每一步由当时的视觉画面进入控制器，形成在线观察与动作的闭环；物理状态仍按AEBS简化公式推进。30/30说明该开发条件下跑通，不能单靠30条推断高置信度安全。

同批开发轨迹的图像/代理动作MAE约0.180，最大动作差约2.729。最大差提醒我们：动作平均相近，仍可能出现少数不同的制动决定。

随后按登记协议采集459条轨迹，针对每条轨迹的**最大下一速度差**做CP校准，得到阈值`0.150685468 m/s`，输出置信度约`0.990079`、目标覆盖率99%。这个数的单位是米/秒，描述两条路径的下一状态可能差多少；它本身不是安全概率，也不能单独证明车会安全停下。

## 七、为什么“把CP误差加到每一步”失败

曾尝试把`±0.150685468 m/s`当成一个全局误差盒：无论当前状态是什么，每一步都允许任选盒中的误差，并要求SBC在每种选择下都成立。结果在8910个被检查的状态中，下降条件有8884个违反；初始区和不安全区的边界条件也有违反。

这并非只差几个训练轮次。一个具体压力测试从400个初始状态出发，若每一步都叠加盒中最大的正误差，400条轨迹全部进入不安全区。最大制动动作3.0在0.05秒内名义减速`0.15 m/s`，而盒子允许每步加回`0.150685468 m/s`，抽象模型中制动可被持续抵消。

后来按动作大小分12组，最大制动组的正误差仍接近`0.147900537 m/s`；重复施加组内极值，400个起点仍全部不安全。这说明仅按动作分组没有解决问题。

**这些是“允许最坏误差每步重复”的抽象模型中的失败轨迹。** 结果说明这个全局鲁棒要求对当前控制器不可行，不能说明真实图像系统在同样400条轨迹中全部失败。这里也不能用原SPVC的“随机误差下平均下降”替代“误差盒内每种情况都下降”：两者要求不同。

## 八、轨迹屏障函数B：v1到v3解决了什么

前一条路线要求全局误差盒内所有可能序列都安全。之后改用真实采到的轨迹，训练一个状态函数`B(d,v)`：希望初始状态的B小、不安全状态的B大，同时已观察到的安全转移上B尽量不增加。旧459条轨迹被用于开发训练/验证，按整条轨迹做80%/20%划分，避免同一轨迹前后步骤被当作独立样本分到两边。

| 版本 | 主要变化 | 开发结果 | 说明 |
|---|---|---|---|
| v1 | 初始低、不安全高、观测转移不增加 | 验证转移7434/7453违反，约99.75% | B沿安全轨迹上升，训练目标不够 |
| v2 | 强化安全轨迹上的B保持低值 | 验证转移458/7453违反，约6.15%；不安全网格仍有5点违反 | 大幅改善，边界仍未过 |
| v3 | 加强不安全边界附近样本与目标 | 验证转移131/7453违反，约1.76%；初始/不安全区网格0违反 | 区域分开，动态条件仍未全过 |

v3不安全区网格最小B约1.529；验证转移最坏下降差约`−6.57×10⁻⁵`。这个数字很小，但不能直接写成“误差为零”或“已经有严格SBC”。它仍是开发数据上的软损失训练结果，不能套用另一篇论文“最后一层线性规划scenario方法”的PAC证明。

还有一个数据检查事项：训练脚本用保存状态的相邻行当作转移。若采集器在终止动作后立即停止，可能漏掉每条轨迹最后一步。因此，必须用实际动作重建终止后继并核对保存的结果；不能仅凭训练转移里没看到unsafe就说整条轨迹没有unsafe。

## 九、第21步：冻结旧策略后的轨迹CP结果

冻结当时的R2表示、旧PPO和v3屏障后，另用459条新轨迹计算每条轨迹的屏障分数：

```text
分数 = 初始B值 + 途中所有正向B增量之和 − 1
```

它的意思是：从起点风险值出发，把途中每次朝危险方向的上涨都加起来，最后看是否仍低于危险阈值1。对完整、一致的停止轨迹，进入不安全区时分数应不小于0；因此分数小于0排除了该条轨迹进入指定不安全集合。

用户回传的结果是：459条均为success；分数中位数`−0.999996638`、P95为`−0.999907858`、最大值`−0.999807990`。CP阈值`q_hat=−0.999807990`，严格小于0；脚本状态为`trajectory_sbc_cp_safety_pass`。另外，`400×每条轨迹最大单步正增量`的保守评分阈值也小于0。

如果采集前冻结、完整轨迹、独立同分布、无挑选轨迹等前提经核验成立，这支持**在登记采集分布和400步范围内**：“以至少99%置信度，新轨迹避免规定不安全集合的概率至少99%”。这是概率和置信度两层意思：不是“事故概率已经精确测量为0”，也不是“任意地图、任意起点都保证99%”。这里报告的99%是安全事件，不自动是任务成功率。

需要注意，脚本在安全终止时把B设为0、在不安全时设为1。这使轨迹分数有可解释的事件关系，但不证明原神经B在所有连续状态上满足SPVC的条件期望下降。第21步结果还应与“459条都成功时直接做二项统计”比较，说明屏障函数究竟额外提供了什么。

## 十、第22步：原SPVC同口径训练与范围对照

另一条分支从R2-PPO出发，沿用本地原SPVC的SBC/PPO交替训练、AEBS动力学、均匀噪声、100×100网格和原检查器。主要替换是：原前端的cGAN/状态估计网络被DINO图像路径和小网络q代理路径替代。因q与原环境使用不同的距离归一化尺度，接入时作了明确的单位转换。

这一步保存了**新PPO和新SBC**，不能把它与第21步旧PPO及v3屏障当作同一套模型。结果采用相同最终checkpoint做三个范围的对照：

| 检查范围 | 实际检查点数 | 硬违反 | 加入代码中网格补偿后的违反 |
|---|---:|---:|---:|
| 原SPVC窄带 | 69/10000 | 0/69 | 1 |
| 不安全阈值以下的安全区域 | 1332/10000 | 103/1332 | 162 |
| 全部安全网格 | 9253/10000 | 109/9253 | 356 |

“窄带”指 **B值接近不安全区屏障下界**，不一定是物理距离上很窄的一条区域。原检查器先生成10000个网格点，再筛选，因此`0/69`的含义是“69个被选点里零硬违反”，不是全部10000个点零违反。

初始区B上界`1.307321`，不安全区B下界`20.039461`，全域B下界`0.405764`，次序正确。仅根据这些区域值可计算出`0.954081128`的比率；**不能单凭它写成“已证明安全概率至少95.41%”**，因为动态条件和图像路径误差尚未完整闭合。

这次对照回答了一个重要问题：R2代理模型在原实现的窄带检查口径下能够取得正面结果；但同一模型扩大检查范围后会出现违反。窄带补偿后仍有1个违反，连续域证明也未完成。这是候选屏障和实现口径的结果，不等于原论文理论条件全部成立。

## 十一、第23步检查了什么

原SPVC交替训练可能改变PPO动作。为了知道第22步的安全检查是否以控制质量退化为代价，已写出“旧PPO09 vs 新PPO22”的精确图片配对程序：对train和validation每张图片的自身距离标签、相同速度，比较旧图像、旧q、新图像、新q四种动作，并计算每种动作的单步结果。

它特别统计“旧策略该步未unsafe，新策略该步变unsafe”的样本；即使新图像和新q彼此一致，也不能掩盖两条路径共同退化。运行前还会核对checkpoint哈希、q参数、动作加载一致性和距离单位转换。

首次运行因不同float32距离归一化顺序产生约`1.66893×10⁻⁵`的动作差，在加载自检阶段停止；分开“同输入加载检查”和“跨坐标舍入诊断”后，复跑通过。旧新actor有6个参数张量不同，确认第22步确实更新了策略。训练集371,160个配对的双路径动作MAE为`0.019848 → 0.019897`，验证集147,240个配对为`0.119587 → 0.119424`。两集合的“新unsafe、旧不unsafe”与相反方向计数均为0。训练集仍有5,328个检查状态在新旧策略下都出现双路径共同单步unsafe；这是静态检查点数，不是在线事故回合数，也不能未经分析就称这些状态物理不可恢复。

该程序给出的是精确图片标签处的单步开发诊断，不是CARLA逐步实时图像的完整回合评价；若通过，还需要同协议在线回放。

### 为何现在不能把所有“好数字”相加

R2表示误差约7.63%、第21步99%覆盖、第22步区域比率95.41%，各自测量的对象不同，模型版本也可能不同。它们既不能相加、也不能相乘成一个“最终安全率”。第21步CP评价的是冻结旧策略的轨迹分数；第22步是代理路径上新策略的屏障检查；第23步正在核对新策略的图像动作。

## 十三、接下来按什么顺序做

1. **完成第24步同协议在线新旧策略配对回放。** 在相同原截图协议、初始条件和外观下比较第22步新旧PPO的success、unsafe、timeout及步数；第23步精确图片单步检查不能替代它。
2. **核对模型身份与完整产物。** 保存第21、22步的`metrics.json`、登记文件、checkpoint哈希和对应数据版本，核对第21步轨迹末步、结果标签与评分程序的一致性。
3. **评估第22步最终PPO的原协议图像在线闭环。** 用相同开发初始条件与外观比较旧策略和新策略，报告success、unsafe、timeout及步数；避免用图片库回放替代在线效果。
4. **明确想证明什么。** 若目标是原SPVC式SBC，需要对同一最终策略补齐条件随机模型、规定区域内的下降验证、连续域界和图像误差传递。若目标是有限时域统计安全，应固定模型与评分规则，严谨核验独立轨迹校准，并与直接统计unsafe结果比较。
5. **最后使用保留的test。** 所有开发决策固定后再做最终评价，并明确采集协议、状态范围和时间范围；不把开发集结果当最终测试。

第22/23步结果与跳板同步命令见[实验文档](R2_DINO原版SPVC最小替换实验.md)。本文是当前状态说明，不代替该文档中的可执行命令。

## 十四、常见术语速查

| 术语 | 在本项目中是什么意思 |
|---|---|
| 闭环 | 图像/状态送控制器、执行动作、更新状态、再产生下一次观察，反复循环 |
| DINO | 已训练好的视觉特征提取模型；当前冻结其权重 |
| latent/表示 | 从图像或物理距离得到的32个内部数字，交给PPO使用 |
| q代理 | 将物理距离映射到同一latent空间的小网络；不是强化学习Q函数 |
| PPO | 从输入表示和速度输出制动动作的强化学习控制器 |
| SBC/屏障 | 给物理状态打数值的候选安全论证函数；必须满足相应条件才能形成证书 |
| CP/保形预测 | 用预留样本给误差或轨迹分数建立具有明确条件的统计覆盖阈值 |
| 契约 | 规定误差覆盖范围、概率、采样条件和适用模型的一份约束说明 |
| 硬违反 | 按检查器规则，某个状态不满足要求的屏障不等式；不等于真实碰撞 |
| 网格补偿 | 尝试把网格中心检查扩展到网格之间的项；需要界本身可信才能用于连续域证明 |
| 精确配对 | 图像与物理代理比较时使用同一张图像自己的距离标签，避免图片检索距离误差 |
| 最近邻回放 | 在已有图片库中按距离找最接近的一张图供闭环使用；不是CARLA实时生成图像 |
| 在线开发轨迹 | 实验运行中逐步取视觉画面并输出动作；仍使用当前简化AEBS状态更新 |
| train/validation/test | 训练、开发判断、最后独立评价；当前test尚未用于主线最终结论 |
| MAE | 平均绝对误差，例如同一状态下两种动作平均差多少 |
| P95 | 有95%的样本不超过该数值；仍有较差的尾部样本 |
| `q_hat` | CP校准得出的阈值；不同实验可能有不同单位，不能互换 |
| checkpoint | 保存的模型权重文件；必须和表示、PPO、屏障及数据版本对应 |
