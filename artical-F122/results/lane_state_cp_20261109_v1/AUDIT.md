# 车道状态相关 CP 包：审计与撤回

2026-11-09。**状态：withdrawn / unverified。不要把本包的数字作为 CP 或安全结论引用。**

## 发现的问题

1. **报告与附带脚本不一致。**
   - `state_cp.json` 声称 degree-1、4 个系数、199 条轨迹拟合、cap 0.0992。
   - `source_snapshot/fit_lane_state_cp.py` 实际是 degree-2、9 个系数、99 条拟合 + 100 条校准、无 cap，并用 `np.quantile` 而不是有限样本 CP 秩。
   - 因此报告不是该脚本的产物，缺少可复现依据。

2. **留出分数用了校准残差。**
   - `score(idx, data, states_all)` 没有使用 `data`；第 31 行始终读取全局 `res[idx]`（校准残差）。
   - 所以“留出覆盖率”不是留出轨迹的覆盖率。

3. **不满足标准 split CP。**
   - 同一批 199 条轨迹既拟合 `b(e,θ)` 又取分位数，缺少独立校准。
   - 执行 `min(q·b, 0.0992)` 会缩小集合，原覆盖保证不能自动保留。
   - SBC 在 0.0992 盒上通过只证明盒内安全，不证明视觉误差有足够概率落入盒内。

4. **当前仍有效的部分。**
   - `verification_at_max/certificate.json` 只说明：在常量 0.0992 盒上，SBC 通过。
   - 它不证明状态相关 CP 的统计覆盖，也不证明状态盒是有效的 95% CP 盒。

## 处理

- 本包保留作失败审计记录，不作为当前结果。
- 当前车道主结果仍是常量轨迹 CP **0.0900931580** + 原 SBC 审计。
- 若要重做状态相关 CP：用独立拟合集、独立校准集、有限样本 CP 秩、固定 cap 之前先冻结合同，并对留出数据重新计算残差。
