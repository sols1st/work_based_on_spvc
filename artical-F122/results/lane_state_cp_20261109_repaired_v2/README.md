# 车道状态相关误差包络：修复版 v2

2026-11-09。旧 `lane_state_cp_20261109_v1` 已撤回；本包重新拟合、校准和验证，保留旧包追溯，不恢复旧报告的数字或保证。原 0.090093 常量盒主结果不变。

**本地与服务器 conda vt 均已通过实际状态相关集合的神经 SBC 数值验证。** 无半径截断，actor/SBC/视觉前端权重未改。它仍是固定状态观测映射的实验，不是联合学习视觉投影和 C 的新前端。

## 修复了什么

1. 从原 199 条轨迹中固定取前 99 条拟合尺度，后 100 条校准；轨迹索引不重叠。不能把一条轨迹拆成“独立帧”。
2. 留出分数只读取留出数据自身的 errors，修复了旧脚本误取全局校准残差的问题。
3. 明确唯一基函数定义：先将物理状态变成 `(e/0.85,theta/0.30)`，再映射到 `[0,1]^2`；系数顺序是 00、01、10、11。用 degree-1 张量 Bernstein 拟合正尺度。出域状态采用截断坐标延拓，仍保留其误差记录，不删除失败轨迹。
4. 分数为整条 80 步、两个归一化误差分量的最大 `abs(error)/b(state)`。有限样本秩为 `ceil(101*0.95)=96`，不使用插值分位数。
5. 半径为 `q*b(state)`，**没有** `min(...,0.0992)`。先写协议及哈希，拟合/校准后先冻结合同，再读取旧留出集做回归。测试保证修改留出误差不能改变系数或阈值。
6. 对每个待验证状态盒，取双线性尺度在四个顶点的最大值，保守包住整个状态盒上的误差集合，然后验证所有允许后继的不增条件。

这里的 93/100 是新代码重新计算的结果，与旧文档恰好相同；不能据此认为旧脚本恢复正确。比较平均半径时，应优先使用同一 100 条校准的常量对照，不能把原 199 条校准与本轮 100 条校准的差异全归因于包络形式。

**统一最大盒失败与状态集合通过不矛盾：**把 0.235815 的误差施加到所有状态，会加入原状态相关集合根本不允许的扰动。这个扩大后的盒验证失败，报告保存在 `verification_at_max/`。实际 `r(x)` 在不同位置大小不同，直接检查该集合则通过，见 `verification_state/certificate.json`。没有靠缩小 CP 半径取得通过。

## 保证与仍然存在的限制

- SBC 证明对象是声明动力学、三个固定曲率和实际 `r(x)` 误差集合；条件于轨迹误差始终在该集合内，数值审计支持不越界。
- 修复后的拟合/校准流程符合分离数据的 split-CP 结构；其理论覆盖仍要求固定规则下校准与新轨迹分数可交换。
- **本轮复用了此前已查看过的数据，是方法修复与回归实验。没有新增盲测轨迹，不把它包装成新的独立 95% 部署安全验证。**正式发表前应冻结全部选择，再独立采集新校准及留出轨迹。
- 状态相关半径不提供每个固定状态分别 95% 的条件覆盖，也不意味着误差更小或覆盖更好。新对照未显示明显优于常量盒。
- float64 数值区间无全面向外舍入，不是浮点程序形式化证明。没有联合训练 C，没有更新 PPO 或神经 SBC。

## 复现

从 `artical-F122`，服务器使用 `conda activate vt`；每个输出目录必须不存在：

```bash
python -m Aebs.lane_keeping.state_dependent_cp \
  --source results/lane_trajectory_cp_20261107_v1 \
  --output-dir results/lane_state_cp_repro
python -m Aebs.lane_keeping.verify_state_cp \
  --source results/lane_trajectory_cp_20261107_v1 \
  --contract results/lane_state_cp_repro/perception_contract.json \
  --output-dir results/lane_state_cp_repro/verification_state
python -m pytest tests/test_lane_state_cp.py tests/test_lane_trajectory_cp.py \
  tests/test_lane_joint.py tests/test_lane_certificate.py -q
```

文件：`protocol.json` 保存划分、规则和数据哈希；`perception_contract.json` 保存系数、阈值及模型身份；两个 scores 文件保存逐轨迹分数；`report.json` 是验证前的校准报告，最终状态以 `summary.json` 与两个本地/服务器证书为准；`manifest.json` 校验包内文件，自身除外。
