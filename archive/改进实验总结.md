# SafePVC 论文改进实验汇报（通俗版）

> 汇报日期：2026-09-12
>
> 实验场景：车辆自动紧急制动（AEBS）
>
> 当前状态：最简版本已经做完并跑通；感知和安全控制取得了有效结果，但最后的“数学安全证明”没有通过。

## 0. 先说结论

这项工作研究的是：**一辆依靠摄像头判断前方障碍物距离的车，怎样既能自动刹车，又能对它的安全性进行检查。**

本阶段已经完成了一条完整流程：

```text
摄像头图像
   ↓
估计前方障碍物距离，并给出可能的误差范围
   ↓
控制器决定刹车力度
   ↓
安全过滤器在必要时强制增加刹车
   ↓
检查车辆在各种感知误差下是否会进入危险区域
   ↓
尝试训练一个数学“安全证明函数”
```

最终结果可以分成两部分：

### 成功的部分

1. 图像距离估计平均误差为 `0.1004m`。
2. 给出的距离误差区间，在测试集上有 `97.5%` 的真实距离落在区间内。
3. 原控制器在最坏感知误差下会发生 `100%` 的危险事件；加入安全过滤器后降为 `0%`。
4. 从读图、估计误差、控制、训练安全函数到输出反例，整套代码已经跑通。

### 没有成功的部分

最后训练出来的“安全证明函数”没有通过检查：在 4483 个需要检查的状态中，仍有 2556 个不满足要求。

因此现在可以说：

> 改进后的感知模块和安全过滤器在实验中有效，但目前没有得到能够证明整个状态空间都安全的数学证书。

不能说：

> 已经从数学上证明车辆在所有情况下都安全。

## 1. 这个实验到底在做什么

可以把整个问题想象成一个非常简化的自动刹车场景：

- 车辆前方有障碍物；
- 摄像头看到图像；
- 程序根据图像估计车辆离障碍物还有多远；
- 控制器根据距离和速度决定是否刹车、刹多大；
- 如果车辆高速进入离障碍物过近的区域，就算发生危险。

这里最大的困难是：**摄像头估计的距离不可能每次都完全准确。**

例如，真实距离可能是 10m，但程序估计成 10.3m。如果控制器完全相信 10.3m，就可能比应该刹车的时间更晚刹车。

所以我们的目标不是只检查“估计完全准确时是否安全”，而是检查：

> 即使距离估计偏大或偏小，只要误差仍在我们测量得到的范围内，车辆是否也能安全停车？

### 1.1 文中常见词语的白话解释

| 名词 | 白话解释 |
|---|---|
| AEBS | 自动紧急制动系统，发现可能撞车时自动刹车 |
| Controller / 控制器 | 根据当前距离和速度决定刹车力度的程序 |
| PPO | 一种通过反复尝试和奖励学习控制策略的方法，本项目原控制器使用了它 |
| Semantic / 语义信息 | 从图片中提取的、对控制有直接作用的信息；本项目就是障碍物距离 |
| Calibration / 校准 | 用一组不参与训练的数据测量模型通常会错多少 |
| Contract / 契约 | 后续控制和验证必须考虑的感知误差范围，不是法律合同 |
| Safety filter / 安全过滤器 | 原控制器刹车不足时，自动把刹车力度提高到最低安全值的保护层 |
| Uncertainty / 不确定性 | 程序不能精确知道的误差，例如看错距离或车辆运动偏差 |
| Barrier function | 给每个状态打“危险分数”的函数，也可理解成安全证明候选函数 |
| Certificate / 证书 | 一个通过全部数学条件检查的 barrier function；通过后才能用于安全证明 |
| Verifier / 验证器 | 逐个检查状态是否满足安全条件的程序 |
| Violation / 违反点 | 没有满足某条安全条件的状态点 |
| Margin / 余量 | 距离通过条件还有多远；正数表示通过，负数表示失败 |
| Epsilon / ε | 要求危险分数每一步至少下降多少，本实验最终使用 0.001 |
| Unsafe rate | 实际测试中进入危险区域的回合比例，越低越好 |
| Return / 回报 | 控制任务的综合得分；通常兼顾完成任务速度、动作代价等，越高越好 |

## 2. 原论文的方法是什么

原论文 SafePVC 的做法可以简化为：

```text
车辆状态
  ↓
用生成模型制作一张模拟摄像头图像
  ↓
再用一个小网络模仿这个生成模型
  ↓
控制器根据模拟图像做动作
  ↓
统计环境变化造成的状态误差
  ↓
训练安全证明函数
```

它的优点是希望把视觉控制器和数学安全验证连接起来。

但它有几个问题：

1. 先生成图像，再让另一个模型模仿生成器，过程较长，每一层都可能产生误差。
2. 控制真正关心的是“障碍物多远”，不一定需要重新生成整张图像。
3. 原方法把不同状态下的扰动统一当成同一种分布；但现实中远距离、近距离、高速和低速时的误差可能不同。
4. 感知误差和车辆运动误差容易混在一起，甚至被重复计算。

## 3. 我做了哪些改进

### 3.1 不再生成图像，直接估计控制需要的距离

原方法比较像：

> 根据车辆状态画一张图片，再从图片中决定怎样控制。

本次改成：

> 直接从真实图片中估计“前方障碍物距离”。

这个距离就是“语义信息”。这里的“语义”不是什么抽象概念，它只是指对控制真正有用、而且人能够理解的信息。例如：

- 障碍物距离；
- 相对速度；
- 距离碰撞还剩多少时间。

由于现有 AEBS 数据主要提供图像和距离标签，本阶段只使用一个语义量：**障碍物距离**。

### 3.2 不只给一个距离，而是给一个误差范围

普通模型可能只输出：

```text
估计距离 = 10m
```

但这个数字不可能完全准确。因此我们进一步输出：

```text
估计距离 = 10m
可信误差范围 = 9.6m 到 10.4m
```

这个范围在代码里叫做 `semantic contract`，中文可以理解为“感知误差约定”：

> 后面的控制和验证不能只看 10m，而要把 9.6m、10m、10.4m 等可能情况都考虑进去。

误差范围不是人工随便设的，而是用一部分专门保留的数据计算出来的。这部分数据叫 calibration set，也就是“校准集”。

### 3.3 尝试让原控制器适应距离误差

我们先尝试重新训练控制器。训练时不只输入准确距离，也输入：

- 准确距离；
- 误差范围内部的随机距离；
- 误差范围的两个边界。

直觉上，这相当于让驾驶员在训练时见过“距离看近了”和“距离看远了”的情况，希望它学会更稳健地刹车。

但是这次训练没有成功。新控制器更保守，回报下降，而且危险率反而上升。因此没有继续使用它。

### 3.4 增加一个有物理意义的安全过滤器

因为重新训练控制器没有成功，我们增加了一个简单的安全过滤器。

它的逻辑类似真实驾驶中的最后一道保护：

1. 原控制器先给出一个刹车力度；
2. 程序根据当前速度、最保守的障碍物距离和停车距离，计算“至少需要多大制动力”；
3. 如果原控制器刹车不够，就强制使用更大的制动力。

可以简单写成：

```text
最终制动力 = 原控制器制动力 和 最低安全制动力 中更大的一个
```

这一改进取得了最明显的安全效果。

### 3.5 把两种误差分开

系统中至少有两类不同误差：

1. 感知误差：图片看错了距离；
2. 运动误差：车辆真实运动和数学模型预测不完全一致，例如路面、制动或仿真误差。

早期代码把“看错距离后造成的动作变化”又记录成运动误差。这样同一个感知误差会被计算两遍，验证结果会过度保守。

修正后：

- 感知误差只在控制器输入端处理；
- 运动误差只表示车辆下一状态与动力学预测之间的差。

### 3.6 训练并检查“安全证明函数”

最后，我们训练了一个小神经网络，用来给每个车辆状态打一个“危险分数”。这就是 barrier function，可以把它通俗地理解成一张危险程度地图：

- 正常初始区域的分数应该低；
- 已经危险的区域分数应该高；
- 车辆每走一步，最坏情况下的危险分数也应该下降。

理想情况类似下山：

```text
当前危险分数  >  下一步最坏危险分数
```

只要每一步都在下降，车辆就不会突然爬进代表危险的高分区域。

验证程序会在状态网格上逐点检查这个要求，并找出最严重的失败位置。

## 4. 实验是怎样一步一步进行的

整个过程可以分成五个阶段。

### 阶段一：把基础程序跑通

完成内容：

- 固定一个 AEBS 场景；
- 固定 seed 7；
- 建立统一配置和运行入口；
- 保存每一步的模型、指标和日志。

目的不是立刻获得最好结果，而是保证每个模块能连接起来，结果能够重复查看。

### 阶段二：改进感知模块

完成内容：

- 用真实图像训练距离估计器；
- 将数据分成训练、校准和测试三部分；
- 计算不同距离区间的误差范围；
- 检查真实距离是否落在预测区间内。

结果是成功的：

| 指标 | 结果 | 通俗解释 |
|---|---:|---|
| MAE | 0.1004m | 平均大约差 10cm |
| RMSE | 0.1934m | 对较大误差更敏感的综合指标 |
| 最大误差 | 1.2678m | 测试集中最差的一次误差 |
| 区间覆盖率 | 97.5% | 80 个测试样本中约 78 个被误差范围覆盖 |
| 目标覆盖率 | 95% | 实际覆盖率高于预定目标 |

需要说明：四个距离区间中，有一个区间的误差半径达到 `2.7757m`。这会让后续安全检查比较保守，是数据和感知模型仍需改善的地方。

### 阶段三：改进控制器

先测试了“重新训练一个适应误差的 PPO 控制器”。结果如下：

| 测试模式 | 原控制器危险率 | 新 PPO 危险率 | 结论 |
|---|---:|---:|---|
| 距离准确 | 0% | 0% | 无变化 |
| 区间内部随机误差 | 1% | 21.5% | 明显变差 |
| 区间边界随机误差 | 17% | 28% | 变差 |
| 每次使用最坏边界 | 100% | 100% | 没有解决 |

同时，新 PPO 的任务回报也明显下降。因此这条路线判定失败。

随后加入安全过滤器：

| 测试模式 | 过滤前危险率 | 过滤后危险率 | 回报变化 |
|---|---:|---:|---:|
| 距离准确 | 0% | 0% | 405.747 → 372.498 |
| 区间内部随机误差 | 4% | 0% | 404.442 → 116.761 |
| 区间边界随机误差 | 12.5% | 0% | 402.440 → 15.293 |
| 每次使用最坏边界 | 100% | 0% | 241.608 → 330.017 |

结论：安全过滤器成功消除了本次测试中的危险事件，但在部分模式下过早或过强刹车，造成回报下降。它实现了“安全优先”，但还不是性能最好的控制器。

### 阶段四：修正运动误差和验证范围

我们把状态空间分成 `4×4=16` 个区域，准备分别记录不同状态下的运动误差。

最终得到的运动 residual 全为 0。原因不是现实世界没有噪声，而是：

- 当前仿真动力学是确定性的；
- 现有数据只有图像和距离标签；
- 没有保存真实下一状态与模型预测下一状态之间的误差。

因此，这一步的成功是“代码定义和接口正确”，而不是“已经学到真实车辆扰动”。

同时还修正了验证范围：

- 已经安全停车的状态不再要求危险分数继续严格下降；
- 已经来不及停车的状态被单独标记，不能假装控制器还能恢复；
- 危险状态始终优先按危险处理；
- 对安全终止后的下一状态使用固定安全值，避免神经网络在无数据区域随意输出。

这些修改不是为了删掉失败点，而是为了让检查条件符合车辆制动过程。

### 阶段五：训练和改进安全证明函数

我们尝试了若干版本。可以把它们分成三类，而不需要记住每个名字。

#### 第一类：先让平均情况变好

把验证网格加入训练、增加平均下降损失后，违反数量一度从 4170 降到 1096，但最坏点反而从约 `-0.53` 变成 `-1.02`。

这说明：平均成绩好看，不代表最危险的个别位置也安全。

#### 第二类：重点修最坏点

加入 worst-case、top-k 和 hard-case loss 后，有的版本能把最坏误差压小，但会破坏初始区域或危险区域的分数要求。

这说明不同目标之间发生了拉扯：顾住一个要求时，另一个要求又变差。

#### 第三类：修正物理范围和低速状态

在修正停车域、不可恢复状态和终止状态后，最好的一版是 `low_speed_curriculum`：

```text
主检查：2576 / 4483 个状态违反
不要求额外下降量时：1379 / 4483 个状态仍然上升
最坏差值：-0.000793
初始区、危险区、非负要求：全部满足
```

这说明我们已经把最严重的错误缩小到很小，但仍有很多位置存在轻微上升。

最后又尝试把网络输出形式改成 `softplus-square`。结果：

```text
主检查：2576 → 2556，只减少 20 个违反点
真正上升的状态：1379 → 2089，反而增加 710 个
最坏差值：-0.000793 → -0.004527，变差
```

因此最后一个改动失败，并决定停止继续换网络和调参数。

## 5. 最后到底失败在哪里

### 5.1 用一个直观例子解释

把安全证明函数想象成一张地形图：

- 出发区域应该在低处；
- 危险区域应该在高处；
- 汽车每走一步都应该向低处走，不能向高处走。

最终网络已经做到了：

- 出发区域基本在低处；
- 危险区域在高处；
- 整张地图没有低于零的异常值。

但地图中仍存在大量很小的局部上坡。汽车经过这些位置时，下一步危险分数会稍微增加。因此这张“地图”不能作为完整安全证明。

最坏反例位于：

```text
障碍物距离：7.785m
车辆速度：1.215m/s
使用的感知情况：距离误差的一个最坏边界
当前危险分数：0.089132
下一步危险分数：0.093660
```

下一步分数比当前高 `0.004527`，所以检查失败。

### 5.2 不是因为要求的下降量设得太大

正式检查要求每一步至少下降 `0.001`。可能有人会问：是不是这个要求太严格？

我们已经做了一个更宽松的检查，把最低下降量设成 0，也就是只要求：

```text
下一步不能比当前更危险
```

即使这样，仍有：

```text
2089 / 4483 个状态的下一步危险分数上升
```

所以失败不是简单把 `0.001` 改小就能解决。

### 5.3 不是初始区或危险区完全没学会

最终结果中：

- 非负要求：0 个违反；
- 危险区域要求：0 个违反；
- 初始区域要求：只有 1 个轻微违反。

说明网络已经知道“哪里是起点、哪里危险”，真正没有学好的是“车辆移动一步后，危险分数必须持续下降”。

### 5.4 当前训练方式只能追求平均，不能保证每一点

神经网络训练会把所有状态的误差加起来求平均。于是可能出现：

```text
大部分状态很好 + 很多状态只有很小的错误 = 平均 loss 看起来很小
```

最终训练的 decrease loss 只有 `0.000582`，看起来很小，但逐点检查仍发现大量违反。这正是“训练指标较好”和“数学证明通过”之间的区别。

### 5.5 安全过滤器实验成功，不等于数学证书一定存在

安全过滤器的 0% unsafe 表示：在我们实际运行的有限批测试中，没有发生危险。

数学证书要求更强：它要覆盖整个检查区域，并考虑每个状态下的所有感知边界。

这类似：

- 道路测试一万次都没有事故，是很好的实验结果；
- 证明任何满足条件的情况都不会发生事故，是更强的数学结论。

前者成功，不代表后者一定能由当前这个小神经网络证明出来。

### 5.6 感知区间较宽，使检查更保守

四个距离区间中，有一个误差半径是 `2.7757m`。也就是说，某些情况下程序必须同时考虑“距离可能比估计值近将近 2.8m”。

为了安全，验证器必须检查这个边界，不能只检查平均误差。这会明显增加获得统一安全证明的难度。

### 5.7 目前还不能判断是“证书不存在”还是“训练没找到”

当前失败可能有两种原因：

1. 存在满足要求的安全证明函数，但当前小网络和训练方法没有找到；
2. 对当前控制器和当前检查要求，本身就不存在这样的安全证明函数。

现有训练结果无法严格区分这两种情况。这也是为什么继续随机调学习率、权重或激活函数意义不大。

## 6. 为什么前面改了很多版本

前面的修改并不全是调参，可以分成两部分。

### 必须修正的问题

这些属于实现或定义错误，不修正就无法相信结果：

- 感知误差和运动误差被重复计算；
- barrier 使用了与训练时不同的 controller；
- 已停车状态被要求无限次严格下降；
- 安全终止后的网络输出被错误地继续使用；
- 已经物理上无法停车的状态和可恢复状态混在一起；
- 危险区和低速终止区的边界优先级不清楚。

### 后续尝试但没有成功的改良

- 提高 decrease loss 权重；
- 加入验证网格训练；
- 加强最坏点和 top-k loss；
- 分阶段训练；
- 改变 barrier 输出形式。

这些尝试帮助定位了问题，但没有获得最终证书。现在已经停止，不再继续堆实验版本。

## 7. 哪些地方可以算成功

### 成功一：感知模型更直接

用“图像 → 障碍物距离”替代“状态 → 生成图像 → 蒸馏模型”，减少了中间环节，并且距离误差可以直接解释。

### 成功二：感知误差进入了后续安全检查

不再假设预测距离完全正确，而是检查距离区间的中心和边界。这比只检查平均预测更符合安全任务。

### 成功三：安全过滤器显著改善最坏情况

最坏感知边界下，危险率从 `100%` 降到 `0%`。这是目前最有说服力的实验结果。

### 成功四：不确定性定义被理顺

感知误差和运动误差已经分开，避免同一个误差被计算两次。

### 成功五：验证程序能够给出具体反例

程序不仅返回“失败”，还会告诉我们：

- 在什么距离和速度下失败；
- 哪个感知边界最危险；
- 当前分数和下一步分数分别是多少。

这让失败是可解释、可复查的，而不是只看到一个 loss 数字。

## 8. 做到了哪一步，还有什么没做到

| 工作 | 状态 | 能否在论文中使用 |
|---|---|---|
| 图像距离估计 | 已完成 | 可以作为正向结果 |
| 距离误差区间 | 已完成 | 可以，但要说明样本量较小 |
| 适应误差的 PPO | 已完成但失败 | 可以作为负结果 |
| 安全过滤器 | 已完成且测试成功 | 可以作为主要正向结果 |
| 区分感知误差和运动误差 | 已完成 | 可以作为方法改进 |
| 状态相关运动误差接口 | 已完成 | 可以作为代码实现 |
| 真实车辆运动误差模型 | 没有完成，缺数据 | 不能声称已完成 |
| 安全函数训练程序 | 已完成 | 可以说明方法已实现 |
| 网格验证和反例输出 | 已完成 | 可以报告验证失败结果 |
| 通过验证的安全证书 | 没有得到 | 不能声称成功 |
| 整个连续状态空间的严格证明 | 没有完成 | 不能声称成功 |

## 9. 这项工作还可能继续完成吗

有可能，但不能保证。

现有结果说明车辆在测试中可以通过 safety filter 安全停车，所以系统本身不是完全没有希望。真正的问题是：当前神经网络能否形成一张满足所有要求的“危险地图”。

如果以后继续，最值得做的不是继续调神经网络，而是先直接回答：

> 在当前 80×80 网格上，到底存不存在任何满足全部要求的危险分数？

可以把每个网格点的危险分数都当作一个未知数，直接交给数学求解器寻找。通俗地说：

- 以前是让神经网络反复猜一张地图；
- 下一步是让求解器直接判断“这样的地图是否存在”。

结果只有两类：

1. 如果求解器能找到，说明问题主要在神经网络训练，可以直接使用求解结果或再让网络模仿它；
2. 如果求解器也找不到，说明当前控制器和证明条件之间存在冲突，继续训练神经网络没有意义。

另一个有物理意义的方向，是根据“当前距离减去所需停车距离”直接设计安全函数。因为 safety filter 本来就是根据停车距离工作的，这种函数比完全由神经网络自由学习更容易解释。

这些属于下一阶段研究，不建议为了明天汇报临时继续运行。

## 10. 明天汇报时可以怎样讲

### 10.1 三分钟版本

> 原论文通过生成视觉图像并学习随机扰动来验证视觉控制器。我这次先做了一个最简改进：不再生成图像，而是直接从真实图像估计障碍物距离，同时用校准数据给出距离误差范围。距离估计的平均误差约为 10cm，误差区间在测试集上覆盖了 97.5% 的真实值。
>
> 在控制部分，我先尝试让 PPO 控制器适应距离误差，但结果反而变差。随后加入基于停车距离的安全过滤器。在准确距离、区间内部误差、边界误差和最坏边界四种模式下，危险率都降到了 0%，其中最坏边界从原来的 100% 降为 0%。代价是部分场景下回报下降，说明过滤器比较保守。
>
> 最后我实现了安全证明函数的训练和逐点验证。程序已经能检查初始区、危险区、感知误差边界和车辆下一状态，也能输出最坏反例。最终初始区、危险区和非负要求基本满足，但最关键的逐步下降条件仍有 2556/4483 个状态违反；即使不要求额外下降，也还有 2089 个状态会上升。因此目前不能声称已经获得数学安全证书。
>
> 我的结论是：感知契约和安全过滤器取得了有效结果，完整实验链路也已经跑通；失败集中在安全证明函数，而不是整个系统没有工作。当前实验已经收口。如果继续，应该先用直接求解判断证书是否存在，或者根据停车距离构造有物理意义的安全函数，而不是继续盲目调神经网络参数。

### 10.2 汇报时建议展示的四张表

1. Semantic encoder：MAE、RMSE、coverage。
2. Robust PPO：说明简单重新训练为什么失败。
3. Safety filter：突出四种模式全部达到 0% unsafe。
4. 最终 SBC：展示 2556/4483 violations 和具体最坏反例。

## 11. 导师可能会问什么

### 问题一：既然测试都是安全的，为什么还说失败？

回答：测试安全只说明运行过的有限场景没有出事故；安全证书要求整个检查区域中的所有状态都满足数学条件。两者要求不同。目前实验安全性有改善，但数学证明没有通过。

### 问题二：是不是多训练一会儿就能通过？

回答：可能性较低。训练后期的违反比例已经长期不再下降，而且换输出形式后真实上升点反而增加。继续相同训练缺少依据。

### 问题三：把下降要求调小可以吗？

回答：已经测试到最低下降量为 0，仍有 2089 个状态的下一步分数比当前高，因此不是只改阈值就能解决。

### 问题四：为什么做了这么多版本？

回答：前半部分是在修正误差重复计算、controller 不一致、终止状态和不可恢复状态等定义问题；后半部分才是少量训练方法尝试。现在定义问题已经理顺，训练方法仍失败，所以已经停止继续增加版本。

### 问题五：这篇论文还能继续做吗？

回答：可以继续，但下一步应先用直接求解判断当前网格约束是否可行。如果可行，再解决网络拟合；如果不可行，就需要修改控制器或证明条件。这比继续调参更有判断力。

### 问题六：现在最主要的成果是什么？

回答：完成了可解释的语义感知和误差区间、实现了在最坏感知边界下有效的 safety filter、理顺了两类不确定性，并建立了能输出具体反例的完整验证链路。

## 12. 汇报时需要避免的说法

不要说：

- “已经证明系统安全”；
- “已经完成完整的分布鲁棒 SafePVC”；
- “真实过程噪声为零”；
- “97.5% 单步覆盖率等于无限时间 97.5% 安全率”；
- “只要继续调参就一定能通过”。

建议说：

- “安全过滤器在当前测试设置下实现了 0% unsafe”；
- “感知区间在独立测试集上的经验覆盖率为 97.5%”；
- “fixed-grid verifier 返回 violated，并给出了具体反例”；
- “最简实现已经完整跑通，但还没有获得形式证书”；
- “后续先判断证书约束是否可行，再决定是否继续训练”。

## 13. 当前决定

- 本阶段实验已经结束，不再继续换网络或调参数。
- 保留 `low_speed_curriculum` 作为相对更好的安全函数候选。
- `softplus-square` 作为最后一个被实验否定的改良方案。
- 论文重点报告感知契约、安全过滤器和可解释验证流程。
- 对 robust SBC 诚实报告失败结果和具体原因。
- 后续若继续，优先进行网格约束可行性求解或停车距离安全函数设计。
