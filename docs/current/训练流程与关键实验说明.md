

## 一、研究对象

研究对象是一个看图像决定刹车的自动紧急制动系统。原SPVC通过“根据物理状态生成图像”的代理，分析控制器与安全屏障；我们首先尝试用预训练DINO图像编码器和低维表示，替代这段图像生成前端，保留后面的控制与安全分析任务。

这就形成两条路径：

```text
实际观测路径：相机图像 → DINO → 图像latent → PPO控制器 → 刹车动作

物理代理路径：已知物理距离 → q代理网络 → 代理latent → 同一个PPO → 刹车动作
```

“latent”就是网络内部的一组数字，可以理解为机器读懂图像后写下的摘要；不要求其中某一维直接等于距离。“q”在这里是把距离转换成摘要的网络，不是强化学习中衡量动作价值的Q函数。

为什么保留两条路径？第一条负责实际看图像控制，第二条让训练和验证程序能从一个已知物理状态计算控制行为，不必每次启动CARLA拍图。研究的关键不是单纯把两组数字变得相似，而是：**代理是否足够准确，能不能用代理上的安全分析说明图像控制器也安全。**

目前已经得到四项主要结果：

1. 完成了DINO双路径前端、PPO控制器和原SPVC后端的衔接，有可运行的最小版本；不是只有一个表示学习网络。
2. 在相同图像和物理状态的开发对照中，DINO方案的距离读出误差、由图像与代理差异引起的下一速度误差，均明显小于本次采用的原cGAN基线。
3. 不只比较了32维：还比较了Transformer时序预测，以及PCA、自动编码器等18组原生表示分别配新PPO的方案。新R2组合在这轮静态表示选型中综合表现较好。
4. 已定位为什么“误差变小”仍不等于“图像闭环安全证明完成”：极端误差、控制器敏感性、误差的时间结构，以及早期图库模拟中的观测错位，都影响最终安全结论。

当前最准确的进度是：**前端替换与误差改进已有实验证据，代理路径也能得到原SPVC代码口径下的安全读数；但把真实图像与代理差异完整纳入可靠的SBC保证，仍是未完成的主问题。** Transformer目前是预测实验分支，不是已经替换上线的完整新控制系统。

## 二、任务是什么，怎样才算完成

### 2.1 控制任务

车辆逐渐接近前方障碍物。程序用两个物理量描述状态：距离 `d`，单位米；速度 `v`，单位米/秒。控制器输出动作 `a`，范围为−3到3；本项目约定正值表示制动，负值表示加速。

每个控制步长为0.05秒，主要对照使用的解析更新为：

```text
下一距离 = 当前距离 − 0.05 × 当前速度
下一速度 = 把“当前速度 − 0.05 × 动作”限制在0到3之间
```

例如，当前速度2米/秒、动作1.2，则下一速度为1.94米/秒。这个例子只是解释公式，不是一条实测记录。

任务希望车辆进入距离5到6米、速度不高于0.5米/秒的目标区；若距离已经不大于6米、速度却仍高于0.5米/秒，则记为危险。停在目标区外、超出定义域、运行超时，都应单独记录，不能为了“没有危险”就一律算成功。典型评估最长400步，对应模型中的20秒。

因此需要同时看两件事：能否安全，以及能否完成任务。一直停在远处可能不危险，但不是合格控制器。

### 2.2 这里有三种不同的“环境”，不能混称真实闭环

| 实验环境      | 实际怎样得到图像/后继                        | 能回答什么                              |
| --------- | ---------------------------------- | ---------------------------------- |
| CARLA同步采集 | 在仿真场景中记录对应时刻的图像、物理状态和动作            | 提供同一时刻的配对数据和轨迹；是否使用CARLA物理后继要看具体实验 |
| 精确图像单步评估  | 使用一张已有图片及它自己的距离标签，配指定速度，经解析模型算一次后继 | 隔离图像路径与代理路径差异，不需要查最近图片             |
| 图库近似闭环    | 解析模型每步产生新距离，再查图库中距离最近的图片           | 快速开发与训练；图库不连续时会引入额外观测错位            |

本文报告的主要“下一速度差”是同一解析动力学下的两条控制路径差，不是已经测量了真实车辆轮胎、路面、制动执行器的全部模型误差。雨天图片已经参与表示学习，但当前解析动力学不会仅因图片是雨天就自动降低摩擦系数。

## 三、整个框架：哪些网络负责什么

### 3.1 原SPVC与当前最小替换版

原方法的有关前端，可以概括为：

```text
物理状态 → cGAN生成图像 → 原图像处理/状态网络 → 控制器
真实图像 ───────────────→ 原图像处理/状态网络 → 控制器
```

我们保留“实际图像路径与可计算代理路径”的思想，将前端改为：

```text
真实RGB图像
    ↓ 统一预处理
冻结的DINOv2 ViT-S/14
    ↓ 384维全局特征
可训练投影网络
    ↓ 32维图像表示 z_img ──┐
                            ├─ 当前速度v → 同一个PPO → 动作 → 下一物理状态
已知距离d → q网络           │
    ↓ 32维代理表示 z_q ─────┘

安全分析支路：当前物理状态、控制后继、噪声假设 → SBC屏障B → 条件检查/概率读数
```

图中上下两条路径是分别输入同一个控制器，不是把两个latent同时拼接输入PPO。SBC通常是旁边的安全分析器，并不是“PPO输出必须经过SBC网络才能执行”。只有某些历史QP/过滤器分支会另外修改动作；它们不属于当前最小DINO-SPVC主线。

### 3.2 具体输入、输出与训练范围

| 模块      | 输入                | 输出               | 在哪一步学习/使用                     |
| ------- | ----------------- | ---------------- | ----------------------------- |
| 冻结DINO  | 预处理后的RGB图像        | 384维全局特征         | 使用预训练权重，不在本项目数据上重训主干          |
| 图像投影网络  | 标准化的384维特征        | 32维图像latent      | 在表示学习阶段训练，PPO阶段冻结             |
| 物理代理q   | 训练/验证时已知的距离       | 同坐标系32维代理latent  | 与图像投影对齐，或在独立候选实验中重拟合          |
| 辅助距离读出头 | latent            | 距离预测             | 表示监督和诊断用，不作为PPO运行时必经模块        |
| PPO控制器  | latent加当前速度       | 动作分布；评估时通常取确定性动作 | 表示冻结后训练策略和价值网络                |
| SBC屏障   | 本实现中的物理状态及相关后继    | 一个安全分析标量B        | 在选定控制器后训练，或按原SPVC流程与actor交替更新 |
| 时序预测器   | 历史表示、动作，部分版本再输入速度 | 未来的表示            | 额外实验分支，不能与静态q混为一谈             |

原静态图像投影结构为 `384→128→32`，q结构为 `1→64→64→32`，隐藏层使用ReLU。原R2把距离按保存的比例缩放后输入q；后续“原生表示+新PPO”实验采用新的坐标标准化与q输入标准化，不能混用权重或预处理。

当前静态PPO仍额外接收速度。单张静态图片难以可靠确定当前车速，且速度决定何时刹车。实验中给控制器的速度是任务已提供的状态量，并不表示DINO已经从图片估计出速度；车辆部署时需要对应的车速信号。

### 3.3 为什么报告中会出现不同的R2、q和PPO

“R2”是表示学习的一次版本名称，并不唯一指定整个系统。至少要区分以下三套组合：

| 本文简称        | 组成及作用                               | 不能混用的地方                        |
| ----------- | ----------------------------------- | ------------------------------ |
| 早期R2/PPO09  | R2前端配最初训练的完整PPO；许多历史CARLA轨迹由它产生     | 这些轨迹不是后续新策略自主运行的数据             |
| 最小DINO-SPVC | R2前端接原SPVC流程，actor与SBC继续更新，形成最终保存模型 | 最终actor不同于PPO09，需核对保存模型与验证模型一致 |
| 新R2原生组合     | 保留R2图像投影，重新标准化latent、拟合q、从头训练对应PPO  | 误差下降来自整套组合，不能只归功于换编码器          |

此外，“R2之后单独再训q”“冻结旧控制器换q”“新q配新PPO”是三个不同实验。一个q拟合误差小，不保证把它直接接回旧PPO就更好。

### 3.4 各部分的研究来源与项目适配

| 部分             | 主要思路来源                                                                    | 本项目实际上做的范围                               |
| -------------- | ------------------------------------------------------------------------- | ---------------------------------------- |
| 代理、控制器、屏障与后端检查 | 原SPVC论文与仓库                                                                | 最小替换实验保留其后端，另明确原实现的范围限制                  |
| 图像与物理状态映射到共同表示 | 用户提供的semantic+latent建议                                                    | 冻结DINO、训练投影与q；同距离多外观分组是本项目的具体训练适配        |
| 根据历史预测未来表示     | 用户提供的潜在空间CBF/世界模型论文，以及相关DINO-WM思路                                         | 使用已有CLS缓存做小型因果时序模型，不是完整patch模型或完整安全控制复现  |
| 真实转移的屏障成本反馈给策略 | Model-Free Safe Reinforcement Learning Through Neural Barrier Certificate | 实现了单步/短多步NBC成本与PPO更新对照，但没有证明训练收益或自动继承其理论 |
| 校准误差或整轨迹风险     | 用户提供的CP验证思路                                                               | 使用轨迹级统计与置信检查；当前开发复用数据和图库分布限制必须保留         |

这些来源说明“为什么尝试这个组成部分”，不表示这些方法已经同时组成一个满足全部论文假设的系统。

## 四、从数据到控制器：一步一步怎样训练

整个训练顺序可以先记成：

```text
采集图片与距离标签
  → 划分训练/验证/测试组
  → 冻结DINO，缓存384维特征
  → 训练图像投影和q，使两条表示对齐
  → 冻结表示，训练PPO学动作
  → 选定控制器，训练/检查SBC
  → 单独核对图像与代理误差是否进入安全结论
```

这些阶段不是每次实验都全部重跑。例如“换一个时间预测器”可能冻结原PPO，只测预测差异；“新原生表示配PPO”则必须重训对应控制器。后面的实验记录均标明了实际改变部分。

### 第一步：采集带物理标签、带外观变化的图像

保留原SPVC相机与车辆采集方式，主要扩充距离和外观数据，而不是另换拍摄几何。扩充数据包含约2000条距离采样、4种天气、3种车身颜色，共24000张RGB图片；同一距离的不同天气与颜色组成配对数据。

每张图片保存文件身份、距离、天气、颜色和分组，避免训练后不知道误差出在哪种外观。数据审计显示24000张全部可解码，无解码错误、无近常量图像。视觉审查与文件审计是两件事，前者确认画面/目标正常，后者确认文件和标签结构正确。

**输入：** CARLA场景、原采集方式、距离表、天气与颜色组合。

**输出：** 图片、距离标签、外观标签、配对分组和采集完成记录。这个阶段还没有PPO或安全证书。

### 第二步：按距离组划分，而不是把相邻图片随机打散

按0.25米距离块组织44个组，同组及其不同外观必须在同一划分内：

| 划分 | 距离块组数 | 图片数 | 用途 |
|---|---:|---:|---|
| train训练集 | 26 | 14172 | 学习网络参数 |
| validation开发验证集 | 9 | 4908 | 比较方案、选择开发候选、定位问题 |
| test保留测试集 | 9 | 4920 | 留待最终固定方案，不能反复用于调参 |

跨划分重复组数为0。这样比“相邻距离、同距离不同颜色随机落到不同集合”更能检验未见距离块的泛化。

代价是：单独取train或validation，不再覆盖所有连续距离。这不会让静态误差评估失效，但会让“从这个子集中查最近图片来模拟连续相机”产生大空洞。这个问题后来已专门审计，见第十节。

### 第三步：冻结DINO，缓存特征

对train和validation共19080张图片统一缩放/归一化，经过冻结DINO，得到19080行、每行384维的特征，存为HDF5缓存。test的4920张在这一阶段未编码、未评估。

**输入：** RGB图片与固定预处理。

**输出：** DINO特征矩阵与标签索引。缓存的意义是后面每次比较小网络时不重复运行大图像主干，不是“已经完成32维表示训练”。

### 第四步：训练图像投影与物理代理，使两条路径对齐

对每个有标签的训练样本，分别计算：

```text
同一张图片的DINO特征 → 投影 → z_img
这张图片的真实距离   → q网络 → z_q
```

损失同时考虑三件事：两条latent接近；latent保留距离相关信息；相距较远的物理状态不要全部压成同一个向量。后一点用于防止“所有图片输出一样，误差自然为零”的无意义解。

R2进一步一次抽取同一距离的多种外观，让这些图像latent靠近同组中心。注意：本次R2直接的“q到组中心”额外损失权重为0；q主要仍通过原有图像/物理配对损失学习。不能把配置写成所有中心约束都启用了。

**输出：** 图像投影、q、辅助读出头，以及必须随模型保存的尺度和标准化参数。

### 第五步：冻结表示，再训练PPO

PPO需要学的不是“图片长什么样”，而是“看到这个表示、当前这个速度，应该采取什么动作”。一次环境步为：

```text
当前物理状态
  → 选择代理路径，或选择图像观测路径
  → latent与当前速度
  → PPO采样动作
  → 限制动作范围并执行
  → 解析动力学产生下一状态
  → 计算奖励、终止原因
  → 保存观测、动作、旧动作概率、奖励、下一状态
  → PPO用一批记录更新策略与价值网络
```

早期R2/PPO09训练采用每回合50%代理、50%训练图库图像的混合；一个回合内天气、颜色固定。实际完成200704个环境步，策略/价值网络隐藏层均为64、64，学习率0.0003，每批采样2048步、batch64、每批10个训练epoch，折扣0.99，GAE系数0.95，熵系数0.01，seed为7。

训练沿用原环境从距离5～16米、速度0～3米/秒抽起点；常用任务评估则从15～16米、2.5～3米/秒的20×20网格起步，共400个起点。训练状态范围和评估起点范围不是同一个区域。后续NBC短更新试验又改用指定任务起点，不能与这一完整PPO训练混称。

奖励鼓励向目标靠近，扣除每步时间成本，进入目标区给奖励，危险时按速度处罚。PPO并不需要每一步都有“正确动作标签”：它根据一批动作带来的回报，增加表现较好动作的概率，并限制单次策略改动过大；价值网络帮助估计长期回报。随机探索训练与确定性评估不同，评估100%成功不表示训练过程从未出现危险。

这时DINO、图像投影和q均冻结，更新的是完整PPO，不是把所有网络一次端到端更新。图像库混合是训练近似，并不证明运行时每帧观测准确对应物理距离。

**输出：** 对应表示坐标系的PPO策略、价值网络、探索参数和配置。

### 第六步：训练SBC并核对保存模型

#### 6.1 为什么控制器已经会刹车，还要训练SBC

第五步得到的是一个会根据观测输出动作的控制器。有限回合测试成功，只说明它在这些起点和观测下完成了任务；还没有给出规定随机模型下的安全概率分析。

SBC可以理解为另外学习一把“风险刻度尺”：把当前状态和下一状态放到同一把尺子上，检查风险如何变化。它不是再训练一个决定刹车的控制器，也不是只给图片做安全分类。我们希望它同时做到：初始区域刻度低，不安全区域刻度高，在所分析的闭环动力学下满足相应的平均变化条件。

这里的刻度值本身不是事故概率。例如B等于20不表示事故概率2000%；需要先满足区域与动态条件，再通过相应公式转换为概率界。

#### 6.2 SBC网络到底输入什么 输出什么

本节原SPVC口径的屏障网络记为 `B(s)`，代码中叫L-Net或`l_model`。它读两个数：归一化距离和当前速度，不读32维latent，不直接读图片，也不把PPO动作作为第三个输入。

```text
当前物理状态 s = [归一化距离, 速度]
                ↓
         小型屏障网络B
                ↓
           一个非负标量
```

网络结构是 `2→16→8→1`，两个隐藏层使用tanh。配置里的`square_l_output=True`容易误读：目前实际调用的公共MLP实现使用Softplus让输出非负，不是把输出真的平方。它约束的是函数形状，不会自动让动态条件成立。

**要区分两种输入：** PPO读“32维latent＋当前速度”，共33维；SBC读“归一化距离、当前速度”，共2维。因此安全检查可以利用离线已知的物理状态分析控制器，但不能据此说车辆运行时已经从图片精确知道了距离。

#### 6.3 训练SBC的数据从哪里来

这一步原口径训练主要使用物理状态采样，不是把24000张图片逐张输入SBC，也不是把459条旧轨迹全部当作SBC标签。

| 样本类别 | 怎样得到 | 用来学习什么 |
|---|---|---|
| 全域动态状态 | 将原物理定义域划为100×100网格，取10000个中心点；每批再在相应小格内轻微扰动 | 检查控制器作用下的平均风险变化 |
| 初始区状态 | 从距离15～16米、速度2.5～3米/秒的区域抽256个点 | 让出发位置的屏障值较低 |
| 不安全区状态 | 从原定义的距离5～6米、速度0.5～3米/秒盒中抽256个点 | 让危险区域的屏障值较高 |

初始/不安全区样本在每个训练批次中由固定种子生成；它们不是每批都增加256条新的独立轨迹。训练状态的距离按原后端尺度归一化，适配器再转换成q所需尺度，不能把不同版本的距离标准化直接混用。

每个动态训练状态都要先经过当前控制器，生成后继，才能训练屏障。数据流为：

```text
物理网格状态s，在小格内扰动
       ├──────────────────────────────→ B(s)
       ↓
取距离 → 冻结q → 32维代理latent
       ↓ 拼接当前速度
当前actor → 动作a → 解析动力学F(s,a)
                         ↓ 加入旧后端的随机扰动
                  16个扰动后继s'_1…s'_16
                         ↓ 分别输入同一个B
                   B(s'_1)…B(s'_16)
                         ↓ 取平均
                    平均下一屏障值
                         ↓
                与B(s)比较，产生训练损失
```

**这解释了为什么能不调用相机训练原口径SBC：** 动作由q代理路径产生。真实图像、天气与颜色对动作的影响，只有先被代理建模，或在额外的图像误差/实际转移实验中加入，才会影响这里的安全结论。仅替换成DINO，不会让这10000个状态自动附带所有天气下的真实图像后继。

#### 6.4 为什么一个状态要生成16个后继

原训练代码给同一个确定性后继加入16组扰动，再对16个屏障值取平均。它是在近似计算“给定当前状态和策略，下一步风险的条件平均”，不是要求16个结果每个都下降，也不是16条完整控制轨迹。

本实现的扰动幅度由旧环境参数`factor=0.05`和各状态坐标范围确定。速度范围为0～3，因此速度扰动的半宽为0.15米/秒；距离扰动也按原后端定义的距离范围生成。这是旧模型预设的扰动，不是由本轮DINO误差校准得到的。

特别要注意：**预设噪声的0.15米/秒与后来CP测得的0.150685米/秒，只是数值接近，不是同一个契约。** 它们的来源、分布与适用对象不同，不能用前者自动覆盖后者。

代码中还有一个实现口径差异：屏障训练使用三角分布采样；旧验证器对噪声小格按均匀分布的概率质量加权。因此不能把“16点训练平均”和“旧验证期望读数”说成完全相同的精确积分。这一差异没有在最小替换实验里擅自修正，相关读数仍按原实现范围解释。

#### 6.5 网络究竟被要求学会什么

原口径训练主要由三类损失组成，含义分别如下。

**第一类是动态损失：** 对固定状态，比较16个后继的平均屏障值与当前值。本节基线配置的动态损失可写成：

```text
L_dec = 各训练状态上 max(平均下一B − 当前B + 0.1, 0) 的平均
```

0.1是屏障数值上的训练下降裕量，不是10%的碰撞风险，也不是0.1米/秒误差；它与第五步PPO的奖励折扣0.99无关。这里使用原配置`gamma_decrease=1.0`的分支，其他历史SBC实验的0.01或0.001不能直接套进来。

举一个仅用于理解的例子：当前B为0.8，四个示意后继的值为0.4、0.5、0.6、1.1，平均为0.65，代入损失得到0。虽然其中一个后继高于当前值，但平均满足了这个训练条件。实际代码每个状态用16个，而不是示例的4个。

**第二类是区域损失：** 让初始区和不安全区拉开刻度。训练目标安全概率设为95%时，原损失希望初始抽样点的最大B不超过1，不安全抽样点的最小B不低于 `1/(1−0.95)=20`；不满足时分别处罚。

这就是为什么日志里经常出现“初始上界接近1、不安全下界接近20”，而不是必须用0与1分类。训练区域目标只是优化目标，不代表未采样区域已经满足这些界。原实现还带有一个对参考零点的刻度正则项；该零点不是车辆的实际起始位置。

**第三类是平滑损失：** 处罚屏障对输入过于剧烈的变化，尽量避免相邻距离/速度对应的B突然跳变。本基线使用屏障输入梯度阈值4，外部权重0.001。它是帮助训练的正则项，不等于已经证明了全域平滑上界。

屏障总损失是：

```text
L_B = 1000 × 动态损失 + 0.001 × 平滑损失 + 区域损失
```

动态项权重大，所以损失下降可能主要来自动态项改善；也可能区域分离先改善而动态仍失败。需要分别查看各分量，而不是只看总损失。

#### 6.6 一次优化实际更新哪些参数

一次屏障更新可以按以下顺序理解：

1. 从10000个网格训练状态中取一批，原配置batch为2048，再构造小格内扰动状态。
2. 用当前q和actor生成动作、确定性后继及16个扰动后继；这一步在屏障训练时不更新控制器。
3. 同一个B分别评价当前状态、扰动后继、初始区样本和不安全区样本，计算上面的损失。
4. 反向传播只更新B的参数，使用Adam、学习率0.003，屏障梯度裁剪上限5。
5. 遍历一遍状态集叫一个epoch；原流程通常先训练10个epoch，再检查一次。

**这不是PPO训练。** 它没有重新收集策略回报来更新价值网络，主要是在固定当前策略下拟合一个候选屏障。DINO、图像投影和q也不会因为这一轮屏障训练而改进。

#### 6.7 两条已经做过的SBC路线 不能混称

| 路线 | 控制器是否更新 | 一轮怎样进行 |
|---|---|---|
| 最小DINO-SPVC，沿用原循环 | 更新actor，表示与q冻结 | 训B 10个epoch→检查→计算原概率读数→按循环设置再训actor 1个epoch→下一轮 |
| 新R2原生组合的屏障独立基线 | q与完整PPO都固定 | 只训B 10个epoch→检查→记录并保存较好屏障，不执行actor更新 |

原循环更新actor时，主要利用屏障动态损失以及相对冻结参考策略的动作保持损失，不是第五步那套“奖励、价值网络、探索分布”完整PPO重训。actor更新用128组噪声后继，不要与训练B时的16组混淆。

还有一个已审计的实现细节：当前actor平滑项的计算未保留继续反向求导所需的关系，意味着“这个值算出来、打印出来”不等于“这个项确实推动了actor参数更新”。这是旧actor更新的限制，不能拿平滑日志当作额外安全证据；它与上面B网络实际进行的平滑训练不是一回事。

新R2独立屏障实验实际跑了80轮、每轮10个epoch，最佳候选出现在第76轮。它回答“固定这个新控制器，能否训练出原口径代理屏障”，不是“控制器与SBC已经共同变得更安全”。

#### 6.8 训练完成后 怎样检查而不是只看loss

原后端的检查至少包括区域界和动态条件两部分。区域检查尝试对小格计算网络输出界，而不是只用训练时那256个区域样本：

| 日志字段 | 程序要估计的量 | 怎样理解 |
|---|---|---|
| `ub_init` | 初始区屏障上界 | 从出发区域看，最高风险刻度是多少 |
| `lb_unsafe` | 不安全区屏障下界 | 进入危险区时，刻度最低是多少 |
| `domain_min` | 定义域屏障下界 | 给刻度提供共同平移基准 |
| `hard_violations` | 原动态检查中不满足无补偿条件的点数 | 是屏障条件违反，不是撞车次数 |
| 补偿违反 | 额外加入状态小格/梯度补偿后仍不满足的点数 | 比无补偿条件更严格，应另外报告 |

动态检查从100×100网格出发，但原实现会先按B的归一化值筛选，主要检查接近不安全区刻度的95%～100%窄带。这个“带”是按屏障值选的，不简单等于障碍物前某几米。**训练用全域网格，不代表验证对全部10000点都检查了下降条件。** 最小DINO-SPVC实际窄带82点，新R2屏障独立基线为112点。

验证阶段也不是再随机抽16个噪声结果就结束，而是将噪声范围划为小格，调用旧区间输出界并按小格概率加权。其目的是约束平均后继B；但旧区间接口及补偿有效性曾有审计问题，保留原实现不等于这些问题已经解决。

原代码硬违反比例阈值为0.1%，分母沿用10000点缓冲区。因此日志中1/10000可能被判为通过，即使实际进入动态检查的只有112点；它既不是零违反，也不是10000点全部通过。

还要区分训练计数与验证计数：训练日志`train_violations_l`按“16个后继的平均B不低于当前B”计数，没有包含0.1裕量；动态训练损失包含这个裕量。因此可能出现原始违反率较低、动态损失仍非零。两者不能当作同一个通过条件。

#### 6.9 概率读数是怎么得到的

若程序得到有限且正确分离的区域界，原读数可概括为：

```text
m = 定义域下界
u = 初始区上界
l = 不安全区下界

原安全到达概率读数 = 1 − (u − m) / (l − m)
```

直观上，初始区刻度越靠近域内最低值、离不安全区刻度越远，读数越高。新R2独立基线的 `u≈1.066446、l≈19.833374、m≈0.271146`，代入得到约95.9345%；同时实际窄带112点、硬违反1。前面最小替换版的95.6169%属于另一套保存模型。

这个公式是在解释程序怎样产生读数，**不是只要三个区域数值代入就完成证明**。若动态条件不成立、区间界无效、噪声不匹配，或图像路径误差没有包含进来，就不能把它当成实际图像控制器的可靠安全下界。训练时区域目标95%、旧验证器构造参数中的90%、最终95.9345%读数也属于不同设置与输出，不能互相替换。

#### 6.10 为什么必须对保存模型再查一次

原交替循环可能先验证当前B和actor，随后继续更新actor再保存。这样日志对应的是更新前控制器，而保存文件已经是更新后控制器；即使屏障权重没变，原检查结论也不能直接搬过去。

因此需要保存并重新加载同一套表示/q、actor和B，重建针对该屏障的检查包装，再计算区域界、实际窄带、硬违反、补偿违反与概率读数。新R2屏障独立基线还逐张量核对q和控制器确实未改，避免“固定PPO”只写在配置里。

这一阶段完整交付的应是：**候选屏障权重、对应控制器身份、训练配置、各项损失记录、最终保存模型检查结果，以及保证适用范围。** 当前交付的是原实现口径的代理SBC基线；它没有直接读入真实图像误差，仍需第七步及后续CP/风险转移工作。

本节解释的是已经做过的原SPVC口径训练，不把后续轨迹场景SBC、NBC或有限时域新候选混进同一损失。最新三组有限时域候选与其未通过原因，另见[技术记录第十八节](CP与SBC安全余量实验_逐步说明.md#十八-回到sbc主线-概率条件不是所有转移都下降)。

对应实现：[屏障损失与训练](../../artical-F122/Aebs/VT/train.py)、[网络与噪声采样](../../artical-F122/Aebs/VT/utils.py)、[物理区域与噪声定义](../../artical-F122/Aebs/system/env.py)、[原交替循环](../../artical-F122/Aebs/VT/loop.py)、[原检查器](../../artical-F122/Aebs/VT/verify.py)、[新R2只训屏障入口](../../artical-F122/Aebs/dino_latent/train_native_sbc_legacy.py)。

### 第七步：单独核对“代理与实际图像到底差多少”

不能用代理上的SBC检查代替这一步。我们在同一图片、同一物理状态、同一控制器下比较两条路径：

```text
真实图像 → z_img → a_img → v_next_img
标签距离 → z_q   → a_q   → v_next_q
```

两条路径的下一速度差是更直接的任务误差。这里不需要图像与生成图逐像素相同，也不要求latent的每一维相同；但不能因为平均误差小，就忽略很少见的危险方向大误差。

## 五、表示学习与原SPVC替换：关键实验记录

### 实验1：R0→R1，先确认扩充外观数据是否有用

**问题：** 早期表示是否只适应原来的少量图像和外观？

**做法：** R0使用原外观子集约1181张训练图片，R1使用扩充后的14172张训练图片；DINO冻结，训练表示与q。都在4908张开发验证图像上检查，不使用保留test。

| 验证指标 | R0原外观版本 | R1多外观版本 |
|---|---:|---:|
| 两路径latent RMSE | 0.350721 | 0.058908 |
| 相对latent RMSE | 78.888% | 8.695% |
| 图像辅助距离MAE，米 | 1.753420 | 0.185920 |

**解释：** 扩充外观并重新学习后，泛化误差明显改善。这里的8.695%是误差相对latent变化尺度的比值，不是8.695%的样本失败，也不是碰撞概率。R0/R1取自历史阶段记录，后面的R2结果文件还保存了R1作为基线。

### 实验2：R1→R2，显式利用“同距离、不同天气颜色”

**问题：** 即使图片更多，同一物理距离的不同外观还可能被编码成不同摘要。

**配置：** 从R1继续学习；每批8个同距离外观组，组内一致性权重0.2；联合训练3000次更新，AdamW学习率0.0003。另尝试400次q单独拟合，保存最合适候选。

**实际选择：** 最佳联合步为2600；后续q单独拟合的最佳步为0，即额外400步没有被采用。不能把“程序跑了400步”写成“q又成功改进400步”。

| 验证指标 | R1 | R2 |
|---|---:|---:|
| 两路径latent RMSE | 0.058908 | 0.055999 |
| 相对latent RMSE | 8.695% | 7.633% |
| 图像辅助距离MAE，米 | 0.185920 | 0.165559 |
| 图像辅助距离RMSE，米 | 0.240156 | 0.213772 |
| q路径辅助距离RMSE，米 | 0.023216 | 0.004949 |

**得到什么：** 更好的R2投影与q，后续多条路线由它出发。

**说明什么：** 配对外观约束有帮助，但图像与q的误差仍不为零。q比图像更容易精确读出距离也不奇怪，因为q输入本来就是距离；不能拿q估距很准来证明相机估距同样准。

### 实验3：R2配完整PPO，检查是否真的能控制

**输入：** 冻结R2表示与q；第4节所述混合观测训练设置。

**输出：** PPO09及任务、动作一致性检查。

在早期图库近似评估中，代理400回合、12种训练外观各400回合均成功，共5200回合。精确配对开发验证另使用147240个非终止图像/速度组合，图像独有危险后继与代理独有危险后继均为0；两路径动作MAE约0.119587。

**解释：** 控制训练跑通，且给定这批验证状态，没有发现图像路径单独增加的一步危险。5200回合来自近似图库模拟，不是5200条新的CARLA同步图像轨迹；147240也不是回合数。后来的图库审计要求保留这个范围限制。

### 实验4：最小DINO前端接原SPVC，不改后端

**目的：** 先验证前端替换能否接回原来的学习和检查体系，不同时加入QP、CP、新噪声模型或新验证器。

**过程：** R2前端替代cGAN/原state_net，保留原PPO/SBC训练与VT检查设置；最终重新加载保存actor/SBC复查，确保验证对应保存模型。

| 最终保存模型复查项 | 结果 |
|---|---:|
| 完整网格状态数 | 10000 |
| 实际进入原下降检查窄带的状态 | 82 |
| 硬违反 | 1，原日志分母显示为10000 |
| 带补偿检查的违反 | 2 |
| 初始区屏障上界 | 1.183674 |
| 不安全区屏障下界 | 20.141102 |
| 定义域屏障下界 | 0.314660 |
| 原代码安全到达概率读数 | 95.6169% |
| 保存模型与验证一致 | 是 |

**结论：** 最小替换版能按原代码口径运行、分开区域并给出代理安全读数。原代码容许违反比例不超过0.1%，所以1/10000能满足它的阈值；这不是零违反。10000也不代表每个点都检查了动态下降，实际窄带为82点。

**尚未得到：** 真实图像路径的误差覆盖，以及在修正后的连续/区间口径下完整成立的端到端证明。不能把95.6169%读数直接写成真实相机控制器已有同等保证。

另一个历史R2检查点还做过“模型完全不动，只改变检查范围”的对照：

| 检查范围 | 实际检查数 | 硬违反数 |
|---|---:|---:|
| 原SPVC窄带 | 69 | 0 |
| 阈值以下安全区域 | 1332 | 103 |
| 全部安全网格 | 9253 | 109 |

这组69点与上述82点、后文112点属于不同检查点，不是结果前后矛盾。它说明同一个模型能通过窄带而不能通过更宽检查，必须连同检查范围汇报；没有证明原SPVC所有成功都只由窄带造成，也没有重跑原cGAN的同项对照。

对应历史actor更新也核对过：6个actor参数张量实际改变；在147240个精确验证组合上，双路径动作MAE从0.119587到0.119424，没有新增采样一步危险，但图像动作本身已有漂移。这是“更新没有在这些样本上恶化危险后继”的证据，不是“控制器从未改变”或“安全已证明”。

### 实验5：同场景同物理状态，DINO相较cGAN到底误差小多少

**为什么这样比：** 像素差与32维latent差单位不同，不能直接说“0.05小于图像误差，所以更准确”。我们使用相同4908张验证RGB、相同147240个非终止物理状态组合，冻结模型，不训练、不查最近图片。

比较两类量：当前距离的辅助读出；以及每种方法自己的实际图像路径与代理路径，经过对应控制器后造成的下一速度差。

| 相同开发样本下的指标                     |   cGAN基线 | 最小DINO-SPVC |
| ------------------------------ | -------: | ----------: |
| 实际图像距离MAE，米，旧图像0～1预处理          | 2.667726 |    0.165559 |
| 实际图像距离RMSE，米                   | 3.262061 |    0.213772 |
| 代理距离MAE，米，cGAN零随机输入            | 0.144614 |    0.004124 |
| 图像/代理下一速度差MAE，米/秒，cGAN均匀随机多次取样 | 0.074961 |    0.006044 |
| 上项RMSE，米/秒                     | 0.088620 |    0.022538 |

旧图像的另一种有符号预处理也做了检查，其图像距离MAE为2.639413米，结论方向未变。

**能说明：** 在这批相同开发样本、这套冻结模型和控制接口下，DINO方案显著降低了平均任务相关偏差。

**限制：** cGAN一侧使用仓库提供的基础PPO，不是已经核实的原论文最终SPVC控制器；这比较的是现有两套实现，不能当成只改变前端的严格单因素消融，也不能说推翻原论文。误差下降不是碰撞概率证明。共同R2语义空间的补充比较也存在任务训练评价器偏向，不能替代物理单位的比较。

## 六、为什么继续试q、新PPO和其他表示

### 实验6：冻结旧PPO，只把q拟合得更好，是否就够了

**做法：** 固定图像表示与旧控制器，重新拟合q，继续在同一批历史同步轨迹状态上计算两路径下一速度差。

| 旧控制器下的方案 | 速度差MAE，米/秒 | 轨迹参考半径/最大差，米/秒 |
|---|---:|---:|
| 原最小R2/q | 0.010053 | 0.178398 |
| 单独重新拟合q | 0.011771 | 0.186554 |

**解释：** q在latent拟合目标上改变，不一定让旧PPO的动作更一致。控制器可能对某些小方向变化很敏感。这个结果不支持“再多训几轮q就自然解决安全误差”。这里的参考半径来自已反复使用的459条旧轨迹，不能称为新策略的独立正式CP契约。

### 实验7：18组原生表示，各自重新训练对应控制器

**为什么重训：** 把不同表示强行送回旧R2控制器，会偏向R2接口。于是让不同表示在自己的坐标中训练q与PPO，而不是只比较距离读出或强行读回32维。

比较范围包括：R2的32维、DINO全局384维，以及PCA、AE、VAE、VICReg各16/32/64/128维，共18组。每组使用自己的标准化与q，PPO从头训练200704步、seed7；隐藏宽度和主要训练预算一致，但输入维度不同意味着参数量并非严格完全相等。

**输入：** 相同静态训练数据、相同历史参考状态和主要PPO预算。

**输出：** 每种表示自己的q/PPO，以及物理速度残差、图库开发任务表现。

| 代表方案 | 维度 | 参考速度差MAE，米/秒 | 参考最大差，米/秒 |
|---|---:|---:|---:|
| 新R2组合 | 32 | 0.004740 | 0.084412 |
| 直接DINO全局特征 | 384 | 0.040595 | 0.235666 |
| PCA | 16 | 0.027722 | 0.205805 |
| AE自动编码器 | 16 | 0.014752 | 0.179435 |
| VAE变分自动编码器 | 32 | 0.017346 | 0.132019 |
| VICReg表示 | 16 | 0.013837 | 0.157276 |
| VICReg表示 | 32 | 0.015459 | 0.150508 |

这里使用同一批37828个历史有效参考状态。新R2的P95为0.022312米/秒，没有参考点超过0.15米/秒。但0.15不是通用安全阈值，也不是过了这个数字就自动安全。

新R2在代理与训练图库开发任务上均100%成功；例如VAE32图库任务成功92.58%、危险3.42%，说明残差较小也不能替代任务检查。所有图库任务数值仍是近似模拟结果，不是新CARLA在线性能。完整18组数据见附录。

**当前选型结论：** 在本轮数据、训练方案和开发口径下，新R2是较合适的静态主线。不是证明32维普遍最好，也不是证明其他表示不能通过更合适目标训练得更好。

### 实验8：新R2组合再训练原口径SBC

**配置：** q和新PPO固定，只训练屏障80轮，每轮10个epoch；保留原噪声因子0.05、原后端和0.1%阈值。最佳候选在第76轮，保存模型与检查一致。

结果：10000网格中实际窄带112点，硬违反1；初始上界1.066446、不安全下界19.833374、定义域下界0.271146；原概率读数为95.9345%。

**得到什么：** 更低参考残差的新控制组合，也能训练出原口径代理SBC基线；不是只能给旧actor做证书。

**没得到什么：** 本轮没有把CP误差加入SBC，结果文件明确标记不构成图像路径形式化证书。95.9345%与前面95.6169%属于不同模型，不应拼成一次实验的训练曲线。

## 七、Transformer到底换了哪里，做出了什么

### 7.1 它不是简单把“32维”改成“Transformer”

DINO本身已经是视觉Transformer；新增实验研究的是另一个时间预测网络：根据最近几帧“看到了什么、做过什么动作”，预测将来会看到的表示。

```text
过去3帧图像 → 冻结DINO → 过去3帧表示
                                ↓
                 加入对应动作，部分版本加入速度
                                ↓
                      因果Transformer预测器
                                ↓
                   未来1/3/10步的预测表示
                                ↓ 仅作本轮评价
       与未来真实图像表示比较；送入固定PPO比较下一动作/速度
```

当前静态q是“给定当前真实物理距离，构造相应表示”；Transformer是“给定历史和查询动作，预测未来表示”。两者信息条件不同，不能只按某一误差列认定谁在同一任务上取代了谁。

### 7.2 具体怎么实现与训练

首轮使用459条已有同步轨迹，按整条轨迹分成367条训练、92条验证，得到28502个训练窗口和7085个验证窗口。每个窗口使用3帧历史，递推预测未来3步；相邻帧不能跨回合，未来真实latent仅用于监督，不作为输入。

默认32维版本把latent、速度、动作组成34维时间token；384维版本组成386维token，再映射到128维网络宽度。网络2层、4个注意力头、前馈宽256，采用因果掩码，防止模型偷看未来。预测采用残差结构，从“保持最后一帧”初始化；递推时用自己预测的latent，而非每步偷偷换成真实未来latent。

三组首轮模型均训练1200次更新，batch256、AdamW学习率0.0003、seed7。三帧历史跨度约0.1秒，三步预测为0.15秒；后面的十步预测为0.5秒，不是400步完整任务预测。

未来动作在离线比较中使用同一段记录动作，相当于问“如果执行这段动作，会看到什么”。这不是声称在线运行预先知道PPO所有未来决策。评价预测表示对控制的影响时，目标时刻速度提供给固定PPO；它不等于预测器看到了未来真实速度。

**与参考论文的区别：** 当前缓存是每帧一个384维全局CLS特征，不是完整空间patch网格；本轮属于受论文启发的全局特征小型适配，不是完整DINO-WM或该屏障论文的原样复现。384维预测为了接现有控制接口，还经过冻结R2投影，没有配一个全新的384维时序PPO/SBC。

### 实验9：首轮32维与384维预测对照

同一验证窗口、同一旧minimal控制器，一步预测表示引起的下一速度差为：

| 预测方法 | MAE，米/秒 | 最大差，米/秒 |
|---|---:|---:|
| 保持上一帧，不训练 | 0.012151 | 0.177296 |
| 32维MLP预测器 | 0.007574 | 0.175561 |
| 32维Transformer | 0.007026 | 0.177169 |
| 384维Transformer，经R2接口评价 | 0.008156 | 0.177169 |

**解释：** 学习时间变化比不预测好；32维Transformer本轮平均值较好，但最坏误差没有随之改善。不能用平均值降低替代安全余量改善，也不能从一次全局特征试验得出完整patch世界模型无用。

首轮按共同R2空间的验证误差挑选候选，这也偏向R2接口，不是各表示原生预测能力的最终排名。

### 实验10：速度是否必须拼接

同一首轮预测设置下，32维版本一步物理误差MAE：速度与动作拼接0.007026；不输入速度但保留动作0.006768；速度单独注入0.006987；图像历史版本0.006814米/秒。

**解释：** 预测器不显式拼接速度也能在这些轨迹上学习；但这个消融没有取消后续PPO的速度输入。不能据此说完整系统不需要速度传感器，也没有证明任意驾驶条件都能从短历史恢复速度。

### 实验11：增加多步与任务相关训练目标

进一步比较小MLP、参数量匹配MLP、普通Transformer、不输入速度Transformer、任务辅助Transformer、GRU、RSSM、线性提升模型和PCA表示预测等9组。

这轮按整轨迹划分321/69/69条，分别用于训练、候选选择和内部留出评价；训练800次更新、batch128、学习率0.0003。这里的内部留出不是一直保留的4920张RGB test，也不是新策略独立轨迹。

任务辅助Transformer除了预测特征，还要求辅助距离、固定控制器的动作读出接近目标。PPO在这个实验中冻结，梯度用于训练预测器，不是重新训练安全控制器。对照MLP约269984参数，Transformer约273952参数，减少了“只是网络更大”的混淆。

| 十步预测，经旧控制器评价 | 下一速度差MAE，米/秒 |
|---|---:|
| 小MLP | 0.013119 |
| 参数量匹配MLP | 0.011249 |
| 普通Transformer | 0.011872 |
| 不输入速度Transformer | 0.009946 |
| 任务辅助Transformer | 0.008607 |
| GRU | 0.013253 |
| RSSM小型适配 | 0.014868 |

任务辅助版本相对普通Transformer平均误差降低约27.51%，但多数候选最大速度差仍约0.207102米/秒。因此“让训练目标更关注控制”有效，但极端误差并未同步解决。这里的RSSM等是小型适配，不是完整Dreamer等控制算法复现。

## 八、最新统一误差评价：不再只比一个平均数

### 8.1 为什么又重做评价，而不是继续加模型

之前不同表格可能用不同控制器、不同轨迹帧、不同预测步长、不同聚合方式。数字变化不一定来自表示本身。近期先冻结模型，在同一批同步轨迹上重算，避免将评价条件差异误当算法进步。

新版比较不用最近图片；同一预测长度使用完全相同目标帧，比较九类候选分别接旧/新两个冻结控制器，形成50项路径与步长记录。一步36451、三步35533、十步32320个目标；跨步长进一步只比较相同目标状态的32320个交集。

这些459条轨迹由旧PPO09产生，已被反复用于开发。它们能用于固定样本误差诊断，但不能重新包装为新候选的独立CP校准，也不能当作新候选自主控制轨迹。

### 8.2 两种误差方向，安全含义不同

定义“候选下一速度−实际图像路径下一速度”：

- 若为负，代理预测车辆更慢，但图像控制下实际更快。代理把风险看轻，称为“代理过于乐观”。这尤其威胁从代理推断图像安全。
- 若为正，候选路径比图像路径刹得少、下一步更快。如果用候选替代图像控制，它也可能危险。

所以同时报告绝对误差与正负两个方向。只关注一个方向，可能遗漏另一种替换风险。

均值以“每条轨迹先平均，再对轨迹平均”为主要口径，防止长轨迹占更大权重；再报99分位、最差5%样本平均值和双侧极值。最差5%只是样本尾部统计，不是总体风险上界。

### 实验12：固定新PPO，比较静态q与时序预测器

以下使用同一批一步目标帧。单位均为米/秒；“最大代理乐观误差”不是最大绝对误差。

| 路径 | 轨迹等权MAE | 绝对误差P99 | 最差5%绝对误差均值 | 最大代理乐观误差 |
|---|---:|---:|---:|---:|
| 旧q | 0.010601 | 0.054533 | 0.050025 | 0.072443 |
| 新q | 0.004903 | 0.035787 | 0.030712 | 0.084412 |
| 参数匹配MLP预测 | 0.004111 | 0.035530 | 0.028971 | 0.073224 |
| 普通Transformer预测 | 0.004112 | 0.034641 | 0.028671 | 0.085299 |
| 任务辅助Transformer预测 | 0.003983 | 0.035462 | 0.028513 | 0.082713 |
| 首轮32维Transformer预测 | 0.003714 | 0.031588 | 0.026449 | 0.085299 |
| 首轮384维Transformer，经R2接口 | 0.004226 | 0.035180 | 0.029909 | 0.069030 |

**结论：** 新q比旧q改善了大多数样本的平均误差与尾部均值，但最大乐观误差不是每项都改善；32维预测在本表平均误差较好，384维兼容读出的最大乐观误差较小。没有一个数字能无条件宣布某方案“全局最好”。此外静态q与未来预测器信息不同，应在各自任务内比较，再分析对控制的共同影响。

当前新q在这批同步帧上的按帧MAE为0.004919，最大绝对差0.084412；首轮32维预测为0.003714/0.085299，384维兼容读出为0.004219/0.072142。它们与上表均值略有差异，是按帧等权与按轨迹等权的区别，不是两次模型训练。

### 实验13：不改预测器，只改后面控制器，误差会不会变化

同一首轮32维Transformer预测，接旧minimal actor时一步速度差MAE约0.007638、最大0.190757；接新原生PPO时约0.003714、最大0.085299。

**解释：** 误差还取决于控制器对表示的敏感程度。过去约0.15～0.2米/秒的尾部不能全部归咎于“DINO不够好”或“维度不对”。但是控制器改变也不保证所有方法、所有误差方向都改善，需逐项检查。

### 实验14：排除速度裁剪“掩盖动作差”的影响

因为速度限制在0到3，两条动作即使不同，下一速度也可能都被裁到0或3。新版同时报告动作差、裁剪前速度差、实际裁剪后速度差。

在一步36451个目标中，新q动作MAE约0.157593，裁剪前等效速度MAE约0.007880，而实际速度MAE约0.004919；有14351个目标，动作差大于0.001但物理下一速度差几乎为0。

**解释：** 物理速度差小是真实模型现象，不是计算错误；但它不表示两个latent或两个动作完全一样。涉及不同速度区间或多步风险时，不能只展示裁剪后的低均值。

### 实验15：补上表示自身的预测能力，而不只看R2读出

对于32维和384维预测，各自在自己的训练标准化坐标内，与“保持最后一帧”基线比较。一步原生RMSE分别从0.080685降到0.055089、从0.425886降到0.305512，均优于各自不预测基线；三步也改善。

**解释：** 两种预测器确实学到了变化，不只是碰巧让旧R2控制头输出相近。但两个空间尺度和信息不同，不能直接用0.055小于0.306，宣称32维预测本质比384维准确。

## 九、CP与SBC：做过哪些尝试，为什么没有直接得到最终证书

### 9.1 三个需要分开的命题

第一，**代理误差覆盖**：在指定分布的未来轨迹上，误差是否以高概率落在校准范围内？

第二，**控制器安全性**：如果误差按约定规律出现，控制器是否仍能避免进入危险区？

第三，**证书条件成立**：屏障的初始值、不安全区值和动态条件，是否对声明的状态、噪声与时间范围成立？

CP主要帮助第一个，不能自动代替第二、第三。一个范围覆盖了误差，但控制器承受不了这个范围，仍不能获得目标安全保证。

### 9.2 “99%覆盖、99%置信”分别是什么意思

覆盖谈的是未来轨迹：在约定分布下，希望至少99%的轨迹分数不超过阈值。置信谈的是校准程序：有限样本得到这个覆盖结论有多可靠。两者都不是“所有状态百分之百没问题”。

本项目部分实现采用带高置信覆盖的轨迹容忍界。以459条、最大值作阈值为例，在轨迹独立同分布、控制器与评分预先冻结等条件下，得到99%覆盖的置信值为 `1−0.99^459≈0.990079`。不能把某一条轨迹内的几万帧当作几万个独立校准样本，也不能反复在这459条上选模型后仍声称相同的独立校准结论。

尤其要注意：即使误差覆盖成立，也只是保证“误差在这个范围内”的概率。还要证明在该范围或随机规律下，控制器与屏障能导出目标安全界。

### 实验16：整条轨迹的速度残差CP参考

**数据流：** 同步图像轨迹 → 冻结表示与控制器 → 每步图像/代理动作 → 同一物理模型的下一速度差 → 每条轨迹取最差差异 → 用459条轨迹做统计校准。

早期匹配SPVC口径的输出为半径0.150685468米/秒，参数设置目标覆盖99%、置信目标99%，报告置信值约0.990079。后续改变控制器、q、统计帧范围后得到其他参考半径，不能将它们都称为同一条正式契约。

还做过54个登记路径/步长组合的旧控制器参考统计：minimal R2约0.178398，首轮32维Transformer一步约0.190757，任务辅助Transformer十步约0.220587米/秒。54项是路径与长度组合，不是54个独立完整控制系统。旧轨迹被反复使用、候选策略改变，故这些数值降为开发参考，不宣称新的独立CP保证。

### 实验17：把全局半径当成“每一步可任意出现”的误差盒，检查可行性

**目的：** 在继续训屏障之前，检查规定的系统是否本来就允许碰撞。

**做法：** 在400个任务起点，最长400步，分别持续施加零误差、正半径、负半径；用允许的极端序列寻找反例。早期半径0.150685的正方向持续误差使400个起点全部危险；即使按动作区间分别估计误差，正方向压力序列仍失败。

新R2半径已减为0.084412，又做了一次同类检查：零误差400成功；持续正半径400危险；持续负半径400超时。一个正误差反例从距离15米、速度约2.763米/秒出发，在第62步进入危险区。

**为什么这不等于实际图像控制必撞：** 盒模型允许每一步都向最坏方向、独立于状态地取误差；实际图像误差不一定能生成这样的持续序列。反例否定的是这套过强建模规格，不是所有随机SBC，也不是对实际图片轨迹的碰撞判定。

0.15米/秒恰好等于本模型0.05秒内最大制动动作3可降低的速度，说明该早期误差量级确实很大；但即使低于0.15，也不是充分安全条件，0.0844的反例已经说明这一点。

**结论：** 不继续原样训练这个已发现不可行反例的全局盒规格。仅增加epoch或收更多同类图片，不会自动排除模型允许的坏序列。

### 实验18：用实际轨迹转移训练场景SBC

**目的：** 不再人为每步拼接独立最坏误差，先利用同步轨迹真实出现的转移学习屏障。

早期按367条训练、92条验证轨迹推进了几轮：首轮下降条件几乎全不满足；增加安全访问区域约束与边界训练后，初始/不安全区域分离逐渐改善。第19阶段验证下降违反为131/7453，约1.76%，最差余量约−0.0000657，初始与不安全区域违反均为0。

**解释：** 已能把访问状态和危险区域分开，但还没有满足全部所选动态条件。不能因为数值很小就直接当成证书通过。另一方面，这里逐条转移检查的是具体训练规格；随机SBC理论通常要求条件期望不增加，不等于每一次随机转移都必须下降。因此还需要检查训练目标是否比真正需要的概率条件更强，或是否与终止处理不一致。

### 实验19：轨迹风险分数与CP，替代“最大单步误差乘全时域”

动机是：最大单步误差不一定每步持续出现。可以对整条轨迹累计风险变化，再校准整轨迹分数，保留误差随时间出现的结构。

早期冻结轨迹SBC校准曾得到459条成功轨迹，负阈值约−0.999808；但它不是原SPVC连续随机模型上的SBC证书，也不是后续新PPO的独立安全数据。

最近在新R2的固定训练图库近似模拟中，又训练了一个独立的小风险监测器，用200条开发回合、16242个转移、3000次更新，再做459条校准和1000条评价。预先指定的轨迹正变化分数阈值约−0.983190，1000回合成功，分数经验覆盖99.7%；“400乘最大单步增加”的保守分数阈值约+1.336335，没有通过。

**这说明什么：** 在固定图库模拟分布里，利用整轨迹变化比把最坏单步增加重复400次更不保守，是值得保留的思路。

**但为什么仍不作为最终SBC：** 这个风险监测器在不安全区域网格仍有16/10000个值不满足约束；它不是已验证SBC。更重要的是，这批数据来自近似图库模拟而非新同步相机闭环。负分数只有在监测器与危险事件之间的关系成立时，才有安全含义；单独一个负阈值不能自动推出真实系统安全。

### 实验20：改变图库分布，检查统计结论能否迁移

保持模型与原校准阈值不变，换成验证图库，1000回合中347成功、653危险；只保留q、但把输入距离量化为同一查图距离的反事实版本，1000回合也全部危险。

一开始这看似严重的图像泛化失败，后续审计确认检索距离错位是重要混淆因素。因此这些危险数不能直接解释为“新PPO对真实验证相机有65.3%碰撞率”。它证明的是：**旧图库模拟和原阈值不具备跨此种观测变化的保证，必须先修正评估环境。**

## 十、一次重要纠错：图像很多，为什么还会查错距离

### 10.1 不是检索程序乱查，而是子集有空洞

原全量数据每种外观约1999个不同距离，最大间隔约0.006006米；若只考虑这份完整静态表的最近距离匹配，其最坏误差约0.003003米。

但是距离块划分之后，单独训练图库最大间隔约0.756757米，单独验证图库最大间隔约2.006006米。验证子库对全域查询的最大错位约1.501502米。

程序穷举核对82437次查询，没有发现最近邻索引算法错误；缓存标签与原标签差仅浮点舍入量级。问题是“用不覆盖这个距离的子集当连续相机”，不是原数据只采了少量图，也不是已经证明拍照标签不准确。

例如模拟状态在8.0米，但子库最近只有9.0米图像，控制器看到的就是更远的障碍物。把此时误差全部算成latent不准、再给CP校准，就混入了本不属于实际同状态图像的错误。

### 10.2 怎样改评价，而不破坏留出划分

不把验证/测试图片回填训练库来美化成功率。静态比较使用每张图片自己的真实标签；时序比较使用轨迹同一时刻记录的图像；图库开发若不能满足观测对齐门槛，只能明确标为近似模拟，不用于主安全结论。

最新精确单步审计，对新R2控制组合得到：

| 数据 | 有效图像/速度组合 | 速度差MAE，米/秒 | 最大差，米/秒 | 图像独有危险后继 |
|---|---:|---:|---:|---:|
| 训练图片 | 371160 | 0.001569 | 0.038653 | 0 |
| 开发验证图片 | 147240 | 0.007391 | 0.141350 | 0 |

验证RMSE约0.019073，P95约0.045630，P99约0.086661米/秒。这一结果不查图，直接比较同一物理标签的图像和q，更适合说明前端差异。

训练表中有5395个“两条路径都产生危险后继”的组合，另有5个仅q危险组合；这些状态是人为遍历的图像/速度组合，不全是策略从任务起点能访问的状态，不能写成训练运行碰撞5395次。验证表的两路径共同危险数为0，也不意味着所有未测状态安全。

**最终保留的认识：** 图像/代理误差确实存在，但早期图库闭环给出的某些大误差和危险结论混入了查图错位，需要降级解释；不是用一个新均值直接覆盖旧负面结果。

## 十一、其他探索做到了哪里，为什么没有全部堆进当前框架

### 11.1 早期语义距离、过滤器、standalone PPO与物理可恢复集

DINO之前先做过直接语义距离、感知误差区间、鲁棒PPO和神经SBC；鲁棒PPO有过比基线更差的结果，神经屏障多轮调整仍未满足所选条件。后来安全过滤器能在有限评估中消除危险，但干预频繁，部分版本因保守而超时。

随后尝试把过滤器行为蒸馏到不带运行时过滤器的standalone PPO，并修复高低速边界；在四类误差模式有限回合评估中取得100%成功，分裂区间传播最终对手工定义物理可恢复域完成局部动作条件检查。还构造过可恢复/目标/危险三状态的有限状态屏障。

这些结果依赖当前制动模型的解析可恢复条件、误差假设和特定域，不等于当前DINO图像系统证书。后来提出希望提高通用性，没有把手工计算可恢复集作为现主线的解决方式。

### 11.2 QP可微层：修改动作的探索，不是当前主线已有安全保障

QP是二次规划：在尽量不偏离PPO动作的前提下，尝试满足由屏障提供的约束。可微层意味着优化结果还能把训练梯度传回上游网络。它与“只训练SBC来分析现有动作”是两件事。

早期采样诊断已经接通PPO/SBC到QP，并检查干预、线性近似和梯度。一次128状态诊断中干预46.09%、正松弛1.56%、最大松弛0.060072；松弛是允许约束暂时不满足的量，大于0不能称约束全部满足。

后续原始AEBS的20回合配对测试中，PPO与QP均20/20危险，QP没有产生超出动作裁剪的有效修正；并审计了原区间实现口径。这说明“接上优化层”不等于已经学得安全控制器。

当前DINO最小前端、18组新PPO与时序预测对照，不把这些QP结果当成部署组件；也不能把历史QP先导称为已成功实现当前全部网络联合安全训练。

### 11.3 借鉴Model-Free NBC：让屏障条件反过来影响PPO

**动机：** 先训任务PPO、再训SBC可能出现“控制器不适合被所选条件证明”。于是利用实际转移的屏障违规评分影响策略学习。

实现了以下链条：图像观测→PPO采样动作→记录物理后继→NBC计算成本→用新旧动作概率比把成本加入PPO损失→更新NBC。表示/q冻结；不等于已经把图像与代理的全部误差纳入理论保证。

首次联合、加入旧约束回放/候选保留修正、五步安全反馈，均做过8192步开发试验，并配同预算关闭安全反馈的普通PPO对照。固定同一个NBC、同294480个精确验证组合比较，避免屏障变化造成评分虚好：

| 方法 | 固定NBC下动态违反数 | 有限确定性图库回放 |
|---|---:|---:|
| 不继续更新的原控制器 | 13863 | 108/108成功 |
| 首次联合更新 | 14616 | 108/108成功 |
| 加入保留机制的联合更新 | 14583 | 108/108成功 |
| 同预算普通PPO对照 | 14508 | 108/108成功 |
| 五步安全反馈 | 14617 | 108/108成功 |

**结果：** 安全反馈确实参与梯度更新，但未证明比原控制器或普通PPO更安全。保留机制避免了首次出现的16个不安全区域符号错误，却拒绝了全部4轮NBC候选，没有完成NBC对新策略的有效适应。五步反馈也未带来所选验证指标改善。

因此保留这些作为负结果与工程经验，不把它们包装成当前已接受的安全控制器，也不把108/108近似图库成功当作真实安全证明。借鉴了训练反馈思想，不等于获得原论文全部假设与定理。

## 十二、现在能得出什么结论，下一步缺什么

### 12.1 已经形成的成果

**系统实现方面：** 形成了冻结DINO、可训练图像投影、物理q、PPO和原SPVC后端的可复现连接；有保存模型与检查身份核对，不只是画了一张架构图。

**数据方面：** 从少量单外观扩充到24000张配对多外观图像，完成分组留出、特征缓存和同步轨迹记录；明确了静态图片、一步组合与完整轨迹三种数据单位。

**误差方面：** R0/R1/R2展示了数据与配对学习带来的改善；同图同状态下DINO较现有cGAN基线平均物理后继偏差更小；新标准化/q/PPO组合进一步降低了参考轨迹误差。

**方法比较方面：** 完成多维静态表示各自配PPO的18组比较，以及历史预测、速度消融、任务辅助、参数匹配和同状态跨actor对照。明确了预测器、表示、控制器、裁剪和采样分布都会影响误差。

**安全分析方面：** 获得原代码口径代理SBC基线；用反例排除了持续全局最坏误差盒；试验了轨迹风险CP与NBC反馈，记录了失败和适用边界。现在的问题比“继续训SBC直到通过”更明确。

### 12.2 仍不能声称完成的事项

| 想证明的结论 | 当前状态 |
|---|---|
| DINO能替代生成图像前端，保留后端运行 | 已实现 |
| 本次开发样本上的平均任务相关偏差更小 | 有数据支持，受模型/基线/分布限制 |
| 32维一定优于所有其他表示 | 没有证明；本轮配方综合较好 |
| Transformer已经形成更好完整控制器与SBC | 没有；当前主要是预测对照 |
| 原代码代理检查给出约95%读数 | 已获得，存在非零违反、窄带与原实现口径限制 |
| 新图像闭环误差已经被正式CP覆盖 | 尚未完成适用于冻结最终策略的新同步独立校准 |
| 图像误差已纳入可靠的SBC安全保证 | 尚未完成 |
| 天气、路面、执行器等所有物理扰动已覆盖 | 没有；目前主要覆盖外观变化及所选模型/噪声假设 |

### 12.3 为什么是概率安全，还不能简单允许一部分节点违规

随机屏障常要求：给定当前状态，下一步屏障值的**条件平均**不增加，或其增加不超过规定预算；单次转移可以有升有降。这与“每一条随机转移必须下降”不同，也与“随机放过1%的网格点”不同。

如果被放过的少量点恰好集中在每条轨迹必经的制动边界，整体失败概率可能很大。若采用统计概率声明，需要明确轨迹/状态的分布、独立校准、时域和由评分事件推导危险事件的关系；不能用节点通过比例直接替代安全概率。

### 12.4 接下来最小而有意义的一步

不再同时更换表示、控制器、误差契约和验证域。建议优先冻结新R2原生组合，保留Transformer作为独立候选，按以下顺序补证：

1. **先固定声明对象。** 指定到底分析哪套图像投影、q、PPO，起点分布、外观范围、动力学、终止规则和400步时域是什么；随结果保存身份信息。
2. **为这个对象选择适合的概率SBC规格。** 不再使用已找到持续误差碰撞反例的无结构全局盒；区分条件期望约束与路径最坏约束，正确处理终止，不以放宽日志阈值制造成功。
3. **先检查证书可行性，再追加神经训练。** 有限时域、允许小期望漂移或更结构化的误差模型可以作为候选，但要先给出具体约束与验证结果。本报告尚无这些新候选已成功的实验依据。
4. **模型冻结后再取得对应策略的同步轨迹。** 原数据可继续开发，不因数量多就天然适用于新策略最终校准；复用数据与新采集的边界必须记录。
5. **最终同时交付任务与安全证据。** 包括成功/危险/超时、同状态误差尾部、SBC区域和动态检查、统计保证适用分布。不能只选一张好看的均值表。
