# DINO双路径方案：当前进度、实验结果与问题总结

更新日期：2026-10-05。

范围：本文总结当前“冻结DINO＋双路径32维latent＋PPO”的方案，并说明与之前方案的区别。不把旧语义编码器、旧控制器、旧SBC或QP的结果当作当前模型的结果。

## 1. 先说结论：现在做到哪一步了

**已完成数据扩充、数据检查与划分、DINO特征提取、双路径联合训练，以及适配新表示的PPO训练和开发评估。**

最重要的进展：在相同新验证集上，多外观训练将两条latent路径的相对误差从 **78.89%降至8.70%**；新PPO在代理路径和多数外观的训练图片库回放中成功完成任务。

尚未完成：阴天回放仍有10次不安全，准确配对诊断存在3个图像路径独有的一步不安全；剩余表示误差尚未形成有效的误差契约；当前模型的SBC、安全保证及真实在线图像闭环均未完成。

**因此当前状态是：有明确的表示改善和可运行控制流程，但还没有得到端到端安全保证。**

## 2. 当前系统到底是什么

### 2.1 两条表示路径

```text
图像路径：RGB图像 → 冻结DINO（384维）→ 可训练投影网络 → z_image（32维）
物理路径：物理距离d → 小型映射网络q → z_phys（32维）
```

latent就是网络内部的一组数字。希望两条路径在对应同一物理状态时，输出接近的、对控制有用的信息。光照和车身颜色可以不同，但不能因此让控制相关表示大幅改变。

物理网络目前输入距离，并不是能描述任意驾驶场景的完整状态。其适用范围和当前AEBS任务一致，不应夸大成通用自动驾驶表示。

辅助距离解码网络用于检查和训练“latent仍保留距离信息”，不是把最终表示换回一维距离。PPO输入是 **32维latent＋速度，共33维**。

### 2.2 当前已经跑过的闭环

```text
AEBS仿真物理状态
  → 物理代理latent，或训练图片库检索出的图像latent
  → PPO动作
  → 原AEBS状态更新、奖励和终止判断
  → 下一物理状态
```

这已经是仿真控制闭环，但图像模式使用静态图片库最近邻回放，**不是每一步在CARLA实时生成图像再识别的在线闭环**。

当前执行链条没有接入运行时safety filter、QP或CP，当前R1模型也没有训练完成SBC。历史方案中这些模块曾做过的实验，不代表它们已经适配了当前DINO模型。

## 3. 数据方面做了什么

### 3.1 先纠正了采集方式偏离原实验的问题

早先新增采集器采用camera sensor、多道路锚点、固定相机参数。虽然便于同步标注，但改变了画面构图，用户观察到近距离车辆在画面中的大小与原实验不一致。

之后参考genGANData恢复桌面截图时，仍使用了固定截图矩形和不同地图索引；这也不是用户实际认可的版本。

最终直接读取CARLA机器上的 **spvc_carla.py**，以它为准，保留：

- available_maps[3]加载地图，spawn_points[4]放置车辆；
- Tesla车型，默认晴天红车；
- spectator沿实际车辆朝向后退，相对高度2米；
- 移动后等待0.3秒；
- mss读取主显示器全屏，BGRA转BGR，再缩放640×640。

新增入口为 `Aebs.connect.collect_spvc_expanded`。没有覆盖用户原脚本，也没有把不同采集方案的数据混入本次实验。

### 3.3 验收与固定划分

自动审计：24,000张均能完整解码；decode_errors=0、near_constant=0、cross_split_duplicate_groups=0。

按0.25米距离区间划分44组，16米并入最后一组。同一区间的全部天气、颜色和重复样本属于同一集合。

| 集合 | 距离组数 | 图片数 | 已使用方式 |
| --- | ---: | ---: | --- |
| train | 26 | 14,172 | 表示训练、PPO训练图片回放 |
| validation | 9 | 4,908 | 选表示模型、表示评估、配对动作诊断 |
| test | 9 | 4,920 | 仅做数据质量检查与划分；未提特征、未做模型评估 |

这避免了逐张随机分割把同距离外观泄漏到不同集合，但相邻距离区间仍可能非常相似。不能声称它们统计独立，也不把此划分称为未见天气或未见场景测试。

## 4. 特征与表示训练做了什么

### 4.1 新数据入口与H5

旧入口读取400张灰度H5，不能直接读新RGB目录。已新增：

1. `prepare_expanded_data`：验收并生成固定split manifest。
2. `cache_expanded_features`：按manifest读取RGB，提取冻结DINO特征，保存H5及元数据。

H5结果：**19,080×384维**，涵盖训练和验证；DINO冻结、test_encoded=0，耗时192.09秒。H5只是存储格式，384→32由后续可训练投影网络完成。

### 4.2 R0与R1对照

| 项目 | R0_original | R1_all_appearances |
| --- | --- | --- |
| train图片 | 晴天红车，1,181张 | 全部外观，14,172张 |
| validation | 同一4,908张 | 同一4,908张 |
| 联合更新 | 9,250步 | 9,250步 |
| 网络/种子 | 同结构、seed7 | 同结构、seed7 |
| q后拟合 | 400次更新 | 400次更新 |

特征归一化与距离尺度分别由各自允许的训练子集计算。训练按距离区间均衡抽样，不使用test。

本轮H5只有原RGB特征，没有旧合成增强视图，因此两组都未使用历史synthetic invariance项，也未加入新的真实配对损失。模型选择统一使用“验证辅助距离归一化RMSE＋0.2相对latent误差”。这些变化已预先记录，因此主要比较本轮R0/R1，不声称严格复现历史B算法。

共同更新数不等于严格相同计算成本：q后拟合是全批，R1每次使用更多样本。本轮只有一个种子，尚无多次重复实验的统计结论。

| latent RMSE | 0.350721 | **0.058908** |
| 相对latent误差 | 78.8881% | **8.6953%** |
| 残差长度P95 | 3.014422 | **0.647734** |
| 最大残差长度 | 4.088566 | **1.288736** |
| 图像辅助距离MAE | 1.753420米 | **0.185920米** |

相对latent误差相对下降约88.98%。R1并非把全部输出缩成常数：表示尺度没有缩小，辅助距离和状态分离也改善。

但R1训练相对误差2.95%、验证8.70%，仍有泛化差距。P95和最大值也非零。这里的8.70%是表示误差比例，不是不安全概率。

### 4.4 详细检查的发现

- R1的12外观组合，原始latent RMSE均低于R0对应组合；总体相对误差和辅助指标改善为这一结果提供额外支持。
- 晴天红车验证RMSE也由0.1338降至0.0675，不是只改善新增外观。
- 阴天红车是R1外观组中误差较大的组合，RMSE约0.0710。
- 验证区间15～15.25米、7.5～7.75米平均误差较大；12.25～12.5米包含最大单样本残差。
- 抽查019375.png、003852.png、000501.png未见终端/桌面遮挡；阴天图片天空发黑。这个渲染现象值得记录，但没有证据证明它就是误差根因，未删除这些图片。
- R1最佳联合checkpoint在最后9250步，后期仍有波动和改善，不能声称已完全收敛。

## 5. PPO方面做了什么与实际结果

### 5.1 实现

新增 `run_expanded_ppo`，固定R1网络和归一化，重新训练33维输入PPO，计划20万步，seed7、CPU。保持原AEBS环境的动力学、奖励、动作范围和终止条件。

训练每回合50%使用物理q路径、50%使用训练图片库。图像回合均匀选择天气/颜色并在该回合固定，最近邻只从该外观的train图片中查找。

这样修正了一个新数据接入问题：旧nearest逻辑在同距离有12张图时，可能一直取第一张，导致其他外观没有真正参与控制训练。这里只改观察数据选择，不改物理任务定义。

### 5.2 开发闭环回放结果

每个模式400个固定起点：距离15～16米、速度2.5～3米/秒的20×20网格。各外观重复使用同一套起点，不是互相独立的新400起点。

图像最近邻匹配距离误差均值约0.049～0.050米，最大约0.37838米。由于train故意留出了validation/test距离区间，运行中不一定有完全对应距离的训练图片，回放并非真实状态下实时观察。

### 5.3 准确配对的一步诊断

为避免最近邻混淆，使用每张图自身标签距离，与31个速度组成状态；在同一状态下分别输入图像latent和q latent，比较PPO动作及原AEBS一步更新结果。已经终止的起点另行排除并记录。

| 指标 | train | validation |
| --- | ---: | ---: |
| 图片数 | 14,172 | 4,908 |
| 检查的非终止图像—速度对 | 371,160 | 147,240 |
| 动作MAE | 0.025295 | 0.145254 |
| 最大动作绝对差 | 1.864548 | **4.665221** |
| 图像动作少制动的比例 | 6.30% | 4.85% |
| 仅图像路径下一步unsafe | **3** | 0 |
| 仅代理路径下一步unsafe | 0 | 0 |
| 两条路径都下一步unsafe | 5,328 | 0 |
| 下一步类别不一致 | 3 | 0 |

这里lookup_distance_error=0，因为没有检索另一距离图片。但零一步类别不一致不等于动作相同，也不等于整条轨迹安全。

train与validation覆盖不同距离区间，验证起点难度不等同于训练起点。不能因validation的unsafe数量更少就说其比训练集更安全。5,328个both unsafe是否不可避免，当前没有逐例验证，不沿用旧数据中94个案例的解释。

## 7. 当前证据能说什么、不能说什么

可以说：

- 在本轮固定数据划分和训练设置下，多外观数据改善了表示一致性，同时保留了更多距离信息。
- R1适配的新PPO在代理路径与多数训练外观库回放中完成任务。
- 已找到明确的剩余失败场景和尾部动作差异，后续可以有针对性诊断。

不能说：

- 两条latent路径已经完全一致，或剩余误差已被契约覆盖。
- 8.70%表示不安全率，或P95是95%安全保证。
- 所有连续状态、所有感知误差、未见天气/场景都安全。
- 静态图片库回放就是实时CARLA视觉闭环。
- 当前SBC已经训练成功，或旧模型的概率数字可以用于新模型。

## 8. 下一步只做固定模型失败诊断

先不重训、不打开test、不改变安全阈值，也不重新随机划分数据。

1. 从回合记录取阴天浅灰9个、阴天红1个失败起点，固定当前PPO/R1重放。
2. 每步记录物理距离/速度、检索图片ID及标签距离、图像与q动作、后继状态和终止原因，找到第一次关键分歧。
3. 重新扫描准确配对，定位3个图像独有unsafe。当前摘要只给计数，最差动作差样本未必包含这3例，不能假定已找到。
4. 查看validation最大动作差附近样本和速度，确认是否集中在动作切换边界；大差异不自动等于不安全，但值得追踪。
5. 根据证据决定下一步：检索偏差主要影响则改评估设计；控制对小残差敏感则考虑训练鲁棒性；表示有明确结构性错误才增加配对约束。

不把validation反例直接加入训练，不以删除失败起点、收缩域或调终止阈值来制造成功。需要调整任务定义时必须另列实验并说明。

这一步完成后，才决定PPO修复和误差契约的具体路线。SBC应对当前固定模型与误差假设重新建立，不能复用旧结论。

## 10. 对导师汇报的一段话

我们当前把图像通过冻结的DINO转换为特征，再学习一个32维控制表示；同时学习从物理距离到同一表示空间的小网络，希望两条路径对同一状态的描述接近。为解决旧数据外观单一的问题，我们保持原采集方式，扩充了距离、天气和车身颜色，得到24,000张配对图片，并按距离区间隔离训练、验证和测试。在相同验证集上，多外观训练把相对latent误差从78.89%降到了8.70%，辅助距离估计也明显改善。随后冻结表示训练PPO，代理路径及12种外观中的10种回放全部成功，但两种阴天外观仍出现10次不安全；准确配对也发现3个图像路径独有的一步失败。说明表示和控制流程已取得效果，但还存在尾部误差与安全问题。下一步先固定模型定位这些失败，再决定针对性改进，并把剩余误差纳入契约和SBC，而不是现在就宣称闭环安全。
