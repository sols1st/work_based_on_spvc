## 当前统一结论与SPVC异同

**已经得到原SPVC实现口径的“非空窄带零硬违反＋区域值分离”结果，尚不能表述为已经获得与原论文同等级的端到端安全保证。**

- 第21步轨迹CP与第22步代理SBC是不同证据；必须核对最终策略身份，不能直接合并成更强保证。

## 0.3 CP鲁棒SBC第一次训练结果与当前判断

第一次全局盒鲁棒SBC使用正式契约 `q_hat=0.150685468`，把每一步速度残差写成
`[-0.150685468,+0.150685468] m/s`，并要求整个物理状态矩形中的所有非终止状态都满足最坏场景下降。结果为：下降违反
`8884/8910`、初始区域违反`5942`、不安全区域违反`1651`，最小下降裕量为`-0.050334990`。这不是可以直接解释为“多训练几轮即可消失”的小误差。

当前需要先区分两种原因：

1. 神经SBC的优化没有找到可行解；
2. “每一步均可独立选择全局最大正残差”的盒式规格本身不可行。

新增 `Aebs.dino_latent.diagnose_cp_box_feasibility`。它从登记初始区域的固定网格出发，分别使用`-q_hat`、零残差和`+q_hat`进行400步闭环诊断。若持续`+q_hat`这一条被当前全局盒允许的残差序列就能从任一登记初始状态进入不安全区，则初始低值、不安全高值和全程不增加三项SBC条件在数学上不可能同时成立；此时不再盲调训练权重，而应把全局盒改成预先登记的状态条件契约或独立轨迹场景方法。若未找到反例，也只能说明没有简单反例，不能据此宣称可行或安全。

诊断已经得到决定性反例：`-q_hat`和零残差下400/400安全终止，持续`+q_hat`下400/400进入不安全区。第一个反例从`[15.0 m,2.5 m/s]`出发，在第61步到达`[5.88498 m,3.0 m/s]`。此时PPO已输出最大制动`3.0`，名义速度每步下降`3×0.05=0.15 m/s`，但全局盒仍允许每步增加`0.150685468 m/s`，因此这个假想扰动可以持续抵消最大制动。结论是：**当前全局残差盒对应的鲁棒SBC规格数学上不可行，不能靠增加epoch或重新加权修复。**

下一步新增`Aebs.dino_latent.diagnose_action_conditional_contract`，只作为开发诊断：按当前PPO名义动作分组，统计现有459条轨迹各动作区间中实际出现的下一速度残差，再用每组经验最大正残差做闭环压力测试。它回答“全局最大误差是否被错误地搬到了最大制动状态”。因为这459条数据已经被查看并用于选择新方法，所以得到的分组包络不能直接称为新CP保证；若结果有希望，必须先冻结动作分组和分数公式，再采集一套新的独立轨迹做正式校准。

动作条件诊断同样失败：最大制动区间`[2.5,3.0]`内的经验最大正残差仍为`0.147900537 m/s`，按动作条件最大值重复施加时400/400初始状态仍进入不安全区。继续叠加人工距离/速度小格会逐渐变成针对旧459条数据的包络拟合，既容易产生空格回退问题，也不能继续把同一批已查看数据称为正式校准集，因此停止这条不断分箱的路线。

新的主路线改为真正的轨迹场景SBC：`Aebs.dino_latent.train_trajectory_scenario_sbc`直接读取459条真实闭环轨迹中实际连续出现的`(state,next_state)`，按完整轨迹80%/20%划分开发训练与验证，训练初始区低值、不安全区高值和观测轨迹转移不增加。到达安全终止状态的后继值按停止过程置零，不再要求全矩形域承受任意拼接的全局最大残差。该459条数据在这一步明确降级为开发数据；只有开发验证通过并冻结SBC以后，才采集一套全新独立轨迹，对每条轨迹的最大SBC违反分数做正式CP校准。这种方法不使用人工可恢复集，且避免把不同时刻的极端误差拼成从未观测过的虚假轨迹。

轨迹场景SBC v1仍未通过：训练转移`29901/29970`、验证转移`7434/7453`违反不增加，比例均约99.7%；但459条轨迹中没有发现不安全后继。训练与验证的最坏裕量、平均裕量几乎一致，说明主要不是验证集泛化崩溃，而是v1目标欠约束：它只要求初始区低和合成不安全区高，没有直接要求整条已知安全轨迹保持在低值盆地，网络因而沿接近目标的安全轨迹逐步升高。v2保留相同轨迹划分和安全定义，只新增“安全轨迹占用低值”损失，并把区域损失权重从20提高到100；训练时初始区和不安全区使用小的内部裕量，验证仍使用原阈值0.01和1.0。下一次运行必须使用新输出目录，不覆盖v1。

v2取得大幅但不完全的改善：训练/验证下降违反率分别从约99.7%降到5.77%/6.15%，验证平均偏差仅`-1.329e-6`、最坏偏差`-3.487e-4`；初始区`0/10000`违反，安全轨迹P95 SBC值约`5.49e-6`。剩余不安全区仅5个网格点违反，但最小值仍为0.232，定位到`v`刚超过0.5的窄边界。v3作为静态SBC的最后一次针对性修改：将一半不安全训练样本固定覆盖`v=0.5001/0.501/0.505/0.51`并沿`d∈[5,6]`铺开，下降权重提高到500、区域权重提高到200、不安全内部训练目标提高到1.2。若v3仍不能满足严格开发条件，则停止继续调静态SBC，转向时间相关SBC或直接轨迹事件CP。

v3完成了区域条件：初始区与不安全区网格违反均为0，不安全区最小SBC值为1.529；验证安全轨迹P95 SBC值约`4.91e-8`。严格下降仍有`131/7453=1.76%`违反，但平均幅度仅`-9.92e-8`、最坏幅度`-6.57e-5`。按照预先写明的停止条件，至此冻结v3，不再以增加epoch或权重追逐浮点意义的严格0违反。

下一步采用轨迹级CP吸收这些微小剩余违反。新增`Aebs.dino_latent.calibrate_trajectory_sbc_cp`，对每条全新独立轨迹计算停止屏障分数：`B(s0)+sum_t max(B(s_{t+1})-B(s_t),0)-1`。定义安全终止时`B=0`、进入不安全集合时`B=1`，因此任何不安全轨迹的该分数必定非负；若新校准集得到的轨迹级CP阈值`q_hat<0`，即可把99%/99%轨迹覆盖结论转成登记分布和400步范围内的安全结论。旧459条轨迹已经训练v3，不能再次校准；必须用新种子采集至少459条、冻结DINO/R2/PPO/SBC且不进行模型选择的新轨迹。

为保证采集前冻结实验，新增`Aebs.dino_latent.register_trajectory_sbc_cp`。它在新数据采集前保存v3屏障、R2表示、PPO和旧开发H5的哈希，固定新采集种子91009、459条、400步、原SPVC全屏协议、`epsilon=beta=0.01`及`q_hat<0`通过条件。正式校准入口强制核对登记文件、新H5采集配置和全部模型哈希，并拒绝复用SBC训练H5。

## 1. 先说结论：现在做到哪一步了

**已完成数据扩充、数据检查与划分、DINO特征提取、双路径联合训练，以及适配新表示的PPO训练和开发评估。**

最重要的进展：在相同新验证集上，多外观R1将两条latent路径的相对误差从 **78.89%降至8.70%**；进一步的R2同距离外观对齐将其降至 **7.63%**。R2的P95由0.6477降至0.5948，图像辅助距离RMSE由0.2402 m降至0.2138 m；无latent坍缩，但单样本最大L2由1.2887升至1.3789，不能声称所有样本都改善。

已完成固定模型失败复现、插值回放对照、鲁棒PPO v1、R2表示和从头适配R2的新PPO。R2-PPO在q路径和12种train外观nearest回放中均400/400成功；train精确配对动作MAE由R1-PPO的0.02530降至0.01985，图像独有unsafe由3降至0；validation动作MAE由0.14525降至0.11959且无单侧unsafe。

2026-10-08已完成原SPVC截图协议下的在线开发轨迹和正式独立校准。30条开发轨迹全部success，动作反向饱和为0，轨迹最大下一速度残差中位数0.078326 m/s、P95为0.113134 m/s、最大0.136435 m/s。随后用全新种子采集459条正式轨迹并生成轨迹级CP契约：`q_hat=0.150685468 m/s`、置信度下界0.990079，对应物理残差箱`distance=[0,0] m`、`speed=[-0.150685468,+0.150685468] m/s`。该契约只说明同分布新轨迹的双路径下一状态残差覆盖，不单独等于安全证书。

此前Town10HD_Opt加`camera.rgb`的459条校准轨迹全部达到0.3 m/s物理最大残差，并出现182条unsafe；经自检确认其地图和相机协议均偏离训练数据。该结果仅保留为分布外失败诊断，不进入当前主结论。当前尚未完成：正式CP契约对应的SBC训练与连续域可信验证、独立test最终评估。

**因此当前状态是：有明确的表示改善和可运行控制流程，但还没有得到端到端安全保证。**

## 2. 当前系统到底是什么

### 2.1 两条表示路径

```text
图像路径：RGB图像 → 冻结DINO（384维）→ 可训练投影网络 → z_image（32维）
物理路径：物理距离d → 小型映射网络q → z_phys（32维）
```

latent就是网络内部的一组数字。希望两条路径在对应同一物理状态时，输出接近的、对控制有用的信息。光照和车身颜色可以不同，但不能因此让控制相关表示大幅改变。

物理网络目前输入距离，并不是能描述任意驾驶场景的完整状态。其适用范围和当前AEBS任务一致，不应夸大成通用自动驾驶表示。

辅助距离解码网络用于检查和训练“latent仍保留距离信息”，不是把最终表示换回一维距离。PPO输入是 **32维latent＋速度，共33维**。

### 2.2 当前已经跑过的闭环

```text
AEBS仿真物理状态
  → 物理代理latent，或训练图片库检索出的图像latent
  → PPO动作
  → 原AEBS状态更新、奖励和终止判断
  → 下一物理状态
```

这已经是仿真控制闭环，但图像模式使用静态图片库最近邻回放，**不是每一步在CARLA实时生成图像再识别的在线闭环**。

当前执行链条没有接入运行时safety filter、QP或CP，当前R1模型也没有训练完成SBC。历史方案中这些模块曾做过的实验，不代表它们已经适配了当前DINO模型。

## 5. PPO方面做了什么与实际结果

### 5.1 实现

新增 `run_expanded_ppo`，固定R1网络和归一化，重新训练33维输入PPO，计划20万步，seed7、CPU。保持原AEBS环境的动力学、奖励、动作范围和终止条件。

训练每回合50%使用物理q路径、50%使用训练图片库。图像回合均匀选择天气/颜色并在该回合固定，最近邻只从该外观的train图片中查找。

这样修正了一个新数据接入问题：旧nearest逻辑在同距离有12张图时，可能一直取第一张，导致其他外观没有真正参与控制训练。这里只改观察数据选择，不改物理任务定义。

## 7. 当前证据能说什么、不能说什么

可以说：

- 在本轮固定数据划分和训练设置下，多外观数据改善了表示一致性，同时保留了更多距离信息。
- R1适配的新PPO在代理路径与多数训练外观库回放中完成任务。
- 已找到明确的剩余失败场景和尾部动作差异，后续可以有针对性诊断。

不能说：

- 两条latent路径已经完全一致，或剩余误差已被契约覆盖。
- 8.70%表示不安全率，或P95是95%安全保证。
- 所有连续状态、所有感知误差、未见天气/场景都安全。
- 静态图片库回放就是实时CARLA视觉闭环。
- 当前SBC已经训练成功，或旧模型的概率数字可以用于新模型。

## 8. 固定模型失败诊断结果与下一步

本阶段没有重训、没有打开test、没有改变安全阈值，也没有重新随机划分数据。

已新增 `Aebs.dino_latent.diagnose_expanded_failures`。它只加载固定的R1、PPO、train/validation缓存和原PPO适配文件；强制核对输入哈希、PPO完成指标及`test_used=False`，不训练模型。默认重放全部12种训练外观的原20×20网格，并重新扫描train/validation精确配对。

服务器运行命令：

```bash
cd /root/work_based_on_spvc/artical-F122
/opt/miniconda3/bin/conda run --no-capture-output -n vt \
python -m Aebs.dino_latent.diagnose_expanded_failures \
  --cache-dir results/dino_expanded_v1/02_dino_h5 \
  --representation results/dino_expanded_v1/03_alignment_r0_r1/R1_all_appearances/dino_safety_latent.pt \
  --ppo-dir results/dino_expanded_v1/04_R1_ppo \
  --output-dir results/dino_expanded_v1/05_failure_diagnostic
```

输出包括`unsafe_rollout_traces.json`（每个不安全回合的逐步状态、最近图片和双路径动作）、`matched_image_only_unsafe.json`（全部精确配对图像独有失败）、`matched_outcome_disagreements.json`和`metrics.json`。实际运行完整复现原04结果：`source_result_counts_match=True`，回放10次不安全，train精确配对3个图像独有不安全，validation为0；动作MAE也复现为train 0.025295、validation 0.145254。

### 8.1 阴天回放失败

- 9个阴天浅灰失败在关键步都使用`018550.png`，1个阴天红失败使用`002550.png`。
- 当时真实物理距离约7.500～7.504米，而两张图片标签距离均为7.752753米，最近邻距离误差约0.25米。
- 当前状态的q动作已经达到3.0；图像动作分别约0.554和0.938，少制动约2.446和2.062。
- 把q输入改成图片自己的7.752753米标签后，q动作约1.445和1.522，与图像动作的差缩小到0.891和0.583。因此最近邻错配解释了动作差的主要部分，但不能解释全部差异。
- 最终不安全步两条同状态动作都已不安全，说明关键损失发生在更早的制动切换阶段，不能只检查终止前一步。

### 8.2 精确配对失败

3例均来自train雨天图片，状态约为6.02米、0.6米/秒：`014204.png`、`022204.png`和`022205.png`。图像动作比q动作少制动约0.525、0.860和1.595；q下一步为success，图像下一步为unsafe。

这些案例没有最近邻误差。三张图的latent残差在train中的百分位约为11.1%、64.5%和91.5%。第一例不是尾部大误差，却已经改变安全类别。因此“只压低最大表示误差”不足以解决问题，PPO在终止边界附近对latent扰动的动作裕度也必须处理。

### 8.3 插值回放对照

新增`Aebs.dino_latent.diagnose_interpolated_replay`，保持R1和PPO固定，在每个天气/颜色train子库内对相邻标签距离的图像latent做线性插值。12种外观仍使用相同20×20起点：原nearest共10/4800不安全，插值后为0/4800，全部400回合均成功。阴天浅灰由9降为0，阴天红由1降为0，其余外观保持0。

插值过程中，到最近端点的距离误差均值约0.048～0.049米、最大0.378378米；插值括号跨度均值约0.193～0.197米、最大0.756757米。跨度较大来自固定距离区间留出，不应把latent插值解释成真实相机产生了中间图像。

这一结果支持“nearest离散检索是10个库回放失败的主要触发因素”，但不能得出当前视觉控制安全：插值是利用物理距离标签构造的反事实观测，在线系统并不知道真实距离；并且精确配对的3个零检索误差失败仍未消失。

### 8.4 当前判断与下一步

当前证据不支持立即增加R2配对损失，也不能用插值0失败替代真实图像闭环。开发评估中应同时保留nearest作为离散库压力测试、插值作为检索偏差对照、精确配对作为零检索误差诊断，三者不能混为一个成功率。

下一步预登记一个最小鲁棒PPO实验：R1保持冻结，训练时根据train经验残差对latent加入扰动，并单独报告代理路径、原nearest、插值回放和精确配对结果。扰动半径不能读取test决定，validation仅用于开发选择。若鲁棒PPO仍无法覆盖普通量级残差，再考虑动作平滑、安全过滤器或重新设计表示目标。

### 8.5 鲁棒PPO v1预登记与结果

新增入口`Aebs.dino_latent.run_robust_ppo`。本轮固定R1、数据split、AEBS动力学、PPO网络/超参数、20万步和seed 7。训练回合分布预先固定为：50%原train图片nearest、25%干净q、25%“当前状态q＋train经验图像残差”。经验残差定义为train图像latent减去该图标签距离的q latent；只用train计算残差范数P95并截断，残差缩放在每回合从[0,1]均匀抽取。validation和test不定义扰动半径，test完全不读取。

这不是表示R2：DINO和32维projection均不更新。相对04基线，主要变化是把原50%干净q中的一半替换为经验残差路径，同时保留50%原图nearest。正式结果需分别报告：q 400起点；每种外观的nearest、插值和残差修正回放各400起点；train/validation精确配对动作误差及单侧unsafe。不能只选择其中最好的一列汇报。

## 10. 对导师汇报的一段话

我们当前把图像通过冻结的DINO转换为特征，再学习一个32维控制表示；同时学习从物理距离到同一表示空间的小网络。多外观训练把验证相对latent误差从78.89%降到了8.70%。原PPO的nearest图片库回放有10/4800次不安全；逐步诊断发现关键状态约7.50米却检索到7.75米图片，改用相邻训练图片latent插值后降为0/4800，但精确配对仍有3个零检索误差失败。随后保持R1冻结，用train经验残差训练鲁棒PPO：q、nearest、插值和残差修正回放均无不安全，精确配对反例由3例降至1例，validation动作MAE和最大差也下降；代价是策略更保守，且train平均动作差和少制动比例没有全面改善。因此v1只是部分成功，下一步仍需处理安全边界动作裕度，之后才能建立误差契约和SBC；当前不能宣称端到端安全。
