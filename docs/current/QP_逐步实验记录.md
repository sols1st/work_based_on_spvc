## 先用大白话读懂这项实验

### 1. 车到底要做什么？各模块分别负责什么？

实验场景是一辆车接近障碍物。每一步，系统知道车速，并希望从图像判断障碍物还有多远。车在原实验的起始范围是距离 `15–16 m`、速度 `2.5–3 m/s`。进入距离 `5–6 m` 且速度不超过 `0.5 m/s` 算成功；距离已经到 `6 m` 以内而速度仍高于 `0.5 m/s` 算不安全。这里的“成功/不安全”是模拟器里写定的判定，不是实际道路事故率。

整条链可以当成四个人分工：

```text
图像 ──语义编码器──> 估计的距离 + 已知车速 ──PPO──> 想执行的动作
                                         │                 │
                                         └──SBC──> 建议遵守的数学条件
                                                       │
                              PPO 动作 + SBC 条件 ──QP──> 最终动作 ──> 车的下一状态
```

- **语义编码器**：把图像压缩成“障碍物距离”这个控制真正要用的信息；距离再按训练数据的尺度归一化。车速不是编码器从图片里猜的，而是另行输入。当前只做了 8 张真实图像的整链前向检查；后面的 20 回合闭环用的是模拟器的**准确距离和速度**，还不是图像闭环。
- **PPO**：原有的神经网络控制器。它给一个“自己想做的动作”，本文称**名义动作**。本实验正数表示更强制动，动作被限制在 `[-3,3]`。原始 PPO 曾通过强化学习获得；这里的后续 SPVC/QP 训练是用原 SPVC 损失微调其网络权重，**不是再运行一轮标准 PPO 强化学习算法**。
- **SBC**：一个神经网络学习的“风险分数” `B(状态)`。这个比喻方便理解，但分数**不是直接测量出的碰撞概率**。希望初始区域分数低，不安全区域分数高，并且车走一步后的平均分数不要升高。它目前只是一个**候选数学证书**：只有检查方法正确、适用范围足够、所有必要条件真的成立时，才可能成为安全保证。不能因为网络文件叫 `sbc.pt` 就说安全已证明。
- **QP（Quadratic Program，二次规划）**：最后一道动作选择计算。它尽量不偏离 PPO 的动作，同时试图满足由 SBC 算出的条件；它不是另一个会看图像的神经网络。这里的 QP 解对 PPO 输入动作可传梯度，因此可以放在网络输出端参与训练。训练时先更新 SBC，再让损失经过 QP 更新 PPO；不是三个模块同时任意改权重。

### 2. “约束”到底是什么？

约束就是动作必须遵守的规则。第一条很直观：最终动作只能在 `-3` 到 `3` 之间。第二条来自 SBC：对当前状态和某个候选动作，模拟下一步，再考虑原 SPVC 假定的随机过程扰动；希望下一步的**平均风险分数不高于当前分数**。用最少的符号写就是：

```text
下一步平均 SBC 分数 − 当前 SBC 分数 ≤ 0
```

左边称**残差**：小于或等于零表示按这个计算通过；大于零表示未通过。残差是 SBC 网络输出的数值差，**不是“还差多少米刹住”**。这里用的过程扰动是假设车辆状态更新后有小的随机偏差；它与“图像把距离看错”是两回事。当前 20 回合模拟器本身是确定性的，没有把这两类误差都作为真实闭环测试。

真实 SBC 网络是弯曲的非线性函数，而标准 QP 需要直线形式的规则。代码先在 PPO 当前动作附近把规则画一条**切线（线性化）**，QP 实际求解的是这条近似规则。为了计算“下一步平均分数”，代码还把过程扰动范围分为 `10×10` 个小格，取每格中心做近似平均。因此存在三层不同东西：原理上想要的下一步平均不升高、代码用格中心算的平均、QP 中再线性化后的条件。后两者通过，不自动代表第一者在所有状态都成立。

### 3. 什么是 `slack`？为什么“正 slack”很重要？

`slack` 可译成**放宽量**。想象有条规定“动作必须不大于 1”，但 PPO 想输出 1.5。一个**硬约束**系统只能把动作选到 1 或以下；当前用的是**软约束** QP，允许把规则放宽一点，同时对放宽付出数值惩罚。例如最终选 1.1，就要记 `slack=0.1`。这只是解释机制的玩具例子，并非本实验的实际动作数值。

实际实现求解的是：

```text
尽量让最终动作接近 PPO 动作，同时惩罚 slack²
QP 里的线性化 SBC 条件：c × 最终动作 − slack ≤ 右边的界
动作范围：-3 ≤ 最终动作 ≤ 3；slack ≥ 0
```

**`slack=0`**：QP 不需要放松它内部的线性化条件。**`slack>0`**：QP 用了放宽量，内部的严格条件未被满足。原因可能是合法动作里确实找不到满足条件的动作，也可能是有满足条件的动作、但软 QP 认为偏离 PPO 太大而宁可付 slack 罚分；不能只凭正 slack 判定是哪一种。因为 QP 条件本来又是近似的，`slack=0` 也**不等于**已经证明真实系统安全。

最新闭环的“**正 slack 35.07%**”具体指：在这 20 个 PPO+QP 测试回合的**所有执行步**中，约 35.07% 的步满足 `slack>10⁻⁶`。它**不是**35.07% 的车出了事故、35.07% 的回合失败、也不是安全概率。最大 slack `5.512706` 用的是 SBC 分数相关的数值单位，**不是 5.51 米或 5.51 m/s**。20 回合事实上都成功，但不少步靠放宽 QP 条件：经验成功和数学条件满足是两个不同问题。把 slack 的惩罚系数从 `100` 提到 `10000`，此前失败模型的闭环也没有改善，说明不能靠“罚得更重”就假定问题解决。

### 4. 这次说的几个“问题”逐个是什么？

1. **原 PPO 被后续训练带坏**：同样 20 个起点，未经过这轮续训的原 PPO 全部成功；先前保存的语义-SPVC PPO 全部进入不安全区。新入口若仍用原控制器学习率 `0.05`，只训练 512 个状态、各 1 轮，也再次变为 20/20 不安全。这是实验观察，不表示 `0.05` 在所有条件下一定错误。把新 QP 入口的学习率显式改为 `0.0001`，从原 PPO 重启后，完整网格一轮仍保留 20/20 成功。**这改了初始化和学习率**，所以论文里不能把它与旧模型的差异全部归功于 QP。
2. **当前 SBC 条件在很多轨迹步上不好满足**：对旧失败模型的 3 条轨迹，63 个正 slack 状态各扫描 61 个合法动作，都没找到满足同一格中心 SBC 条件的动作。对新成功模型，90 个抽取的正 slack 状态中，仅 3 个在 61 个扫描动作里找到候选。这里“没找到”只针对有限的 61 个动作，**不能证明连续动作范围绝对无解**；更不能说车辆物理上无法安全停车。它说的是“当前学出的 SBC 分数和这个 QP 规则不匹配”。
3. **原验证器只在一条很窄的区域检查下降，QP 却在几乎所有状态都要求下降**：原代码按 SBC 分数筛出靠近“不安全分数”的一个窄带，才检查“下一步平均分数下降”。旧失败模型的 3 条测试轨迹中仅 `1/209` 步落入该带；新成功模型仅 `2/260` 步。QP 当前没有这个筛选，沿途每一步都提出同样要求。因此“QP 经常用 slack”与“旧代码报告网格零违反”可以同时出现，**二者查的不是同一批状态**。这些比例仅来自各 3 条轨迹，不是全体状态的覆盖率。简单在带外关闭 QP 会让 QP 几乎不工作，只能让 slack 指标好看，不能证明安全。
4. **旧 `0/10000` 不能当证明**：它是原程序在 100×100 状态格上输出的计数，分母写了 10000，但程序先筛掉了多数状态，只对窄带执行下降检查。更重要的是，已核对出旧区间计算把“噪声小格的下角点”当成了“整格的上界”。所谓**区间上界/IBP**，本应保证一个小范围里的所有输入算出的分数都不超过它；就像区间 `[1,2]` 的上界应为 `2`，不能只取左端 `1` 冒充上界。旧程序没有正确传入区间，因此实际最大值可能更高。所以 `0/10000` 的准确说法是“旧实现报告零违反”，**不是所有 10000 个状态都经正确数学检查通过**；旧 `96.151%` 也不能当作已证安全概率。
5. **`20/20` 成功也不能当证明**：这是模拟器中 20 个固定起点的有限回合。它说明这些回合没有触发模拟器的失败条件；不能覆盖连续所有状态、图像估计误差、未来随机扰动或其他场景。最新比较里 PPO 不加 QP 已经 `20/20` 成功，QP 加上仍是 `20/20`，因此现在没有证据说 QP 提高了成功率。QP 修改了约 `4.16%` 的执行动作、平均步数略少，但这只是小的任务表现变化。

### 5. 一句话总结目前能说与不能说

**能说**：语义编码器→PPO→SBC 条件生成→可微 QP 的代码、交替训练、保存/重载、8 张真实图像前向与准确语义状态闭环均已跑通；保住原 PPO 能力后，最新 20 个测试回合全部成功。

**不能说**：QP 已经证明安全、QP 比 PPO 更安全、`0/10000` 等于零风险、正 slack 是事故概率、8 张图像前向通过等于图像闭环通过。真正要解决的研究问题是让 SBC 学习的规则、QP 施加规则的状态范围、验证时检查的范围一致，并对最终执行动作使用可信的检查方法。

约束默认 `margin=0`，对应原 `VTVerifier` 统计 `hard_violations` 时使用的“下一步期望值未下降”判定；可用 `--margin` 另外查看严格正余量。QP 线性化的期望使用均匀扰动格**中点近似**；原 VT 验证器当时标称的“IBP 上界”另外报告。后来 Q1d 已确认旧调用不是真正的区间上界，不能把旧标称值当作可靠结论。它们不是同一个数，必须分别看。

本脚本从整个原 100×100 网格均匀抽取 128 个状态，并对抽到的每个状态报告残差；原 `VTVerifier.check_dec_cond()` 还包含自己的状态筛选。因此 Q1 的“多少个正残差”**不能直接与之前的 `0/10000` 相减或视作同一个验证统计量**。它的作用是找出 QP 近似与原上界之间的差距。

2. 20 组原初始区域回合全不安全；训练前后 QP 的真实额外动作修正一直为 0%，即执行动作与环境对原 PPO 动作的裁剪相同。正 slack 表明软约束经常没有被满足。
3. 仅增加 QP slack 惩罚到 10000 也没有改变执行动作或结局。按用户“其他保持原 SPVC”的边界，不引入旧 safety filter、物理可恢复集、改奖励或伪造成功率。
4. 若下一阶段目标从“跑通”转为“提高安全”，必须允许针对**新加的 QP 约束或其训练目标**做实质修改；仅重复当前配置或增加轮数没有明确依据。若继续原样跑更多轮，应当当作探索性试验，不预设会成功。
