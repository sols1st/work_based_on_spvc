## 0. 先用白话建立全貌：怎么读这份文档

### 0.1 先记住一个问题，不要先记公式

想象你在通过摄像头遥控一辆小车。你知道场地里哪些地方有障碍，也知道给小车多大加速度，它大致会怎么动。但画面不总清楚，图像处理还有延迟，因此你无法每一瞬间都准确知道小车在哪里。

一条“在地图上看起来没撞障碍”的路线还不够。你还要知道：**如果看错一点、动作执行偏一点，按现在的纠偏方法，小车最多会偏出路线多少？这部分偏差会不会碰到障碍？**

VISION-SLS 做的就是把这几个问题放到同一套计算里。读后面时，可以一直用三句话检查自己是否理解：

1. **路线是中心线。** 它描述理想情况下怎么走。
2. **反馈是纠偏规则。** 它描述看见偏差后怎么改动作。
3. **管道是偏差范围。** 它描述在指定误差假设下，实际运动围绕中心线可能偏到哪里。

这里“管道”与后文“管束”指同类对象：把每个时刻允许的偏差区域沿路线排列起来。它不是车真的在一个物理管子里行驶。

### 0.2 全文最容易混淆的六样东西

| 对象 | 用白话说 | 是谁产生的 | 后面拿它做什么 |
|---|---|---|---|
| 真实状态 $x$ | 小车实际的位置、朝向和速度 | 真实机器人；仿真中由动力学推进 | 决定下一步运动；仿真中还能拿来核验 |
| 视觉观测 $y^r$ | 图像网络给出的三个数字 | 摄像头、DINO、投影网络 | 提供反馈信息 |
| 名义状态 $z$ | 事先计划“小车应该在这里” | 轨迹优化器 | 作为路线中心和比较基准 |
| 感知残差 $r_{\rm vis}$ | 网络输出与该真实状态应有输出的差 | 事后用真实标签比较得到 | 拟合或验证感知误差界 |
| 反馈创新量 $\nu$ | 实际观测与名义观测的差 | 执行时可直接计算 | 决定动作修正 |
| 感知误差界 $F$ | 允许网络看错的范围大小和形状 | 误差校准 | 让规划器提前计算看错的后果 |

**感知残差与反馈创新量尤其不能混为一谈。** 暂不考虑延迟和坐标平移，设

$$y^r=Cx+r_{\rm vis}.$$

执行时真正拿去反馈的是

$$\underbrace{\nu}_{\text{反馈创新量}}
=y^r-Cz
=\underbrace{C(x-z)}_{\text{小车真的偏离了计划}}
+\underbrace{r_{\rm vis}}_{\text{网络看错的部分}}.$$

所以，一次“观测与计划不一致”可能因为小车真偏了，也可能因为图像看错了，通常两者都有。控制器不能把它们完全分开，必须在两种可能性之间折中。

反过来，事后校准误差时应减去真实状态对应的 $Cx$，才能只检查网络看错多少。若拿 $y^r-Cz$ 去拟合感知界，就会把跟踪偏差也混入感知误差。

### 0.3 一个符号为什么会在不同地方有不同意思

本文沿用论文与源码习惯，以下同名字母需要看上下文：

- 第 6 节二进制 $z_i$ 是拟合中的 0/1 开关；其他大多数地方 $z_k$ 是名义状态。**前者是开关，后者是一条路线上的状态。**
- 多项式 $q_\beta(x)$ 是一个函数；二进制 $q_i$ 是另一个开关，二者不是同一变量。
- 小车状态中的 $v$ 是速度；源码 `measurement(x, v)` 的 `v` 是观测噪声占位变量；论文还可能用 $v$ 表示名义输入。本文一般把名义输入写成 $\bar u$。
- 感知拟合中的 $\mu$ 是松弛惩罚系数；第 12 节的 $\mu$ 是约束对偶变量。二者只是在不同问题里恰好用了同一个字母。
- 第 6 节 $r_i$ 是感知残差范数；第 8 节 $r_k$ 是动力学线性化余项。一个来自“看错”，另一个来自“用直线近似曲线”。

看不懂某个公式时，先问“这是什么阶段，变量是数据还是待求量”，通常比继续硬读更有效。

### 0.5 一张最小依赖图

```text
学到的 p、C：让图像输出能与状态模型对上
            ↓
校准的 F(x)：描述这两者还可能差多少
            ↓
候选路线 z：决定在哪些位置运动、遇到多大的 F(z)
            ↓
设计反馈 Φ：决定过程扰动与看错会怎样影响动作和状态
            ↓
计算管道：把误差大小乘上闭环传播影响，再汇总
            ↓

            ↓

```

### 0.6 看公式前够用的数学读法

| 写法 | 怎样读 | 一个小例子 |
|---|---|---|
| $x\in\mathbb R^4$ | $x$ 是由四个实数组成的向量 | 位置两维、朝向、速度 |
| $C\in\mathbb R^{3\times4}$ | $C$ 把四个数线性组合成三个数 | $Cx$ 是三维观测预测 |
| $[x;u]$ | 把两个向量上下接起来 | 四维状态与二维输入接成六维 |
| $C^T$、$x^TQx$ | 转置；按权重累加平方误差 | 对角 $Q$ 时是 $\sum_jQ_{jj}x_j^2$ |
| $I$ | 单位矩阵，不改变向量 | $Ix=x$，它不是所有元素都为 1 |
| $\operatorname{diag}(a,b,c)$ | 以这些数作对角元素的矩阵 | 分别缩放三个坐标 |
| $\|r\|_\infty$ | 最大绝对分量 | $r=[-0.03,0.04]$ 时为 0.04 |
| $\|r\|_2$ | 向量的欧氏长度 | 同一 $r$ 的长度为 0.05 |
| $\|M\|_F^2$ | 矩阵每个元素平方后求和 | 用于衡量总体响应能量 |
| $\max\{a,b\}$ | 两个数取较大者 | 多项式值太小时采用常数下界 |
| $\partial f/\partial x$ | 输入变一点时，输出怎样变的局部比例 | 多输入、多输出时排成 Jacobian 矩阵 |

下标也要分清：$i$ 常表示第几个数据样本，$k$ 表示控制时间，$j$ 在响应矩阵中常表示误差注入的时间块。$\Phi^{k,j}$ 回答的是“第 $j$ 块误差对第 $k$ 时刻有多大影响”，不是某个新网络的名字。

还有几个优化名词可以先这样理解：NLP 是直接处理非线性模型的优化；QP 是二次目标配线性约束的局部子问题；SOCP 允许二范数锥约束；SCP 则是反复建立局部凸近似、更新路线的整体策略。**“某个固定子问题是凸的”和“整套非线性路线问题有全局最优解保证”不是同一句话。**

## 1. 这篇论文究竟在解决什么问题

论文全名为 *VISION-SLS: Safe Perception-Based Control from Learned Visual Representations via System Level Synthesis*，作者为 Antoine P. Leeman、Shuyu Zhan、Melanie N. Zeilinger 和 Glen Chou。这里分析的是用户提供的 18 页 PDF，其中正文约 10 页，其后为参考文献、证明与实验细节。

它研究的是：**当机器人无法直接获得完整状态，只能通过有误差的视觉观测进行反馈时，如何设计一个考虑不确定性的控制方案，使状态和输入满足约束。**

这个问题同时有三层困难：

- **感知困难：** 输入是高维图像，误差会随位置、姿态和遮挡而改变。
- **控制困难：** 机器人动力学非线性，视觉观测又存在延迟和部分可观测性。
- **验证困难：** 安全要求针对所有允许的误差，而不只是某个平均估计或某次成功仿真。

### 1.1 一个贯穿全文的例子

停车场小车需要绕开已知障碍物，到达目标区域。中间有一片遮挡区域，摄像头在那里很难准确辨认小车位置。

如果仅根据名义位置规划，可能得到一条贴着障碍物的短路线。然而，实际位置偏移一点，就可能碰撞。

VISION-SLS 希望同时决定：

1. 名义上走哪条路线；
2. 视觉误差或运动扰动发生时，怎样根据观测历史修正动作；
3. 这些误差最多会让实际状态偏到哪里；
4. 为了可靠避障，路线需要离障碍物多远；
5. 是否值得绕路去视觉更可靠的区域，先降低不确定性。

因此，它规划的对象不只是一条线，还包括围绕这条线的闭环可达集合。

### 1.2 方法由哪些部分组成

可以把整套方法写成：

$$
\boxed{
\text{视觉表示学习}
+\text{感知误差校准}
+\text{非线性轨迹优化}
+\text{输出反馈 SLS}
+\text{鲁棒约束收紧}
}
$$

学习模块负责把复杂视觉转成简单观测。控制模块使用已知动力学，并把误差传播和约束纳入优化。

**控制器并不是由端到端强化学习直接训练出来的。** 网络输出的是低维观测，实际控制策略由优化计算得到。

### 1.3 论文的四个理论支点

| 理论支点         | 论文位置                   | 回答的问题                      |
| ------------ | ---------------------- | -------------------------- |
| 输出反馈 SLS 参数化 | 命题 1，式（9）—（10）         | 哪些闭环响应对应可实现的因果控制器？         |
| 线性系统的鲁棒收紧    | 命题 2，式（12）             | 如何保证所有允许扰动下的线性约束成立？        |

## 2. 全流程与变量约定

### 2.1 三个阶段，不要混成一个循环

```text
阶段 A：离线学习感知接口

图像—状态配对数据
    ├─ DINO 提取特征
    ├─ 学习投影网络 p 和状态观测模型 C
    └─ 根据残差校准误差函数 F(x)

阶段 B：求解有限时域控制方案

动力学、初始状态、目标、约束、C、F(x)
    ├─ 求初始名义轨迹
    ├─ 局部线性化
    ├─ 设计输出反馈响应
    ├─ 计算安全余量
    └─ 交替更新轨迹与反馈，保存方案

阶段 C：执行闭环反馈

当前图像 → DINO → p → 低维观测
                         ↓
                 与名义观测比较
                         ↓
                 根据历史残差计算修正量
                         ↓
                 名义输入 + 修正量 → 机器人
```

停车场示例把阶段 B 与阶段 C 分成两个脚本。阶段 C 没有每步重新求解完整的阶段 B。

### 2.2 变量表

下文把名义输入记为 $\bar u$，避免论文中的名义输入 $v$ 与代码中观测噪声参数 `v` 混淆。

| 符号           | 含义                    | 停车场例子的维度或代码名           |
| ------------ | --------------------- | ---------------------- |
| $x_k$        | 实际状态                  | $\mathbb R^4$，位置、朝向、速度 |
| $u_k$        | 实际输入                  | $\mathbb R^2$，角速度、加速度  |
| $z_k$        | 名义状态                  | `primal_x[:, k]`       |
| $\bar u_k$   | 名义输入                  | `primal_u[:, k]`       |
| $I_k$        | RGB 图像                | 渲染分辨率 $512\times512$   |
| $d_k$        | DINO 特征               | $\mathbb R^{1536}$     |
| $y_k^r$      | 低维视觉观测                | $\mathbb R^3$          |
| $C$          | 状态到低维观测的线性矩阵          | $3\times4$             |
| $w_k$        | 归一化过程扰动               | 小车为 $\mathbb R^4$      |
| $e_k$        | 归一化观测扰动               | 小车为 $\mathbb R^3$      |
| $E_k$        | 离散过程扰动缩放矩阵            | $4\times4$             |
| $F_k$        | 观测误差缩放矩阵              | $3\times3$             |
| $\Delta x_k$ | $x_k-z_k$             | 实际跟踪偏差                 |
| $\delta z_k$ | 优化器本轮提出的轨迹增量          | 不是实际跟踪偏差               |
| $\Phi$       | 扰动到状态、输入的闭环响应         | 四组分块矩阵                 |
| $b_{k,i}$    | 第 $k$ 步第 $i$ 条约束的安全余量 | `backoff` 的分量          |
| $\tau_k$     | 理论中局部误差分析的管道半径        | 当前主实现未完整实现对应机制         |

**特别注意：$\Delta x$ 与 $\delta z$ 是两种不同的量。** 前者是机器人相对计划的实际误差；后者是优化器修改计划的步长。

## 3. 步骤一：建立动力学与任务约束

**主要源码：** [动力学][S01]、[离散积分][S02]、[实验入口][S03]。

### 3.0 先用白话看这一关：机器人“动起来”遵循什么规则

这一关相当于给规划器一本小车的运动说明书。比如它必须知道：加速度会先改变速度，速度和朝向再改变位置；不能直接命令小车瞬间从障碍左边跳到右边。

**教学假设：** 小车当前向右，速度 1 m/s，未来 0.15 s 不转弯、不加速，也没有扰动。那么它大约向右移动 0.15 m。若它朝上，同样的速度就主要改变纵向位置。这就是 $v\cos\theta$、$v\sin\theta$ 的作用。

接着还要告诉规划器什么是“允许”：速度不能超过上限，转弯与加速度有限，终点要进停车框。动力学回答“做这个动作会去哪”，约束回答“那个状态和动作允不允许”。缺少前者会规划出车做不到的路线；缺少后者会规划出不合任务要求的路线。

**这一关交出的不是路线，而是可调用的运动函数和约束。** 下一关的优化器还要拿这些规则去寻找路线。

### 3.1 输入与输出

**输入：** 机器人运动模型、时间步长、允许的状态和输入范围、初始状态、目标集合、障碍物。

**输出：** 可以供优化器和仿真调用的离散动力学函数，以及统一形式的约束。

### 3.2 小车动力学

状态和输入定义为：

$$
x=\begin{bmatrix}p_x&p_y&\theta&v\end{bmatrix}^{\top},
\qquad
u=\begin{bmatrix}\omega&a\end{bmatrix}^{\top}.
$$

连续动力学为：

$$
\dot x=
\begin{bmatrix}
v\cos\theta\\
v\sin\theta\\
\omega\\
a
\end{bmatrix}+E_cw.
$$

代码中的 `ode()` 实现这一关系。`Model.ddyn()` 默认通过 RK4 积分：

$$
\begin{aligned}
k_1&=f_c(x,u,w),\\
k_2&=f_c(x+\tfrac h2k_1,u,w),\\
k_3&=f_c(x+\tfrac h2k_2,u,w),\\
k_4&=f_c(x+hk_3,u,w),\\
f_d(x,u,w)&=x+\tfrac h6(k_1+2k_2+2k_3+k_4).
\end{aligned}
$$

这意味着后续 Jacobian 是对离散映射 $f_d$ 求导，而不是直接使用连续动力学的导数。

例如，连续模型里 $E_c=0.01I$，不意味着每一步就叠加 $0.01w$。简单 Euler 近似下应是 $hE_cw$；RK4 还会通过积分中的状态耦合改变扰动影响。

### 3.3 统一约束形式

代码把状态和输入上下界写成：

$$
G\begin{bmatrix}x_k\\u_k\end{bmatrix}\le g,
\qquad
G=\begin{bmatrix}I\\-I\end{bmatrix}.
$$

小车 $n_x+n_u=6$，所以阶段约束有 12 条；终端只约束状态，上下界共 8 条。

例如 $v\le2$ 和 $v\ge-1$，分别是两条线性不等式。统一成矩阵形式后，同一个收紧函数就能同时处理所有坐标方向。

圆形障碍物的名义约束为：

$$
\|z_k^{xy}-c_o\|_2\ge r_o.
$$

障碍物中心和半径由实验脚本提供。实机脚本还会把机器人半径加到障碍物半径上；不能默认所有实验中的圆都已经以完全相同方式处理机器人几何。

### 3.4 停车场默认任务

- $N=30$，$h=0.15$ 秒，预测时域为 4.5 秒。
- 默认初始状态为 $[-2.1,-1.75,\pi/2,0]^\top$。
- 默认目标状态为 $[0.25,0.5,0,0]^\top$。
- 目标还有一个允许的终端区间，并不要求每个状态分量精确等于目标值。
- 位置、朝向、速度、角速度和加速度均有边界。

### 3.5 这一步的实际效果和边界

它赋予规划器预测能力，但模型来自事先建模。停车场实验的图像并不承担未知环境建图、在线发现所有障碍物的任务。

因此，需要把两件事分开：

1. **根据图像推断与机器人状态有关的观测；**
2. **根据事先给定的环境几何进行避障规划。**

这份代码主要把第一件事接入第二件事。

## 4. 步骤二：从图像提取 DINO 特征

**主要源码：** [DINO 工具][S04]、[停车场图像生成与推理][S05]。

### 4.0 先用白话看这一关：把一张图片变成便于处理的描述

一张图有几十万个像素，直接把每个像素都放进控制器，计算量太大。DINO 先把图像压成 1536 个特征数字。可以把它理解为视觉描述，但这 1536 个数不是“第一个是横坐标、第二个是速度”这样的物理仪表读数。

**这一关没有输出转向或加速度，也没有直接输出停车场状态。** 它只提供下一关投影网络的输入。DINO 参数在当前执行时固定，车每走一步只是做一次前向计算，不会重新训练 DINO。

从数组看，输入是一批图像张量，输出是一批长度 1536 的向量；下一关再把每个向量变成 3 个观测数字。后面的规划器只使用这 3 维观测的模型，不需要把 1536 维特征全部放入 SLS。

### 4.1 输入与输出

$$
\underbrace{I_k}_{\text{RGB 图像}}
\xrightarrow{\psi_{\mathrm{DINO}}}
\underbrace{d_k\in\mathbb R^{1536}}_{\text{全局视觉特征}}.
$$

小车使用 DINOv2 `vitg14`。执行时模型被置于 `eval()` 模式，特征计算位于 `torch.no_grad()` 中。

### 4.2 实际处理流程

```text
PyBullet 渲染 512×512 RGBA 图像
    → 去掉 alpha 通道
    → 转换为 PIL 图像
    → 默认缩放到 224
    → 转为张量并按 ImageNet 均值、标准差归一化
    → DINOv2 forward_features
    → 读取 x_norm_clstoken
```

核心代码为：

```python
descriptor = model_dino.forward_features(images)["x_norm_clstoken"]
```

代码注释中有时提到 patch 特征，但这个执行路径实际取的是全局 CLS token。文档、注释和实际取出的张量要分别看。

### 4.3 为什么不直接用像素做 SLS

如果使用 $512\times512\times3$ 像素作为观测，单帧观测维度接近 79 万。输出反馈响应需要描述很多时刻的观测误差如何影响状态和控制，维度会非常大。

DINO 首先把图像映射到更紧凑的表示；下一步再降到 3 维。控制求解器只接触低维观测模型，不把完整 DINO 网络放入轨迹优化。

因此，优化器不需要对渲染器或整个视觉基础模型反向传播。

### 4.4 理论支撑与效果

这一步依靠预训练视觉表示的经验能力。DINO 本身既不保证状态可观测，也不保证误差有界。它提供的是后续监督学习的输入特征。

它的直接效果是降低视觉学习难度；安全分析所需要的可控接口和误差集合，需要由后两步建立。

## 5. 步骤三：学习低维观测及其状态模型

**主要源码：** [小车投影网络][S06]、[数据集接口][S07]、[训练循环][S08]、[可见的实机训练入口][S09]。

### 5.0 先用白话看这一关：给视觉输出找一个规划器能理解的含义

这一步有两条路：图像经过网络得到三个数；已知状态经过 $C$ 也得到三个数。训练的目标之一是让两条路在同一状态时尽量对上。

**教学假设：** 为了先看懂接口，临时取一个直接读位置和朝向的矩阵 $C_{\rm toy}$，让 $C_{\rm toy}x=[p_x,p_y,\theta]^T$。当状态标签是 $[1,2,0.1,0.3]^T$ 时，训练希望图像网络输出接近 $[1,2,0.1]^T$。实际论文的 $C$ 是学习后的线性混合，不是这个选择矩阵，但“让图像输出与某个状态函数对齐”的逻辑相同。

这样做的关键好处是：未来路线还没有执行，未来图像也没有，但规划器可以从候选状态算 $Cz$，知道那时“应该看到什么样的三个数”。

这里有两个阶段：训练时用状态标签监督网络；执行时只把图像送进网络。不能因为训练用过真实状态，就认为控制器执行时也读取了真实状态。

**为什么少一个速度分量还能控制？** 就像相机连续两帧看到车的位置变化，可以间接推断运动趋势。单帧缺少速度，不等于整段观测历史永远无法区分速度。后面的动力学和动态反馈负责利用这种时间信息。

### 5.1 输入与输出

**训练输入：** 配对样本 $(d_i,x_i)$，其中 $d_i$ 是图像的 DINO 特征，$x_i$ 是同一场景下的真实状态标签。

**训练输出：** 神经网络 $p_\theta$ 和观测矩阵 $C$。

**执行输入：** 当前图像的 DINO 特征 $d_k$。

**执行输出：** $y_k^r=p_\theta(d_k)\in\mathbb R^3$。

训练阶段需要真实状态标签；实际机器人反馈时不需要再输入这个标签。这是监督标定与在线使用之间的区别。

### 5.2 网络实际长什么样

小车类 `SupervisedDinoObservabilityLargeUnicycle` 中：

```python
self.net = nn.Sequential(
    nn.Linear(params.z_dim, 512),
    nn.GELU(approximate="tanh"),
    nn.Linear(512, 512),
    nn.GELU(approximate="tanh"),
    nn.Linear(512, params.y_red_dim)
)
self.C = nn.Parameter(torch.randn(params.y_red_dim, params.x_dim))
```

配置对应 $1536\to512\to512\to3$，状态维度为 4。

`forward()` 只调用 `self.net`，不会把 `C` 直接乘进网络输出。`C` 是训练时的监督目标模型参数，控制时则成为规划器使用的观测矩阵。

### 5.3 为什么同时学习两个对象

作者希望以下两条路径在同一低维空间对齐：

$$
\text{图像 }I_i
\xrightarrow{\psi_{\mathrm{DINO}}}
d_i
\xrightarrow{p_\theta}
y_i^r,
$$

$$
\text{物理状态 }x_i
\xrightarrow{C}
Cx_i.
$$

因此监督匹配项为：

$$
\mathcal L_{\mathrm{match}}
=\frac1M\sum_{i=1}^{M}
\|p_\theta(d_i)-Cx_i\|_2.
$$

匹配成功以后，规划器可以直接根据候选状态计算 $Cx$，预测未来观测，不必生成未来图像。

### 5.4 为什么不强制网络输出完整状态

单张图像不一定包含完整状态。例如速度并不直接显示在静态画面里。

如果强制网络预测完整 $x$，可能把本来应由时间信息解决的问题交给单帧回归，产生很大的、难以标定的误差。

论文选择学习少量可观察量，再让动力学与观测历史共同提供完整状态相关信息。

小车最终使用的矩阵约为：

$$
C=\begin{bmatrix}
0.9761&0.1324&-0.1721&0\\
-0.2165&0.6678&-0.7121&0\\
0.0209&0.7329&0.6800&0
\end{bmatrix}.
$$

最后一列为零，意味着单次低维观测不直接测速度。前三列构成的变换保留了位置和朝向的信息。

### 5.5 可观测性的直观解释

考虑最简单的一维匀速模型：

$$
\begin{bmatrix}p_{k+1}\\v_{k+1}\end{bmatrix}
=\begin{bmatrix}1&h\\0&1\end{bmatrix}
\begin{bmatrix}p_k\\v_k\end{bmatrix},
\qquad y_k=p_k.
$$

只看 $y_k$ 无法确定 $v_k$。但看两次输出：

$$
\begin{bmatrix}y_k\\y_{k+1}\end{bmatrix}
=\underbrace{\begin{bmatrix}1&0\\1&h\end{bmatrix}}_{\mathcal O}
\begin{bmatrix}p_k\\v_k\end{bmatrix}.
$$

只要 $h\ne0$，矩阵满列秩，就能在无噪声模型下从输出序列恢复位置与速度。

对非线性系统，论文式（28）构造多步输出序列映射 $\mathcal H(x;u)$。局部判断关心的是它对初始状态的 Jacobian：

$$
\mathcal O_x=\frac{\partial\mathcal H}{\partial x}.
$$

若这个 Jacobian 满列秩，则在相应局部条件下，输出序列能区分附近的不同初始状态。最小奇异值较小，意味着某些状态变化很难从观测变化中辨认，噪声影响也更明显。

论文式（29）的意图是：

$$
\mathcal L
=\mathcal L_{\mathrm{match}}
-\lambda\,\sigma_{\min}(\mathcal O_x).
$$

这里把最小奇异值明确写在 Jacobian 上，是为了突出可观测性分析所使用的对象；不能把输出向量本身的数值大小当成可观测性。

### 5.6 防止退化表示

如果只有匹配项，$p_\theta\equiv0$、$C=0$ 就是一个没有信息却误差很小的退化解。

可见训练代码把 $C$ 每一行归一化：

```python
C_norm = net.C / net.C.norm(dim=1, keepdim=True)
```

这限制了整体缩放退化；论文中的可观测性项进一步鼓励不同状态方向能够被区分。行归一化本身不保证行独立，也不保证完整状态可观测。

### 5.7 当前公开训练代码能确认到哪里

仓库中可以确认：

1. 投影网络和可学习 $C$ 的结构存在；
2. 数据集接口读取状态与预计算特征；
3. 通用训练循环使用 Adam、学习率调度、训练/验证划分和权重保存；
4. 停车场运行入口加载预训练权重；
5. 实机训练脚本定义了基于导数和 SVD 的 `loss_gramian()`。

但该实机脚本的实际 `loss_uni()` 中，可观测性项被注释掉了，只返回匹配误差。当前仓库中也没有找到停车场实验完整的、启用论文式（29）的表示训练入口。

因此，本文把带可观测性项的目标解释为**论文方法**，把可见脚本的匹配训练解释为**当前可直接确认的代码行为**。不能据此推断历史上每个 checkpoint 的具体训练过程。

### 5.8 这一步得到什么效果

最终获得一个小维度的感知接口，使后面的控制器能够：

- 使用线性状态观测模型 $Cx$ 预测观测；
- 借助时间历史处理未直接观测的状态；
- 避免在线规划对完整视觉网络求导；
- 把剩余视觉错误集中交给下一步校准。

## 6. 步骤四：校准感知误差界

**主要源码：** [停车场误差界训练][S10]、[观测与误差地图][S11]。

### 6.0 先用白话看这一关：不仅问“平均准不准”，还问“可能错多少”

网络输出接近 $Cx$，并不表示二者相等。假设某次应输出 1.00，网络却输出 1.03，误差是 0.03。误差界不是把 1.03 修成 1.00，而是提前告诉控制器：“这类观测可能偏这么多，你设计纠偏时要把它算进去。”

仍沿用上一节的**教学假设**，若 $Cx=[1,2,0.1]^T$、网络输出为 $[1.03,1.98,0.11]^T$，则原始残差为

$$r_{\rm vis}=[0.03,-0.02,0.01]^T.$$

它的最大绝对分量是 0.03，二范数约为 0.0374。这两个数都正确，但回答的是不同集合问题：前者检查三个坐标各自的界，后者检查向量长度的界。后面计算管道时，必须使用与声明集合相符的公式。

**这一关交出的是可供很多未来状态查询的函数 $b(x)$ 或 $F(x)$，不是某一次图像的真实误差。** 校准数据来自过去样本，规划器将来拿该函数评价候选位置；是否能覆盖将来的样本仍需要条件或验证。

### 6.1 输入、输出和目的

**输入：** 固定的感知网络、观测矩阵，以及另一批图像特征—状态配对数据。

**输出：** 一个状态相关误差函数 $F(x)$，停车场中采用 $F(x)=b(x)I_3$。

目的不是让网络继续提高平均预测精度，而是回答：**在某个状态附近，视觉输出相对 $Cx$ 的偏差需要多大的集合才能覆盖？**

### 6.2 先形成残差样本

$$
\epsilon_i=p_\theta(d_i)-Cx_i,
\qquad
r_i=\|\epsilon_i\|_\infty.
$$

代码使用：

```python
error = torch.abs(
    model(data.data_z) - (C_norm @ data.data_x.T).T
).max(dim=1)[0]
```

如果某次残差是 $[-0.03,0.01,0.02]$，就得到 $r_i=0.03$。这表示所有低维观测分量的绝对误差都不超过 0.03。

### 6.3 用位置拟合误差地图

停车场误差函数依赖 $p_x,p_y$。三次、二变量完整多项式有 10 个单项式：

$$
m(p_x,p_y)=
\begin{bmatrix}
1&p_y&p_y^2&p_y^3&p_x&p_xp_y&p_xp_y^2&p_x^2&p_x^2p_y&p_x^3
\end{bmatrix}^{\top}.
$$

这意味着拟合的是位置对感知可靠性的影响，没有显式把朝向作为误差函数输入。校准数据需要为没有显式建模的状态变化提供足够覆盖；仅凭这种函数形式不能推出对全部朝向的统一保证。

代码最终使用：

$$
b(x)=\max\{\theta^\top m(p_x,p_y),b_{\min}\}.
$$

常数下界防止拟合值在某些位置过小或为负。由于使用 `max`，函数在切换处通常不是光滑的；不能把实际加载的截断函数视为处处光滑多项式。

### 6.4 论文给出的凸拟合

论文式（31）大意为：

$$
\begin{aligned}
\min_{\beta,\xi_i\ge0}\quad &
\sum_i \beta^\top m(x_i)
+\gamma\|\beta\|_2^2
+\mu\sum_i\xi_i,\\
\text{s.t.}\quad &
\beta^\top m(x_i)\ge r_i-\xi_i.
\end{aligned}
$$

各项分别希望：

- 包络不要太大，避免规划过度保守；
- 系数不要过大，限制拟合的剧烈变化；
- 欠覆盖要付出代价，但允许通过松弛变量处理异常点。

这是对有限样本的优化。除非再加入额外验证或统计构造，否则不能自动得到全状态空间的严格覆盖结论。

#### 6.4.1 松弛变量到底是谁决定的

先把样本残差 $r_i$ 当作已经算好的数据。优化器要一起选择多项式系数 $\beta$ 和松弛 $\xi_i$，不是先由人逐个指定松弛。

把约束移项：

$$\xi_i\ge r_i-\beta^Tm(x_i),\qquad \xi_i\ge0.$$

若某个候选多项式在该点只给出 0.08，而数据残差是 0.10，那么至少需要 $\xi_i=0.02$ 才可行。若给 0.01，约束不成立；给 0.03 也可以，但当 $\mu>0$ 时会多付惩罚，通常没有必要。

因此，对固定多项式且没有其他松弛约束，最优值为

$$\xi_i^*=\max\{0,r_i-\beta^Tm(x_i)\}.$$

把这个结果代回目标，就可以把原程序理解为同时权衡：多项式够不够小、系数够不够平稳、欠覆盖总共多少。优化器会比较很多候选多项式，它们各自对应不同的松弛，然后选总目标更低的组合。若 $\mu=0$，松弛没有成本，就不能再认为它一定取上述最小值。

**0.08 是这里假设的某个候选拟合值。它没有被预先规定为通用误差界，也不是 0.08 m。**

#### 6.4.2 为什么允许松弛：一组能手算的代价比较

**教学假设：** 暂时不拟合复杂多项式，只拟合一个非负常数 $b$，四个残差是 $[0.02,0.03,0.04,0.20]$，忽略系数正则项。目标为

$$4b+\mu\sum_{i=1}^4\xi_i.$$

比较两个候选：

| 候选界 | 对应最小松弛 | 目标值 |
|---|---|---|
| $b=0.04$ | $[0,0,0,0.16]$ | $0.16+0.16\mu$ |
| $b=0.20$ | 全为零 | $0.80$ |

$\mu=2$ 时，两者代价是 0.48 与 0.80，所以这两个候选中，优化器更愿意保留小界并允许那个大残差欠覆盖。$\mu=10$ 时，代价是 1.76 与 0.80，于是覆盖大残差的候选更便宜。这里只比较两种候选，不声称一般多项式问题只有这两个选择。

这说明“允许松弛”是一种拟合取舍：避免少量难拟合样本把所有位置的界一起抬高。它不意味着被放宽的样本已经变安全。要用于控制，仍须说明最终误差集合在哪些数据、区域或统计条件下有效；不能把 $\xi_i$ 当成机器人会在线补偿掉的误差。

### 6.5 当前停车场代码的混合整数拟合

实际脚本引入：

- 多项式系数 `theta`；
- 常数下界 `theta_bias`；
- 二进制变量 `z_var`、`q_var`；
- Big-M 常数 $M$。

其核心约束为：

$$
\theta^\top m(x_i)\ge r_i-Mz_i-Mq_i,
$$

$$
b_{\min}\ge r_i-M(1-z_i)-Mq_i.
$$

在 $q_i=0$ 时：

- 若 $z_i=0$，主要要求多项式覆盖该样本；
- 若 $z_i=1$，主要要求常数下界覆盖该样本。

而 $q_i=1$ 会放宽该样本的覆盖条件。额外计数约束限制放宽样本的数量与分组关系。目标函数惩罚样本位置上的多项式值和常数下界。

因此，该脚本实现的是与截断包络相配套的混合整数拟合，使用 Gurobi；它不是论文式（31）的同一个凸程序。

默认脚本抽取 250 个样本，三次多项式，`THRESH_KEEP=0.97`，并限制常数下界不超过 0.04。这个阈值是优化内部参数，不能直接当成未来数据的概率保证。

#### 6.5.1 先看四种具体样本，理解 $z_i$ 的作用

下表均为**教学假设**，且 $M$ 足够完成表中需要的放松。先假定当前候选多项式和常数下界已经给定：

| 样本 | 多项式值 | 常数下界 | 残差 | 不放宽时应该怎样覆盖 |
|---|---:|---:|---:|---|
| A | 0.06 | 0.02 | 0.05 | 只有多项式够大，需要 $q_i=0,z_i=0$ |
| B | 0.01 | 0.02 | 0.015 | 只有常数下界够大，需要 $q_i=0,z_i=1$ |
| C | 0.04 | 0.02 | 0.015 | 两支都能覆盖，$z_i$ 可有不止一种选择 |
| D | 0.01 | 0.02 | 0.08 | 两支都不够，若保留这组系数，就需要允许额外放宽 |

**$z_i$ 的用途是把“至少一支覆盖”表达成优化器能处理的线性约束加二进制选择。** 它不是最后求 `max` 必须用到的变量，也不总等于“哪一支数值最大”的判断结果。比如 C 的多项式更大，但常数也覆盖了残差，两种覆盖条件都可能成立。

#### 6.5.2 再看 $q_i$，以及为什么不能每个样本都放宽

$q_i=1$ 会进一步降低相应约束右端，允许某些样本不被当前包络覆盖。但 $M$ 是有限数值，严格说是按公式放松，不应理解为这条约束从数学上彻底消失。

代码还有计数关系

$$\sum_iq_i=(1-\eta)\sum_i z_i,\qquad \eta=0.97.$$

因此，$q_i$ 不是可以对所有困难样本任意设成 1。比如某次解得到 $\sum z_i=200$，就要求 $\sum q_i=6$。这正是 2026 年 10 月 24 日那次独立 250 点重新拟合记录中的总数，但它不规定哪六个样本必须被放宽。

#### 6.5.3 求解器是怎样一起决定这些值的

可以把整个求解理解为：尝试一组多项式系数和下界；为样本安排可行的覆盖分支和放宽开关；检查所有样本约束和总计数；再比较目标函数，继续寻找更好的组合。实际 Gurobi 使用混合整数优化算法，不是把上述试探过程简单穷举一遍。

选择是全局耦合的：把下界抬高，更多样本可由常数覆盖；改变某个多项式系数，会同时改变很多位置的值；改变 $z_i$ 的分组又会影响允许的 $q_i$ 总数。因此不能只根据单个残差大小，独立判断每个 $z_i,q_i$ 的最终值。

拟合结束后，在线查询只需要保存的系数和常数下界。小车不会在每一步重新运行 Gurobi 来决定这些样本开关。

### 6.6 从标量包络变成观测模型

如果某个状态上确实有：

$$
\|p_\theta(\psi(I))-Cx\|_\infty\le b(x),
$$

那么可以写成：

$$
y^r=Cx+b(x)e,
\qquad \|e\|_\infty\le1.
$$

即：

$$
y^r\in Cx\oplus F(x)\mathbb B_\infty,
\qquad F(x)=b(x)I_3.
$$

这里 $\oplus$ 表示集合的 Minkowski 和。直观上，$Cx$ 是观测中心，$F(x)\mathbb B_\infty$ 是观测可能偏离的盒子。

#### 6.6.1 $e$ 从哪里来：它是对实际残差的一种缩放表示

沿用 6.0 的教学残差 $r_{\rm vis}=[0.03,-0.02,0.01]^T$。假设某候选误差界为 $b=0.04$，就有

$$F=0.04I_3,\qquad e=F^{-1}r_{\rm vis}=[0.75,-0.5,0.25]^T.$$

代回 $Fe$，恰好还原原始残差。这不是说感知误差先由一个真实的 $e$ 传感器产生，再经过 $F$；它是一种方便规划和分析的集合表示。

如果声明的是盒子，检查 $\|e\|_\infty\le1$；如果声明的是二范数球，检查 $\|e\|_2\le1$。本例两个检查都通过。若把界改为 0.03，则每个坐标仍不超过对应盒界，但 $\|e\|_2\approx1.247>1$，不再落入同半径二范数球。第 11 节为什么强调范数匹配，这里就能看出来。

如果实际残差比声明集合更大，$e$ 的范数就会超过 1。不能为了让模型“看起来满足条件”而把诊断中的 $e$ 强行截断到 1；那样相当于把实际发生的超界误差从记录中删除了。

#### 6.6.2 感知界与位置管道不是一回事

感知界属于低维观测空间；位置管道属于机器人状态空间。感知误差要先通过控制器引起输入变化，再通过动力学影响位置，才能得到相应位置偏差。

所以不能说“感知界为 0.04，车就一定偏 4 厘米”。同样的感知误差，乘上不同的响应 $\Phi_{xe}$，可能造成很小或较大的位置偏差。第 9 节计算传播影响，第 11 节才把它转换成各方向安全余量。

### 6.7 为什么规划时不需要真实状态

规划器评估的是候选名义状态 $z_k$，因此可以计算 $F(z_k)$。它不需要预先知道未来真实状态。

但真实状态一般位于 $z_k$ 附近，而不恰好等于 $z_k$。严格保证需要覆盖整个可能状态集合上的误差：

$$
\bigcup_{\|x-z_k\|\le\tau_k}F(x)\mathbb B
\subseteq\Upsilon(z_k,\tau_k)\mathbb B.
$$

这就是论文中管道相关观测误差膨胀的作用。当前主求解器主要在名义状态上评价 $F$，不能把二者视为已经等价。

### 6.8 坐标偏移与模型一致性

`Unicycle_OF.get_disturbance()` 先执行：

```python
x0 = x[0] + 3
```

执行脚本也对渲染状态和名义观测使用 `[3, 0, 0, 0]` 的偏移。

这不是感知算法自动学习出来的坐标变换，而是实验场景与规划坐标的人工对齐。复现时若只修改轨迹坐标，不同步修改图像渲染、$Cx$ 与误差地图，闭环残差会出现系统性偏差。

### 6.9 这一步的效果

遮挡区的 $b(x)$ 大，清晰区的 $b(x)$ 小。后续规划因此能够比较不同路线的感知可靠性。

误差地图首先是一个经过数据校准的模型。其可信范围依赖校准数据覆盖的状态、图像外观和环境条件。DINO 特征具有迁移能力，不等于这张误差地图也能不经验证地迁移。

## 7. 步骤五：求解初始名义轨迹

**主要源码：** [初始轨迹求解器][S12]、[外层初始化][S13]。

### 7.0 先用白话看这一关：先找一条“理想情况下车能走”的路线

到这一步，我们已经有小车怎么动的规则、允许区域、目标和视觉误差地图，但还没有一条具体路线。优化器先假设没有新增扰动，找出 31 个名义状态和 30 个动作，让车从起点进入目标区域。

它同时比较两类代价：离目标太远不好，动作太大也不好。约束则另行规定不能越边界、不能穿障碍。这就像路线规划先有一个可行草案，再进行后续误差分析。

这里的“名义”是“在规定模型与基准条件下预测的”，不是“实际一定发生的”。假如规划预测一步后横坐标为 1.00 m，实际可能是 1.03 m；1.00 是 $z$，1.03 是 $x$，两者的差才是跟踪偏差。

**这一关先提供展开计算的中心线。** 后续会重新考虑反馈和误差余量，所以最终方案不一定沿这条初始路线行驶。

### 7.1 输入与输出

**输入：** $x_0$、目标状态或参考轨迹、离散动力学、障碍物和约束、代价权重。

**输出：** 初始名义轨迹 $z^{(0)}$、名义输入 $\bar u^{(0)}$ 和对偶变量。

小车对应：

$$
Z\in\mathbb R^{4\times31},
\qquad U\in\mathbb R^{2\times30}.
$$

### 7.2 优化问题

代码中的 `NLP.initialize_solver()` 构造：

$$
\begin{aligned}
\min_{z,\bar u}\quad&
\sum_{k=0}^{N-1}\left[
(z_k-x_g)^\top Q(z_k-x_g)
+\bar u_k^\top R\bar u_k\right]\\
&+(z_N-x_g)^\top Q_f(z_N-x_g),\\
\text{s.t.}\quad&z_0=x_0,\\
&z_{k+1}=f_d(z_k,\bar u_k,0),\\
&G[z_k;\bar u_k]\le g,\\
&G_fz_N\le g_f,\\
&\|z_k^{xy}-c_o\|_2\ge r_o.
\end{aligned}
$$

使用 CasADi 构造，IPOPT 求解。

### 7.3 代价权重有什么作用

停车场例子中，轨迹代价主要关注位置误差，阶段朝向、速度项设置为零；终端速度有额外惩罚。

- 增大位置权重：更积极向目标移动；
- 增大输入权重：更不愿使用大角速度、大加速度；
- 增大终端权重：更重视预测终点的精度。

这些是任务性能偏好。后续 `Q_reg`、`R_reg` 等还会单独控制误差响应的代价，不能只根据变量名把它们都理解成普通数值正则项。

### 7.4 为什么先解一个不带完整不确定性的方案

原问题同时依赖轨迹、反馈响应和误差地图，直接从零开始联合求解很难。名义轨迹提供一个参考，让局部近似有几何和动力学意义。

这一步只说明在无扰动模型中存在一条候选路线。它不保证真实视觉闭环执行安全。

## 8. 步骤六：构造局部线性误差模型

**主要源码：** [Jacobian 构造][S14]、[轨迹上的矩阵更新][S15]。

### 8.0 先用白话看这一关：只在当前路线附近，把弯曲关系近似成直线关系

小车转一点方向会怎样改变未来位置，这个关系含 $\sin$、$\cos$，整体是非线性的。规划器在当前名义状态附近求导，得到一套“偏一点会怎样”的局部比例关系。

其中 $A_k$ 描述当前状态偏差怎样传到下一步；$B_k$ 描述动作修正怎样传到下一步；$E_k$ 描述外界运动扰动怎样进入；$C_k$ 描述状态偏差怎样改变观测；$F_k$ 描述感知误差怎样进入观测。

可以把 $A$、$B$ 理解为当前工作点附近的影响系数。求 Jacobian 不是再训练网络，而是对已经写好的离散数学模型求导。沿路线换了位置或朝向，影响系数也可能改变，因此下标 $k$ 不能随意去掉。

**教学假设：** 对 $f(s)=s^2$，在 $s=1$ 附近预测 $s=1.1$，直线近似给出 $1+2\times0.1=1.2$，真实值是 1.21，差 0.01。差的这部分就是线性化余项。偏到 1.3 时，余项变成 0.09。局部近似有用，但偏得越远，漏掉的部分通常越不能忽略。

这一关给后续 SLS 的是当前路线附近的局部模型，不是把原非线性系统永久改造成了精确线性系统。

### 8.1 输入与输出

**输入：** 当前名义轨迹 $(z_k,\bar u_k)$、离散动力学和低维观测模型。

**输出：** 沿时域变化的 $A_k,B_k,E_k,C_k,F_k$，以及当前轨迹的动力学缺陷。

### 8.2 轨迹增量模型与跟踪误差模型

同一套 Jacobian 会出现在两个不同问题中。

**问题 A：优化器怎样修改轨迹。**

令当前名义轨迹的动力学缺陷为：

$$
c_k=f_d(z_k,\bar u_k,0)-z_{k+1}.
$$

新轨迹需要近似满足：

$$
\delta z_{k+1}=A_k\delta z_k+B_k\delta\bar u_k+c_k.
$$

**问题 B：机器人怎样偏离名义轨迹。**

在参考轨迹满足名义动力学时：

$$
\Delta x_{k+1}
=A_k\Delta x_k+B_k\Delta u_k+E_kw_k+r_k.
$$

前者用于轨迹 QP，后者用于闭环响应与安全分析。两者不能因为都叫 `delta` 就混在一起。

### 8.3 代码怎样求导

```python
ddyn_sym = self.m.ddyn(x, u, w, self.m.dt)
meas_sym = self.m.measurement(x, v)

A = ca.jacobian(ddyn_sym, x)
B = ca.jacobian(ddyn_sym, u)
E = ca.jacobian(ddyn_sym, w)
C = ca.jacobian(meas_sym, x)
F = ca.jacobian(meas_sym, v)
```

随后把噪声变量置零，在当前名义状态上求值。

对于 $h(x,e)=Cx+b(x)e$，有：

$$
\left.\frac{\partial h}{\partial x}\right|_{e=0}=C,
\qquad
\frac{\partial h}{\partial e}=b(x)I.
$$

因此当前 $C$ 可以保持常数，而 $F_k$ 随轨迹位置变化。

### 8.4 一步观测延迟

论文模型为：

$$
y^r_{k+1}=Cx_k+F(x_k)e_k.
$$

时刻 $k$ 的状态信息在下一步成为可用观测。代码更新 `F_list` 时，对大部分延迟观测使用前一名义状态评价；初始化时另有首个占位块。

这使观测器和控制器必须遵守因果关系。不能根据还未处理完成的当前图像设计当前动作。

### 8.5 初始状态误差是独立通道

论文写：

$$
x_0=z_0+\Xi\tilde w.
$$

所以响应矩阵的第一个扰动块不是“第零步之后新发生的扰动”，而是初始状态不确定性。后续列才对应各步过程扰动。

代码中的 `E_list[0]` 承担这个初始化缩放角色，可由模型的 `E_init` 覆盖；不存在该属性时，主实现使用相应离散扰动 Jacobian 作为默认值。不要默认它自动等于论文中单独指定的任意 $\Xi$。

### 8.6 非线性余项为什么不能忽略

Taylor 展开中的余项为：

$$
r_k=f_d(z_k+\Delta x_k,\bar u_k+\Delta u_k,0)
-f_d(z_k,\bar u_k,0)
-A_k\Delta x_k-B_k\Delta u_k.
$$

如果局部二阶导数有界，可构造随偏差半径增长的上界。例如对第 $i$ 个分量，在给定范数和对应 Hessian 范数下可以得到形如：

$$
|r_{k,i}|\le\tfrac12L_i\|[\Delta x_k;\Delta u_k]\|^2.
$$

这是解释余项为何通常具有二阶量级的示意推导，不是当前仓库已实现的具体包络公式。

论文用 $\tau_k$ 约束偏差范围，再用 $\Sigma(z_k,\bar u_k,\tau_k)$、$\Upsilon(z_k,\tau_k)$ 覆盖过程扰动、动力学余项和观测误差变化。严格应用时，需要确保原始过程扰动也包含在合成误差集合中。

### 8.7 当前实现的边界

主类默认：

```python
self.linearization_error = kwargs.get("linearization_error", False)
```

而开启后的分支是：

```python
raise NotImplementedError("Linearization error is not implemented yet")
```

因此，这里不是一个可以打开就获得完整非线性保证的现成功能。当前计算主要基于局部线性误差模型和名义状态上的误差取值。

## 9. 步骤七：通过 SLS 参数化闭环控制

**主要源码：** [响应组装][S16]、[块矩阵工具][S17]、[SLS 参数化检查][S18]。

### 9.0 先用白话看这一关：先设计“误差造成的后果”，再恢复纠偏规则

通常会先问：“看到偏差后，方向盘该修多少？”这相当于直接设计反馈增益 $K$。SLS 换了一个设计角度：“我要让每一次运动扰动、每一次看错，对以后的位置和动作分别产生多大影响？”这些影响系数就是响应 $\Phi$。

**教学假设：** 一维系统 $x_{k+1}=x_k+u_k+w_k$，视觉输出 $y_k=x_k+e_k$，采用 $u_k=-0.5y_k$。代入后

$$x_{k+1}=0.5x_k+w_k-0.5e_k.$$

这条等式立即告诉你三件事：原有位置偏差下一步保留一半；这一步运动扰动以系数 1 进入位置；看错会通过控制动作以系数 $-0.5$ 影响真实位置。SLS 把这种“误差从哪里来、以后影响谁”的系数推广到多个状态、多个时刻。

| 四组响应 | 白话问题 | 为什么不能省 |
|---|---|---|
| $\Phi_{xw}$ | 被外界推了一下，之后车偏到哪里？ | 要检查实际状态 |
| $\Phi_{uw}$ | 被推之后，纠偏会用多大动作？ | 要检查输入上限 |
| $\Phi_{xe}$ | 图像看错后，车会被误导到哪里？ | 要检查感知对运动的影响 |
| $\Phi_{ue}$ | 图像看错后，会打出多大错误动作？ | 要限制观测噪声放大 |

这四组响应不能随便填数。比如，不能同时声称“外力把车推偏了”“没有采取任何纠正动作”“偏差下一步又凭空归零”。SLS 恒等式就是保证这些系数遵守动力学与可用信息的规则。

**容易误会的一点：** 设计时用扰动来描述系统，不表示执行时需要测出扰动。保存好响应并恢复 $K$ 后，执行输入只使用可获得的观测历史。扰动通道是分析工具，不是额外安装的传感器。

### 9.1 为什么直接优化反馈增益很困难

为了看清直接设计反馈时的代数困难，先将整段时间堆叠，并把时移吸收到算子里，暂时隐藏延迟细节。以下这一小段中的 $A,B,C$ 是简写的整体算子，不是单步状态转移公式。若：

$$
\Delta x=A\Delta x+B\Delta u+d_w,
\quad \Delta y=C\Delta x+d_e,
\quad \Delta u=K\Delta y,
$$

则有：

$$
\Delta x=(I-A-BKC)^{-1}(d_w+BKd_e).
$$

闭环误差与 $K$ 之间出现矩阵求逆和乘积。要求所有扰动下的约束成立，会变成难处理的非凸增益优化。

SLS 直接把这些从扰动到状态、输入的映射当成变量。

### 9.2 时域堆叠与下移矩阵

把全部时刻堆叠成：

$$
\Delta\mathbf x=[\Delta x_0;\Delta x_1;\ldots;\Delta x_N].
$$

令 $Z$ 为块下移矩阵。例如 $N=2$ 时：

$$
Z=\begin{bmatrix}
0&0&0\\
I&0&0\\
0&I&0
\end{bmatrix}.
$$

它把第 $k$ 个时刻的量放到第 $k+1$ 行，以紧凑表达动态传播。

在适当填充终端块、区分状态和观测下移算子的情况下，记：

$$
M=I-Z_x\mathbf A,\qquad
D=Z_x\mathbf B,\qquad
H=Z_y\mathbf C.
$$

误差系统就写为：

$$
M\Delta\mathbf x-D\Delta\mathbf u=d_w,
\qquad
\Delta\mathbf y=H\Delta\mathbf x+d_e.
$$

其中 $d_w$、$d_e$ 已包含对应的缩放矩阵。下文把过程扰动通道下标记为 $w$，观测误差通道记为 $e$。

### 9.3 定义四个响应

$$
\begin{bmatrix}
\Delta\mathbf x\\\Delta\mathbf u
\end{bmatrix}
=
\underbrace{\begin{bmatrix}
\Phi_{xw}&\Phi_{xe}\\
\Phi_{uw}&\Phi_{ue}
\end{bmatrix}}_{\Phi}
\begin{bmatrix}d_w\\d_e\end{bmatrix}.
$$

这四个对象描述的是闭环系统，而不是裸动力学 $A,B,C$。

| 对象 | 代码名 | 单个时间块的维度 | 单块的含义 |
|---|---|---|---|
| $\Phi_{xw}$ | `Phi_xx` | $4\times4$ | 过程扰动如何影响状态 |
| $\Phi_{uw}$ | `Phi_ux` | $2\times4$ | 过程扰动如何影响输入 |
| $\Phi_{xe}$ | `Phi_xy` | $4\times3$ | 观测误差如何影响状态 |
| $\Phi_{ue}$ | `Phi_uy` | $2\times3$ | 观测误差如何影响输入 |

例如 $\Phi_{xw}[10,3]$ 表示第 3 个扰动块对第 10 个状态时刻的影响。若扰动发生在初始条件之后，需按前文约定把块索引换算成实际注入时刻。

### 9.4 第一组约束：响应必须符合动力学

代入 $M\Delta\mathbf x-D\Delta\mathbf u=d_w$，比较两个独立扰动的系数，得到：

$$
M\Phi_{xw}-D\Phi_{uw}=I,
$$

$$
M\Phi_{xe}-D\Phi_{ue}=0.
$$

这保证响应不会违反系统运动方程。

### 9.5 第二组约束：必须能够只根据输出实现

输出反馈还要求：

$$
\Phi_{xw}M-\Phi_{xe}H=I,
$$

$$
\Phi_{uw}M-\Phi_{ue}H=0.
$$

两组约束与合适的因果结构结合，构成论文命题 1 的输出反馈 SLS 参数化。

仅满足动力学那两条还不够：它可能对应一个需要直接知道不可测状态或扰动的策略。输出反馈条件排除了这种不符合信息结构的响应。

#### 9.5.1 只符合动力学，为什么还不够

设外界刚给小车一个未知推力，你没有测推力的传感器，受到影响的图像又要下一步才到。一个数学方案若要求“立刻给出与该未知推力完全相反的输入”，也许能在运动方程里完美抵消它，却无法按现有传感器信息实际执行。

这就是“运动上说得通”和“控制器有信息做得到”的区别。第一组 SLS 条件保证响应符合运动方程；第二组条件和时间因果结构进一步保证能从已获得的输出实现它。论文不是允许控制器提前读到未来噪声，然后再声称实现了安全控制。

### 9.6 为什么因果结构重要

整个 $\Phi$ 按时间分块，未来扰动不能影响过去状态，因此有相应的块下三角结构。观测延迟会让某些块进一步为零。

这种结构不仅是一种稀疏性优化，还表达了“机器人只能用已经获得的信息做决定”。

### 9.7 从响应恢复控制器

论文式（10）给出：

$$
K=\Phi_{ue}-\Phi_{uw}\Phi_{xw}^{-1}\Phi_{xe}.
$$

其含义可以从两个关系看出。先由状态响应解出过程扰动：

$$
d_w=\Phi_{xw}^{-1}(\Delta\mathbf x-\Phi_{xe}d_e).
$$

代入输入响应：

$$
\Delta\mathbf u=
\Phi_{uw}\Phi_{xw}^{-1}\Delta\mathbf x
+\left(\Phi_{ue}-\Phi_{uw}\Phi_{xw}^{-1}\Phi_{xe}\right)d_e.
$$

再利用 SLS 约束，可将状态项与输出关系合并，得到只依赖 $\Delta\mathbf y$ 的实现。也可以反过来验证：若 $\Delta\mathbf u=K(H\Delta\mathbf x+d_e)$，则比较过程扰动与观测扰动的系数，有：

$$
\Phi_{uw}=KH\Phi_{xw},
\qquad
\Phi_{ue}=K(H\Phi_{xe}+I).
$$

于是：

$$
\Phi_{ue}-\Phi_{uw}\Phi_{xw}^{-1}\Phi_{xe}
=K(H\Phi_{xe}+I)-KH\Phi_{xe}=K.
$$

这一步消元是设计时的代数关系，不要求机器人执行时能够读取实际扰动。真正保证恢复结果符合信息结构的，是前面的整组 SLS 条件和因果结构。

#### 9.7.1 为什么这一串矩阵消元不会让执行变得很复杂

恢复公式中的逆矩阵属于生成并加载方案时的计算。原 rollout 先计算一次整段 $K_{\rm mat}$，每步再取当前输入对应的行块，乘已经获得的观测偏差。

因此，不是每次拍照后都重新求四个响应或重新解这个逆矩阵，更不是让机器人执行时估计出每个扰动的真实数值。保存的 $K$ 已经把相应的历史依赖折叠成一个可执行的线性映射。

对小车而言，一步输出两个输入修正量，过去每次观测提供三个数字，所以当前时刻对应的 $K$ 行块有 2 行，并按历史观测分成若干个 3 列小块。未来观测的块必须不能影响当前输入，这正由因果结构约束。

### 9.8 小车的实际张量与矩阵尺寸

代码为了统一块操作，把状态、输入和观测都填充到 $N+1=31$ 个块：

| 数组 | 四维张量尺寸 | 展平后尺寸 |
|---|---|---|
| `Phi_xx` | $(31,31,4,4)$ | $124\times124$ |
| `Phi_ux` | $(31,31,2,4)$ | $62\times124$ |
| `Phi_xy` | $(31,31,4,3)$ | $124\times93$ |
| `Phi_uy` | $(31,31,2,3)$ | $62\times93$ |

真实名义输入只有 30 步，额外终端输入块是填充，执行时不使用。

`convert_tensor_to_matrix()` 使用：

```python
tensor.transpose(0, 2, 1, 3).reshape(N * n, M * m)
```

不能直接对原张量调用普通 `reshape`，否则时间索引和状态维度的排列会错位。

### 9.9 这一步的输出和作用

**输入：** 局部时变模型与控制设计目标。

**输出：** 可实现的因果闭环响应。

**作用：** 后面可以直接计算扰动下的偏差大小，不必对每一个可能误差序列单独仿真。对固定线性模型，SLS 条件对响应是仿射约束，这也是相关综合问题能够凸化的重要原因。

## 10. 步骤八：用双 Riccati 高效生成响应

**主要源码：** [并行 Riccati 函数][S19]、[内层反馈计算][S20]、[响应组装][S16]。

### 10.0 先用白话看这一关：怎样快速算出上一关那些影响系数

第 9 节说清了“要设计什么”，这一节处理“怎样高效算”。如果把整段时间所有矩阵元素都交给通用求解器，变量很多。双 Riccati 利用局部二次性能子问题的结构，把计算拆成两种递推：

1. **控制侧：** 假如知道状态偏差，怎样用动作把它纠正得划算？
2. **观测侧：** 状态没有直接测全，怎样根据带误差的观测利用可获得的信息？

“Riccati”是这些矩阵递推的名称。先不用记住整行公式，只需看它每一步都在问：现在多修正一点，会减少多少未来状态误差，又要付出多少动作代价？

**教学假设：** 一维状态偏差为 $s$，修正输入为 $u$，下一步偏差为 $s+u$。若希望输入不要太大、下一步偏差也小，就最小化

$$u^2+(s+u)^2=2(u+s/2)^2+s^2/2.$$

平方项最小时 $u=-s/2$。因此偏了 0.2，就先修正 $-0.1$；不是因为必须只纠正一半，而是这组权重恰好给出这个折中。若给未来偏差更大权重，就会更积极纠偏。下面的矩阵 Riccati 是这一计算在多维、多步情形下的递推版本。

观测侧再考虑：如果图像很不可靠，贸然相信它就会打出错误动作，因此不一定应使用很强的视觉修正。最后两侧要组装成能用历史观测实现的完整响应。这里分解的是局部计算，整条路线仍由外层联合优化。

### 10.1 输入与输出

**输入：** $A_k,B_k,C_k,E_k,F_k$，误差代价权重，以及来自约束的权重 $\eta$。

**中间输出：** 控制侧增益与响应、观测侧增益与响应。

**最终输出：** 满足相应 SLS 结构的四组闭环响应。

### 10.2 为什么还要专门设计求解器

即使固定模型下的 SLS 优化是凸的，把整个时域的所有响应元素交给通用优化器，也会产生很多变量和约束。时域和状态维度增大时，直接求解很昂贵。

论文命题 4 利用无约束 LQG 子问题的结构：控制侧和估计侧分别通过 Riccati 递推求解，再组装为完整输出反馈响应。

当前代码还按扰动注入列组织多组递推，并使用 Numba `prange` 并行化这些列。每一列内部仍然按时间递推，并不意味着所有时间点完全相互独立。

### 10.3 控制侧：误差发生后怎样纠正最合适

先考虑局部误差系统：

$$
\Delta x_{k+1}=A_k\Delta x_k+B_k\Delta u_k.
$$

若余下时间的最优代价形如：

$$
V_{k+1}(\Delta x)=\Delta x^\top S_{k+1}\Delta x,
$$

当前一步需要最小化：

$$
\Delta x_k^\top Q\Delta x_k
+\Delta u_k^\top R\Delta u_k
+(A_k\Delta x_k+B_k\Delta u_k)^\top
S_{k+1}(A_k\Delta x_k+B_k\Delta u_k).
$$

对 $\Delta u_k$ 求导并令其为零，得到：

$$
K_k=-(R+B_k^\top S_{k+1}B_k)^{-1}B_k^\top S_{k+1}A_k,
$$

$$
\Delta u_k=K_k\Delta x_k.
$$

把它代回代价，可得 Riccati 递推：

$$
S_k=Q+A_k^\top S_{k+1}A_k+A_k^\top S_{k+1}B_kK_k.
$$

代码 `riccati_step()` 正是：

```python
K = -np.linalg.solve(Cu + B.T @ Sk @ B, B.T @ Sk @ A)
S = Cx + A.T @ Sk @ A + A.T @ Sk @ B @ K
```

在有约束启发式更新中，`Cx`、`Cu` 还加入由 $G^\top\operatorname{diag}(\eta)G$ 分块形成的权重。因而同一个基础递推可以根据约束紧迫程度改变反馈设计。

#### 10.3.1 把 Riccati 手算两步，就知道“向后递推”在做什么

仍取**教学系统** $s_{k+1}=s_k+u_k$，阶段代价为 $s_k^2+u_k^2$，终端代价为 $s_N^2$。

在最后一个可控制时刻，目标是

$$s^2+u^2+(s+u)^2.$$

上一节算出最优 $u=-0.5s$。代回得到最优总代价 $1.5s^2$。因此，往前一时刻看时，可以把“未来所有动作已经最优安排后的代价”概括成一个数 $S=1.5$，不必每次把所有未来动作重新展开。

再往前一步，需要最小化

$$s^2+u^2+1.5(s+u)^2.$$

求导得到 $u=-0.6s$，代回为 $1.6s^2$。递推可总结为：

| 所在步骤 | 已知下一步最优代价系数 | 算出的反馈系数 | 当前最优代价系数 |
|---|---:|---:|---:|
| 最后一个控制步 | 1 | -0.5 | 1.5 |
| 再往前一个控制步 | 1.5 | -0.6 | 1.6 |

这就是“从终点向前算每个时刻应该怎样纠偏”的意思。实际代码把这些标量换成矩阵，并包含局部动力学和约束相关权重；手算例子不等同于停车场最终反馈数值。

### 10.4 控制侧响应怎样向前传播

对在第 $j$ 列注入的状态误差，初始化：

$$
\bar\Phi^x_{j,j}=I.
$$

随后：

$$
\bar\Phi^u_{k,j}=K_{k,j}\bar\Phi^x_{k,j},
$$

$$
\bar\Phi^x_{k+1,j}
=(A_k+B_kK_{k,j})\bar\Phi^x_{k,j}.
$$

这告诉我们：假如状态误差在某一步出现，并采用相应反馈，它会怎样随时间衰减或放大。

但这时用到了完整状态误差。还需要观测侧把它变成可通过输出实现的结构。

### 10.5 观测侧：如何利用带噪观测减少未知状态的影响

观测侧采用对偶 LQR/Kalman 递推。为了说明其含义，令估计误差矩阵为 $\Pi_k$，则一类与延迟预测相适配的表达为：

$$
S_k^y=C_k\Pi_kC_k^\top+F_kF_k^\top,
$$

$$
L_k^+=A_k\Pi_kC_k^\top(S_k^y)^{-1},
$$

$$
\Pi_{k+1}=E_kE_k^\top+A_k\Pi_kA_k^\top
-A_k\Pi_kC_k^\top(S_k^y)^{-1}C_k\Pi_kA_k^\top.
$$

代码通过调用转置系统的 `riccati_step()` 实现对偶计算，其 `L_obs` 采用负转置等约定，所以不能仅按正负号把它与常见 Kalman 增益逐项比较。

直观上：

- $E_k$ 大，过程扰动影响大；
- $F_k$ 大，观测更不可靠；
- $C_k$ 决定哪些状态方向能够从观测中区分；
- 递推在这些因素之间分配观测修正。

这里的 $EE^\top$、$FF^\top$ 出现在 LQG 结构推导中。它们用于性能设计，不意味着安全约束只能在高斯噪声假设下成立。安全是否成立，取决于后面采用的有界扰动集合及其覆盖性。

#### 10.5.1 一个数值例子：观测越不可靠，为什么可能越少相信它

考虑无延迟的一维估计示意：已有预测为 $\hat s^-$，新观测为 $y$，修正公式为

$$\hat s^+=\hat s^-+L(y-\hat s^-).$$

假设预测误差二阶尺度 $P=0.04$，观测噪声二阶尺度 $R_y=0.01$，一种标准折中给出 $L=P/(P+R_y)=0.8$。预测为 1.00、观测为 1.10，则修正后为 1.08。

若其他量不变，但观测更不可靠，取 $R_y=0.36$，则 $L=0.1$，修正后只有 1.01。控制器不把新图像完全丢掉，而是降低它相对预测的权重。

这是帮助理解观测侧权重的**教学例子**，不是停车场延迟观测器的逐项公式。这里采用二阶尺度的估计解释，也不意味着安全集合必须按高斯分布定义。代码的性能递推与后续有界扰动收紧，各自承担不同任务。

### 10.6 两侧怎样组装成输出反馈响应

记控制侧响应为 $X_f,U_f$，观测侧响应为 $X_o,Y_o$，$M=I-Z_x\mathbf A$。代码按论文式（37）组装：

$$
\begin{aligned}
\Phi_{xw}&=X_f+X_o-X_fMX_o,\\
\Phi_{uw}&=U_f-U_fMX_o,\\
\Phi_{xe}&=Y_o-X_fMY_o,\\
\Phi_{ue}&=-U_fMY_o.
\end{aligned}
$$

这一步把“假如能测完整状态应该怎样控制”和“输出能够提供什么状态信息”组合成符合输出反馈信息结构的响应。

### 10.7 为什么使用估计递推，却仍然强调联合设计

固定一个局部模型后的无约束 LQG 子问题具有控制/估计分解结构。这与外层联合选择轨迹并不冲突。

区别在于：**外层的运动轨迹决定未来 $F(z_k)$，进而改变观测可靠性、反馈响应及约束余量。** 轨迹规划并没有假设“状态估计质量与运动选择无关”。

不过，这也不是一个精确求解任意 POMDP 的全局最优双重控制器。它通过局部模型、代价和误差集合实现信息相关规划。

### 10.8 理论保证到哪一层

命题 4 针对无约束线性时变 SLS-LQG 子问题。论文明确承认，完整约束求解器中对偶权重与双 Riccati 的耦合是启发式的，没有整体最优性保证。

需要区分：

1. 响应是否满足 SLS 代数结构；
2. 响应是否满足所需鲁棒约束；
3. 响应是否在所有可行方案中最优。

这是三个不同的问题。

## 11. 步骤九：计算可达管道和约束收紧

**主要源码：** [收紧的并行数值核心][S21]、[收紧更新及避障处理][S22]、[QP 约束构造][S23]。

### 11.0 先用白话看这一关：给路线提前留出“可能偏出去”的空间

假设围墙在横坐标 1.00 m。如果只要求计划位置不超过 1.00 m，规划器可能把中心线放到 0.99 m。可是机器人还可能向右偏 0.03 m，实际就会到 1.02 m。

若已计算出最坏向右偏差是 0.03 m，那么应要求

$$\underbrace{z_k}_{\text{计划位置}}+
\underbrace{0.03}_{\text{预留误差空间}}\le1.00,$$

也就是计划位置最多到 0.97 m。这就是约束收紧。0.03 来自误差大小与闭环响应的计算，不应该为了“看起来安全”随便指定。

管道与收紧是同一组误差传播的两种用途：管道用来描述实际可能在哪，收紧用来让中心线避开危险边界。对不同约束，关心的方向不同，例如横向边界只关心向右最坏偏差，不需要把所有状态分量直接加成一个距离。

**这一关交出的 `backoff` 是优化器下一轮需要遵守的安全余量。** 它不是网络输出的感知误差本身，也不是概率意义上的标准差。

### 11.1 输入与输出

**输入：** 四组闭环响应、扰动集合缩放、阶段和终端约束。

**输出：** 每条约束每个时刻的余量 `backoff`，以及状态和输入坐标方向的管道半宽。

### 11.2 从响应计算所有可能偏差

对某个时刻，把状态和输入偏差合并为：

$$
\Delta\chi_k=
\begin{bmatrix}\Delta x_k\\\Delta u_k\end{bmatrix}.
$$

由响应可写成：

$$
\Delta\chi_k
=\sum_{j\le k}\Phi^w_{k,j}E_jw_j
+\sum_{j\le k}\Phi^e_{k,j}F_je_j.
$$

这对应一个由各步扰动集合经线性映射再相加得到的集合。对于盒形扰动，它具有 zonotope 一类的集合结构；图中的坐标矩形是这个集合的轴对齐外包络，不是完整集合的精确形状。

### 11.3 为什么盒形扰动对应一范数

考虑单个扰动对一条线性约束的贡献 $a^\top w$。若 $|w_i|\le1$，则：

$$
a^\top w=\sum_i a_iw_i\le\sum_i|a_i|.
$$

取 $w_i=\operatorname{sign}(a_i)$，上界可以达到，因此：

$$
\max_{\|w\|_\infty\le1}a^\top w=\|a\|_1.
$$

对约束：

$$
c_i^\top\chi_k\le g_i,
$$

最坏偏差为：

$$
b_{k,i}
=\sum_{j\le k}\left[
\|c_i^\top\Phi^w_{k,j}E_j\|_1
+\|c_i^\top\Phi^e_{k,j}F_j\|_1
\right].
$$

于是只要名义量满足：

$$
c_i^\top[z_k;\bar u_k]+b_{k,i}\le g_i,
$$

实际量就满足原约束。这就是论文命题 2 的核心支持函数推导。

对固定的仿射闭环误差模型和相应独立扰动集合，该最坏情况表达是精确的。对非线性系统，还需要误差包含条件，不能只看这一条代数式。

### 11.4 为什么把不同时刻贡献直接相加

安全约束按最坏情况计算，不是假设误差相互抵消。每一个独立扰动块都可以选择对该约束最不利的方向，所以取各块支持函数之和。

这与独立零均值噪声方差的相加不同，也不是把全部贡献平方求和后再开根号。

### 11.5 当前代码实际使用二范数

`scan_tightening()` 中：

```python
mat_1 = (Gx @ Phi_xx[k, j] + Gu @ Phi_ux[k, j]) @ E[j]
mat_2 = (Gx @ Phi_xy[k, j] + Gu @ Phi_uy[k, j]) @ F[j]

sqrt_beta_x[k, j] = np.sqrt(np.sum(mat_1**2, axis=1))
sqrt_beta_y[k, j] = np.sqrt(np.sum(mat_2**2, axis=1))
sqrt_beta[k, j] = sqrt_beta_x[k, j] + sqrt_beta_y[k, j]
```

最后沿扰动时间轴相加形成 `backoff`。

对欧氏球扰动，有：

$$
\max_{\|w\|_2\le1}a^\top w=\|a\|_2.
$$

所以代码对应每一步过程扰动和观测扰动分别处在欧氏单位球中的支持函数，而论文正文定义的是无穷范数单位盒。

### 11.6 两种集合不一致会造成什么

取：

$$
a=[1,1],\quad \|a\|_1=2,\quad \|a\|_2=\sqrt2.
$$

若允许 $w=[1,1]$，真实最大影响是 2；仅预留 $\sqrt2$ 不够。二维单位盒包含这个角点，欧氏单位球不包含。

感知校准得到 $\|\epsilon\|_\infty\le b$，不能直接推出 $\|\epsilon\|_2\le b$。对 $n_r$ 维观测，只能一般地推出：

$$
\|\epsilon\|_2\le\sqrt{n_r}\,b.
$$

因此，使球形收紧覆盖该盒形误差的一种保守转换，是使用：

$$
F_{\mathrm{ball}}=\sqrt{n_r}\,bI.
$$

另一种方式是把收紧改成一范数以直接对应盒形集合。对于一般非标量、退化或更复杂误差形状，需要重新检查集合包含关系；不能机械套用一个因子就宣称整个安全链条完成。

这里是在解释如何对齐数学模型，本文没有修改原仓库代码。

#### 11.6.1 为什么范数差异真的会改变安全余量

**教学假设：** 某一约束方向受到两个误差分量的影响，组合为 $d=e_1+e_2$。

- 如果声明每个分量都在 $[-1,1]$，可以同时取 $e_1=e_2=1$，所以最大 $d=2$。
- 如果声明 $e_1^2+e_2^2\le1$，就不能同时各取 1；最大值为 $\sqrt2$，在两个分量均为 $1/\sqrt2$ 时取得。

若真实允许的是前面的盒子，却按后面的球只留 $\sqrt2$ 空间，就可能少留裕量。反过来，若真实集合就是那个球，按盒子计算可能过于保守。不是一范数或二范数谁天然更“安全”，而是计算必须与声明集合匹配。

同一时间块内多个误差分量先按其集合算最坏影响；不同时间块的允许误差若可分别选择方向，各时刻的最坏贡献再累加。这是两个层次的运算，不要把“某一行取二范数”误读为把整条轨迹所有时刻只取一次二范数。

### 11.7 管道矩形怎样画出来

若第 $\ell$ 个状态的最大绝对偏差为 $b^x_{k,\ell}$，则有坐标外包络：

$$
x_{k,\ell}\in
[z_{k,\ell}-b^x_{k,\ell},z_{k,\ell}+b^x_{k,\ell}].
$$

停车场位置图使用：

$$
[p_x-b_x,p_x+b_x]\times[p_y-b_y,p_y+b_y].
$$

矩形宽高分别是 $2b_x$、$2b_y$。将所有时刻的这些集合串起来，就得到可达管道的可视化。

### 11.8 避障收紧的几何含义

代码将位置矩形包入圆，取：

$$
r_{\mathrm{tube}}=\sqrt{b_x^2+b_y^2}.
$$

若这个半径确实覆盖位置偏差，利用三角不等式：

$$
\|x^{xy}-c_o\|_2
\ge\|z^{xy}-c_o\|_2-\|x^{xy}-z^{xy}\|_2,
$$

只要：

$$
\|z^{xy}-c_o\|_2\ge r_o+r_{\mathrm{tube}},
$$

就能让该位置误差集合避开障碍物。

在局部轨迹优化中，距离函数在当前 $z$ 处线性化。对于凸距离函数，切平面是其全局下界，因此在固定有效余量下，用这个下界满足距离下限是一种保守处理。但模型、余量和轨迹都在迭代变化，最终仍需重新核查一致性。

### 11.9 数值例子：从半宽到安全距离

假设某一步名义位置为 $(0.5,0.4)$，位置半宽为：

$$
b_x=0.08\text{ m},\quad b_y=0.06\text{ m}.
$$

则位置外包络为：

$$
[0.42,0.58]\times[0.34,0.46],
$$

对应外包圆半径为 0.10 米。若障碍物有效半径是 0.30 米，就要求名义位置离障碍物中心至少 0.40 米。

这些数字仅用于说明计算含义，不是本次重新运行实验得到的结果。

## 12. 步骤十：联合优化轨迹、感知质量与反馈

**主要源码：** [外层主循环][S24]、[内层主循环][S25]、[对偶权重更新][S26]、[管道代价][S27]、[轨迹代价导数更新][S28]。

### 12.0 先用白话看这一关：路线、观测质量和纠偏方式要互相配合

设有两条路线。短路线经过遮挡，图像容易看错；长路线绕到清晰区，但多花时间和动作。不能只按路长选，也不能只挑视觉最清楚的位置；还要看车能否及时纠偏、输入限制够不够、障碍余量是否可行。

**教学假设：** 短路线到障碍边缘只剩 0.10 m，按当前反馈计算的最坏位置偏差为 0.18 m，那么它暂时不满足收紧约束。另一条路线有 0.15 m 空间，偏差只有 0.05 m，就可能是可行选择。这些数只说明选择逻辑，不是原停车场测量值。

为什么反复算？因为改了路线，局部动力学和图像误差大小会变；改了反馈，同样的误差又会产生不同偏差。所以一轮可以理解为：

```text
先拿当前路线 → 在这条路上设计反馈 → 算可能偏出去多少
          → 给路线加安全余量 → 改路线 → 再检查新路上的反馈和余量
```

**外层 SCP** 主要处理非线性模型沿新路线的更新；**内层 fast-SLS** 在当前局部模型下协调轨迹、反馈和约束余量。两个循环不是“训练视觉网络”和“训练控制网络”，都属于模型优化计算。

外层所说的“重新规划”发生在生成方案阶段；当前执行脚本随后加载保存的方案，并不是每一步都运行这两个循环。

### 12.1 为什么需要反复迭代

这几个变量存在循环依赖：

```text
轨迹 z
  → 局部动力学 A、B 与感知误差 F(z)
  → 闭环响应 Φ
  → 不确定性管道和安全余量
  → 可行轨迹及其代价
  → 新轨迹 z
```

一次固定轨迹的控制器设计，只能解决其中一段关系。外层迭代的目的，就是让它们逐步适配。

### 12.2 总代价的两部分

$$
J=J_{\mathrm{traj}}+J_{\mathrm{tube}}.
$$

第一项是前文的目标距离和控制代价。第二项主要是：

$$
\begin{aligned}
J_{\mathrm{tube}}\sim\sum_{k,j}\big(&
\|Q_e^{1/2}\Phi_{xw}^{k,j}E_j\|_F^2
+\|R_e^{1/2}\Phi_{uw}^{k,j}E_j\|_F^2\\
&+\|Q_e^{1/2}\Phi_{xe}^{k,j}F_j\|_F^2
+\|R_e^{1/2}\Phi_{ue}^{k,j}F_j\|_F^2\big)
+J_{\mathrm{terminal}}.
\end{aligned}
$$

这里 $Q_e,R_e$ 对应代码 `Q_reg,R_reg`；终端还有 `Q_reg_f`。它们对扰动引起的状态、输入偏差加权。

在适当的独立单位协方差随机扰动解释下，这种 Frobenius 平方代价对应期望二次偏差能量。这是 LQG 性能目标的来源。

**它不是直接计算最坏可达集合的几何体积。** 论文中“让管道变小”的直观叙述，与实现中的这个能量代理目标需要区分。

### 12.3 主动获取信息究竟从哪里出现

在固定当前响应时，观测误差代价中有：

$$
\|\Phi_{xe}^{k,j}F(z_j)\|_F^2.
$$

轨迹位置改变，就会改变 $F(z_j)$。如果某条路线经过高误差区，即使路程短，也可能产生较大的观测误差传播代价和更大的安全余量。

外层 `update_traj_cost_wrt_tube()`：

1. 把当前响应 $\Phi$ 作为固定参数；
2. 对当前轨迹向量计算管道代价梯度；
3. 计算 Hessian，并加入数值正则项；
4. 把这些代价项交给轨迹 QP；
5. 轨迹改变后，再重新设计响应。

因此，主动获取信息不是一个额外的“看不清就转向”规则，而是状态相关误差模型通过目标函数和约束影响运动选择的结果。

### 12.4 外层 SCP 实际做什么

`SCP_OF_SLS.solve()` 的简化执行顺序为：

```python
solve_nominal_trajectory(x0, x_goal)

for outer_iter in range(20):
    update_jacobian()                # 更新局部模型、误差取值和约束余量基准
    update_traj_cost_wrt_tube()      # 在启用信息相关代价时更新
    solution = fast_solver.solve()  # 内层轨迹—反馈迭代
    z += solution.delta_z
    u_nom += solution.delta_u
    Phi = solution.Phi
    backoff = solution.backoff
    if trajectory_step_is_small():
        break
```

这是说明调用逻辑的伪代码，不是可以直接替换原类的完整实现。

外层停止阈值是轨迹增量向量的二范数小于 $10^{-3}$，最大 20 次迭代。

### 12.5 内层 fast-SLS 实际做什么

`fast_OF_SLS._step()` 的顺序非常重要：

1. **轨迹前向求解：** 用当前收紧约束解 QP；
2. **提取对偶变量：** 得到阶段与终端约束乘子 $\mu$；
3. **更新响应权重：** 形成 $\eta$；
4. **反馈求解：** 运行控制侧和观测侧 Riccati，组装 $\Phi$；
5. **重新收紧：** 用新 $\Phi$ 计算新的 `backoff`；
6. **检查变化：** 若尚未停止，就用新余量再解 QP。

最大内层迭代次数为 25。

这也解释了为什么最后不能只看某次 QP 成功：它解的是上一次余量下的问题，新响应和新余量产生后，需要检查两者是否一致。

### 12.6 对偶变量 $\mu$ 和权重 $\eta$ 的作用

在约束优化里，对偶变量衡量约束边界对最优目标的影响。某条约束非常紧迫时，其乘子往往较大。

代码使用：

$$
\eta_{k,j,i}
=\frac{\mu_{k,i}}{2\sqrt{\beta_{k,j,i}}}.
$$

随后形成：

$$
G^\top\operatorname{diag}(\eta_{k,j})G,
$$

把相关状态和输入方向加进 Riccati 的代价。

直观上：如果位置上限很紧，求解器就希望反馈更有效地限制朝该边界的偏差，而不是只按统一的跟踪权重设计。

但论文明确说明，当前输出反馈约束情形中的这套耦合没有完整的 KKT 最优性推导。代码中 `beta` 与分开过程/观测贡献形成的实际收紧之间，也不能凭平方根求导的直觉就宣称是完整精确梯度。因此应把这一更新理解为作者采用的启发式数值机制。

#### 12.6.1 用“哪堵墙最紧”理解对偶变量

**教学假设：** 左边有一堵很远的墙，右边的墙刚好限制了当前最短路线。若把左墙向外移动一点，最优代价可能几乎不变；把右墙向外挪一点，路线却可以明显变短。右墙这条约束的对偶乘子往往更大。

所以，对偶变量可理解为在适当局部条件下“放宽这条限制，对最优目标有多大帮助”的敏感度。它不是传感器误差，也不是机器人当前受到的真实力。

内层算法利用这种紧迫性，调整反馈设计时重点惩罚的方向：哪条边界更紧，就更重视相关误差方向。但反馈、余量和轨迹会互相影响，因此这仍需迭代，不能把一次对偶更新当作完整问题已经收敛或全局最优的证明。

### 12.7 局部 QP 的变量和约束

停车场局部 QP 的主要变量包括：

$$
[\delta z_0;\delta\bar u_0;\ldots;\delta z_{N-1};\delta\bar u_{N-1};\delta z_N;s_f].
$$

其中 $s_f$ 为终端约束松弛变量。主变量长度为：

$$
N(n_x+n_u)+n_x=30\times6+4=184.
$$

再加 8 个终端松弛变量，共 192 个变量。

约束包括局部线性动力学、阶段上下界、终端界、线性化避障约束及初始增量固定。原轨迹起点已经给定，所以传入局部求解器的 `delta_x0` 为零，不代表实际初始状态没有不确定性。

外层前 5 次迭代允许终端约束松弛，以帮助接近可行方案；之后恢复相应终端限制。松弛和实际收敛状态也应纳入最终检查。

### 12.8 两个实验开关的准确含义

**`certainty_equivalent=True`：** 在当前主类中，主要跳过管道代价关于轨迹的导数构造与更新。因此关闭的是这条显式的信息相关轨迹代价通道；它不会自动把 $F$ 清零，也不会自动关闭全部鲁棒约束或输出反馈。

**`non_robust=True`：** 收紧更新时把应用到约束上的 `backoff`、`backoff_f` 置为零。响应和信息相关代价的计算不一定全部关闭。

所以阅读基线时，要以具体开关的代码作用为准，不能仅根据 CE、NR 的名称假定其实现等于某个教科书算法。

- 用于约束收紧和可视化的余量；
- 初始方案与最终方案之间的比较信息。

由于原问题非凸、局部模型反复改变、内层耦合含启发式更新，不能把结果理解为全局最优；最终可行性也需要独立核查，而不能仅依赖成功标志。

## 13. 步骤十一：恢复控制器并闭环执行

**主要源码：** [方案保存][S29]、[执行入口][S30]。

### 13.0 先用白话看这一关：计划已经算好，现在每一步怎样用图像修正动作

执行前保存了名义路线、名义输入与整段反馈矩阵。执行第 $k$ 步时，先拿到当前可用的图像观测，减去对应的名义观测，再按反馈矩阵当前行块计算动作修正。

**教学假设：** 某一维位置的名义观测为 1.00，实际观测为 1.06，当前对应反馈系数为 $-0.5$，则该项贡献的修正为 $-0.03$。若名义输入为 0.10，且没有其他历史项，实际输入为 0.07。原停车场有三维观测、二维输入和很多历史项，所以代码是矩阵乘法后求和。

这里减的是名义观测，不是真实状态对应的观测。控制器看到的 0.06 可能包括真实偏离和感知错误，不能凭这一数字知道两者各占多少；第 10 节的观测设计和第 11 节的误差余量就是为这种信息不完美做准备。

请始终区分两个动作：**重新读取观测并计算一个新输入，每步都会做；重新求完整轨迹与反馈方案，当前 rollout 每步并不做。**

### 13.1 输入与输出

**执行前输入：** 名义轨迹、名义输入、四组 SLS 响应、误差管道、感知模型。

**每步在线输入：** 已获得的图像观测历史。

**每步在线输出：** 当前实际控制量 $u_k$。

### 13.3 恢复整段时间的反馈矩阵

执行脚本加载方案后：

```python
K_mat = Phi_uy - Phi_ux @ np.linalg.inv(Phi_xx) @ Phi_xy
```

这对应论文式（10）。小车填充后的 $K$ 尺寸为 $62\times93$，可以划分成每块 $2\times3$ 的时间块。

若在数值实现中改写，通常可以用线性求解代替显式求逆；但当前代码确实调用 `np.linalg.inv`，本文没有修改它。

### 13.4 历史观测残差怎样进入当前输入

暂不计首个占位观测，定义延迟对齐后的残差：

$$
\rho_j=y_j^r-Cz_{j-1}.
$$

当前反馈修正为：

$$
\Delta u_k=\sum_{j\in\mathcal I_k}K_{k,j}\rho_j,
$$

其中 $\mathcal I_k$ 是截至时刻 $k$ 已经可用的观测索引集合。实际输入为：

$$
u_k=\bar u_k+\Delta u_k.
$$

代码中，核心循环为：

```python
delta_u += K_block @ (
    observations[:, j] - C @ nominal_state_for_that_observation
)
u = primal_u[:, t-1] + delta_u
```

残差表示“实际看到的”和“按计划应当看到的”之间的差。它不必被单独转换成一个显式状态估计，动态估计的作用已包含在整段输出反馈映射里。

### 13.5 延迟索引的具体例子

执行循环采用 `t=1,...,N`，当前控制索引是 $k=t-1$：

| 循环 | 获取的观测 | 与哪个名义状态比较 | 当前动作 |
|---|---|---|---|
| `t=1` | 初始状态图像，放入首个占位槽 | 初始名义状态 | $u_0$ |
| `t=2` | 状态 $x_0$ 的图像，作为延迟观测 | $z_0$ | $u_1$ |
| `t=3` | 状态 $x_1$ 的图像 | $z_1$ | $u_2$ |
| `t=4` | 状态 $x_2$ 的图像 | $z_2$ | $u_3$ |

虽然首个槽中放了图像，当前递推结构生成的首观测反馈列为零；在本次小规模数值核对中也确认了这一点。因此首槽不应被理解成取消了模型的一步延迟。改变首步观测约定时，需要同步检查 $K$ 的结构和误差传播模型。

### 13.6 一个仅用于说明的反馈数值例子

假设某条历史观测残差是：

$$
\rho_j=\begin{bmatrix}0.02&-0.01&0.03\end{bmatrix}^{\top},
$$

对应当前动作的块是：

$$
K_{k,j}=\begin{bmatrix}
0.5&-0.2&0.1\\
-0.3&0.4&0.2
\end{bmatrix}.
$$

该观测对当前输入的贡献为：

$$
K_{k,j}\rho_j=\begin{bmatrix}0.015\\-0.004\end{bmatrix}.
$$

当前动作还会加上其他历史残差的贡献，最后再加名义动作。这些数值不是实际学习到的增益，只是说明块矩阵乘法的含义。

### 13.7 仿真中真实状态到底有没有进入控制器

代码持有真实状态，原因有两个：

1. 用它把虚拟小车放到场景中，生成对应图像；
2. 用动力学积分计算下一真实状态。

真正的反馈修正使用图像经过 DINO 和投影网络得到的观测。不能因为仿真脚本有一个 `states` 数组，就推断控制器直接使用全部真实状态；也不能因为调用了 PyBullet，就推断小车运动全部由 PyBullet 刚体接触仿真决定。

该执行路径是 `m.ddyn()` 推进状态，再用 PyBullet 渲染。

### 13.8 有限时域反馈与滚动 MPC 的区别

当前示例：

```text
求一次完整方案 → 保存 → 在方案上连续做视觉闭环反馈
```

滚动 MPC 则需要：

```text
更新当前状态/不确定性 → 重求未来方案 → 执行第一个动作 → 下一步重复
```

两者都可以有反馈，但计算流程、递归可行性问题和实时要求不同。当前停车场执行脚本没有每步重求完整方案。

## 14. 步骤十二：验证结果与解释实验指标

**主要源码：** [感知覆盖验证][S31]、[闭环评估][S30]、[求解停止条件][S32]。

### 14.0 先用白话看这一关：到达终点不等于所有中间假设都对

一次运行可能同时出现：“车没有撞”“网络残差超出了误差界”“实际动作超出了预测管束，但没有超过真实输入上限”。这三句话不矛盾，因为它们检查的是三种不同的边界。

**教学假设：** 输入允许范围是 $[-4,4]$，计划输入为 1.0，预测输入半宽为 0.1。若实际输入是 1.2，它仍满足真实输入限制，却超出预测的 $[0.9,1.1]$ 管束。反过来，实际输入即使在某个预测管束内，也要确认那个管束本身没有越过物理限制。

这一关要把任务成功、实际约束、误差集合覆盖、预测管道包含、数值求解残差分别记录。这样才能说清楚方法在哪些方面有效，哪些假设还需要改进，而不是只用一个“成功”数字概括整套方法。

### 14.1 应当分别验证什么

完整方法有几层验证对象：

| 对象 | 合理的检查方式 | 不能由什么替代 |
|---|---|---|
| 感知精度 | 配对数据上的残差分布 | 只看平均训练损失 |
| 感知误差覆盖 | 独立数据上的绝对残差与包络比较 | 只看拟合样本 |
| SLS 结构 | 四组矩阵等式与因果结构残差 | 只看轨迹图 |
| 局部鲁棒约束 | 响应与当前误差集合下的最坏情况余量 | 只看某次 rollout 成功 |
| 非线性一致性 | 动力学余项和观测变化包含、管道自洽 | 只看线性约束满足 |
| 执行表现 | 多初值、多扰动闭环测试 | 只看名义路线 |

### 14.2 感知覆盖率应当怎样计算

目标定义应是：

$$
\widehat{\operatorname{Coverage}}
=\frac1M\sum_{i=1}^{M}
\mathbf1\left\{
\|p_\theta(\psi(I_i))-Cx_i\|_\infty\le b(x_i)
\right\}.
$$

停车场 `verify_perception.py` 中实际写的是：

```python
residual = y_hat - y_lin
Norm_res[t] = np.max(residual)
```

这里漏了绝对值。按上述定义应当比较：

```python
np.max(np.abs(residual))
```

例如：

$$
\epsilon=[-0.20,0.01,0.02],\qquad b=0.05.
$$

当前写法得到 0.02，判定被覆盖；真正无穷范数为 0.20，实际未被覆盖。

所以，这个验证脚本可能高估经验覆盖率。这里只能确定计算方式存在问题，不能在未重新评估数据前给出修正后的覆盖数值，也不能据此直接量化论文所有结果受影响的程度。

### 14.3 每次 rollout 中的扰动怎样生成

停车场脚本固定一个 `eval_idx`，默认做 50 次 rollout：

- 前 8 次分别沿 4 个过程扰动坐标方向取固定正、负单位扰动；
- 后续随机方向归一化到二范数为 1；
- 实际观测误差来自图像和感知网络，不是额外手工注入的 `disturbance_obs`。

固定坐标方向和随机球面方向都属于欧氏单位球，因而这部分过程扰动测试与代码二范数收紧相吻合；它没有遍历盒形扰动的所有角点。

脚本为每条 rollout 设置 `states[:,0] = x0`，没有在这里额外采样整个初始不确定性集合。因此初始误差通道的理论覆盖也不能仅靠这个循环验证。

### 14.4 成功率和违反率的实际含义

代码：

```python
success += int(arrive and not collides)
constr_violation += int(
    (not path_in_bounds) or (not final_in_bounds) or collides
)
```

其中 `arrive` 只检查终端位置分量进入目标区间；`final_in_bounds` 检查完整终端状态边界。

因此某条 rollout 可以位置到达且不碰撞，但某个终端朝向、速度或路径状态违反约束。这解释了成功率和约束违反率不一定互为补数。

此外，这段统计没有把所有实际输入边界检查计入违反率。若要验证完整状态—输入约束，需要同时保存或检查每步 $u_k$。

碰撞检测是在离散状态时刻检查圆形几何关系。若要证明两个采样时刻之间也不碰撞，还需要额外的连续时间或扫掠路径验证；当前离散检查本身不提供该结论。

### 14.5 为什么 `success=True` 不等于数学证书

外层达到最大 20 次迭代时，代码仍可设置成功。内层达到最大次数、没有遇到前向求解异常时，也会返回成功状态。

还有一个停止检查细节：

```python
delta_primal = np.max(current_primal - previous_primal)
```

这里没有取绝对值或范数。若所有变化都是负的，即使幅度较大，也可能使这一项小于阈值。代码另外检查 `backoff` 的绝对变化，但这并不能把前一项自动变成严格的变量收敛判据。

更合理的结果解释是：成功标志表示程序走到了一个允许返回结果的分支；是否收敛、最终约束余量是否为非负、响应与最后轨迹是否一致，应另行核查。

## 15. 安全保证究竟需要哪些条件

### 15.0 先用白话看这一关：理论保证是一条带前提的推理

可以把安全论证想成一张有尺寸限制的通行证：车的实际误差必须在声明范围内，模型必须能包含实际运动，规划器还要真的留够空间。满足这些前提，才能按定理推出约束成立。

“可能误差不超过 0.03 m，并且计划离墙至少 0.03 m”能支持一个条件结论；如果实际误差可能到 0.10 m，就不能继续引用前面那张 0.03 m 的通行证。是否刚好没有撞墙，属于另一个实际结果问题。

读这一节时，先把条件分为三组：**输入的误差范围对不对；传播误差的模型对不对；最后计划有没有真的满足收紧约束。** 后面的符号只是在精确描述这三组检查。

### 15.1 把“保证”写成有条件命题

论文理论的正确理解是：

> 若真实初始状态和所有扰动被所声明集合覆盖，非线性与观测变化被有效包络覆盖，SLS 响应满足实现条件，而且收紧约束及管道自洽约束成立，那么在对应有限预测时域内，实际状态和输入满足所建模的约束。

这里的每个条件都承担具体作用。

### 15.2 非线性管道为什么要自洽

假设某一步的余项包络只在：

$$
\|[\Delta x_k;\Delta u_k]\|_\infty\le\tau_k
$$

时有效。若算出的闭环误差可能超过 $\tau_k$，就不能继续使用这个包络。

因此必须同时保证：

$$
\text{由 }\Phi,\Sigma,\Upsilon\text{ 算出的各坐标最坏偏差}\le\tau_k.
$$

这是论文式（26b）的作用：不是给优化器加一个任意尺寸的框，而是让“包络适用范围”和“响应实际可能达到的范围”相互一致。

#### 15.2.1 “自洽”不是循环论证，而是要检查一个包含关系

假设你只证明了“当偏差不超过 0.10 时，非线性余项不超过某个界”。然后用这个余项界计算闭环偏差，发现最大偏差为 0.08，那么推理范围没有被自己突破：预计到达的范围包含在先前假设的 0.10 范围内。

若计算出最大偏差为 0.13，就失败了。此时不能说“我已经假设了偏差最多 0.10，所以把结果截成 0.10”；需要扩大分析范围、重新计算余项与反馈，或者承认该方案在当前条件下没有通过这项检查。

**教学假设：** 某种局部分析给出的偏差上界为 $T(\tau)=0.05+0.5\tau^2$，且该公式在讨论范围有效。尝试 $\tau=0.04$，得到 $T=0.0508>0.04$，范围不自洽；尝试 $\tau=0.10$，得到 $T=0.055\le0.10$，通过这项包含检查。这个数字模型只是解释 $T(\tau)\le\tau$ 的含义，不是源码实际使用的余项公式。

### 15.3 一个归纳式的证明思路

1. 初始误差落在声明的初始集合中。
2. 假设到当前一步，误差都处在相应局部分析范围内。
3. 有效包络把非线性余项、过程扰动和观测变化包含到线性误差系统的扰动集合。
4. SLS 响应给出该误差系统的闭环偏差集合。
5. 自洽约束保证偏差不会超出下一步使用包络的范围。
6. 支持函数收紧保证每条状态、输入约束在最坏偏差下仍然满足。
7. 沿预测时域重复。

这说明：线性化、包络、管道和收紧缺少任何一项，都不能直接套用完整非线性保证。

### 15.4 当前代码与理论条件的对应

| 理论需要 | 当前实现观察 | 结论边界 |
|---|---|---|
| 可实现的因果输出反馈响应 | 有双侧 SLS 组装，轻量代数核对成立 | 结构构造有明确依据 |
| 扰动集合与支持函数一致 | 论文是盒，主收紧是球 | 需要重新对齐集合或范数 |
| 感知误差有效覆盖 | 经验多项式拟合，允许样本放宽 | 不能当作全区域确定性上界 |
| 覆盖率统计正确 | 可见验证脚本漏绝对值 | 需修正并重算该统计 |
| 非线性余项覆盖 | 主实现未实现，开启会报错 | 不能直接宣称完整非线性证书 |
| 管道内观测误差膨胀 | 主要在名义状态取 $F$ | 未完整实现 $\Upsilon(z,\tau)$ |
| 最终响应、轨迹、余量一致且约束成立 | 依赖迭代，达到上限也可成功 | 需要独立的最终残差检查 |
| 实际执行落在声明模型范围内 | 有限场景的 rollout 和少量实机验证 | 经验支持不等于任意环境保证 |

### 15.5 经验覆盖率不等于整段轨迹安全概率

即使正确测得单个样本上约 99% 的覆盖率，也不能直接宣称 30 步轨迹有 99% 的安全率。

原因包括：

- 控制器选择的状态分布可能不同于校准分布；
- 多步误差存在相关性；
- 一次越界是否导致碰撞，还取决于反馈和几何余量；
- 经验比例本身有有限样本不确定性。

仅为说明概念：若每步误差独立且每步覆盖概率严格等于 0.99，30 步全部覆盖的概率为 $0.99^{30}\approx0.74$。这些独立同分布假设没有由当前校准代码建立，因此该数字不是对论文实验安全率的估计。

论文提到 conformal prediction、极值理论、Lipschitz 或神经网络验证等可能替代方案。这些可以提供不同类型的统计或确定性保证，但当前经验包络不能自动继承它们的性质。

### 15.6 有限时域约束满足不等于无限时域稳定

本文分析的是给定时域和误差模型下的约束满足。若要进一步声称无限时域稳定、滚动 MPC 递归可行、遇到任意完全遮挡也能安全，需要额外条件和算法机制。

例如终端不变集、可恢复策略、在线重新估计不确定性等，都不是看到 `SLS` 或 `MPC` 字样就自动具备的功能。

## 16. 四旋翼、人形机器人与实机的差异

### 16.1 四旋翼：替换动力学和感知维度

### 17.3 为什么规划器能预测未来“看见什么”

因为监督训练让视觉输出与 $Cx$ 对齐。规划器有候选状态 $z_k$，于是可以预测 $Cz_k$。

它预测的是低维观测及其误差集合，而不是未来图像的每个像素。这是低维接口让规划可扩展的关键。

### 17.4 为什么不对 $C$ 做伪逆直接估计状态

小车的 $C$ 是 $3\times4$，单帧缺少速度信息。伪逆只能给出某种欠定解，不会凭空恢复不可观测方向。

时间历史与动力学让速度影响未来位置，动态输出反馈才能利用这些信息。直接单帧伪逆会丢掉论文要处理的部分可观测性问题。

### 17.5 管道是不是机器人自己的置信区间

严格按理论，它是允许扰动集合经过模型和控制器传播得到的最坏情况可达集合或其外包络，不是由某个概率水平定义的置信区间。

但当前感知误差集合采用经验校准，且实现缺少若干完整保证条件，所以图中的绿色管道不能在未经核查的情况下当成绝对包络。

### 17.6 惩罚误差能量就一定能获得最小管道吗

不能。Frobenius 平方代价偏向降低总体加权误差能量；某条具体约束方向的最坏误差，取决于该方向上的支持函数。

所以代码同时需要 `J_tube` 和 `backoff`：前者引导性能和感知质量，后者服务于硬约束处理。二者相关，但不等价。

### 17.7 感知更准，为什么反馈不一定越强越好

过强反馈也会把观测噪声放大成控制输入变化。控制器必须在偏差纠正、输入代价、观测可靠性和输入限制之间折中。

这就是为什么除了 $\Phi_{xw}$，还需要 $\Phi_{xe}$、$\Phi_{uw}$、$\Phi_{ue}$：好的闭环设计不仅要纠正过程扰动，也要控制观测噪声进入动作的幅度。

### 17.8 完全看不见时能不能自动保证安全

不能从当前方法和实验直接推出。若观测长时间失效，系统可能无法持续减少不确定性，管道也可能增长到没有可行路线。

论文把完全遮挡处理列为未来方向之一。当前实验的重遮挡和任意时长、完全无信息的遮挡不是相同条件。

### 17.9 复现时先确认哪些具体一致性

下面是理解和复查本仓库时需要逐项对齐的技术点。后续服务器复现已完成其中多项检查，但这里的清单本身不代表论文全部复现或理论条件均已通过：

1. 配置、checkpoint 中的 $C$ 与动力学类中硬编码 $C$ 是否一致，行归一化约定是否一致；
2. 图像预处理、DINO 版本、CLS token 类型是否与训练一致；
3. 渲染状态、名义观测和误差地图的坐标偏移是否一致；

5. 残差范数、允许扰动集合与收紧支持函数是否一致；
6. 初始不确定性、过程扰动离散化和观测延迟索引是否一致；

## 19. 把一套简化视觉闭环完整手算一遍

本节所有数值均为**教学假设，不是论文参数或复现实测**。为便于手算，使用一维线性运动、无观测延迟、已知初始状态和两个控制步。停车场实际是四维非线性系统并有观测延迟，不能把本节公式直接替换进原脚本。

这套简化模型的优点是，你能逐行看到：视觉误差怎样影响动作，动作怎样影响位置，响应系数怎样变成管道，以及管道怎样决定路线能否贴近边界。

### 19.1 第一步：写明运动、观测与误差范围

设实际运动为

$$x_{k+1}=x_k+u_k+0.02w_k,\qquad |w_k|\le1.$$

这里 $x$ 是一维位置，$u$ 表示一个采样间隔内的位置推进量，而不是原小车的角速度或加速度。$0.02w_k$ 是这一步额外的位置扰动，最大绝对值 0.02。

假设视觉模型为

$$y_k=x_k+0.04e_k,\qquad |e_k|\le1.$$

等价于 $C=1,E=0.02,F=0.04$。这表示观测相对真实位置最多偏 0.04。此处直接假设该界有效；真实实验仍须用校准或分析获得它，不能从一两个样本就宣布全局有效。

模型与名义计划的关系为

$$z_{k+1}=z_k+\bar u_k.$$

选择初始名义位置 $z_0=0.70$，两步名义输入 $\bar u_0=0.12$、$\bar u_1=0.11$，得到计划位置 $z_1=0.82,z_2=0.93$。假设初始真实状态恰好等于 $z_0$。

到这里我们只得到一条中心线：$0.70\to0.82\to0.93$，还没有计算实际可能偏多少。

### 19.2 第二步：选定一个能用观测执行的简单反馈

为示例方便，固定

$$\Delta u_k=-0.5(y_k-z_k),\qquad u_k=\bar u_k+\Delta u_k.$$

它只使用视觉观测与名义位置，执行时不需要真实状态标签。它不是本例两步有限时域的最优 Riccati 答案，更不是停车场已求得的控制器；这里只选一个容易手算的反馈。

记 $\Delta x_k=x_k-z_k$，则

$$y_k-z_k=\Delta x_k+0.04e_k,$$

所以

$$\Delta u_k=-0.5\Delta x_k-0.02e_k,$$
$$\Delta x_{k+1}=0.5\Delta x_k+0.02w_k-0.02e_k.$$

这两行就是“反馈后的误差系统”。注意：第二行的 $-0.02e_k$ 并非观测噪声直接推车，而是它先误导控制输入，再通过运动方程影响真实位置。

### 19.3 第三步：把两步误差彻底展开

初始 $\Delta x_0=0$，于是

$$\Delta u_0=-0.02e_0,$$
$$\Delta x_1=0.02w_0-0.02e_0.$$

再到下一步：

$$\Delta u_1=-0.01w_0+0.01e_0-0.02e_1,$$
$$\Delta x_2=0.01w_0+0.02w_1-0.01e_0-0.02e_1.$$

现在已经能回答“第一步的看错到第二步还有多大影响”：它在 $\Delta x_2$ 中的系数是 $-0.01$。为什么比第一步的 $-0.02$ 小？因为选定的闭环误差系数 0.5 把已有偏差保留了一半。

### 19.4 第四步：看见四组 SLS 响应其实就是这些系数

为了与第 9 节对齐，先把实际幅度记成 $d^w_k=0.02w_k$、$d^e_k=0.04e_k$，将缩放从响应系数中拆出来。上述展开可写成：

$$\Delta x_1=d^w_0-0.5d^e_0,$$
$$\Delta x_2=0.5d^w_0+d^w_1-0.25d^e_0-0.5d^e_1,$$
$$\Delta u_0=-0.5d^e_0,$$
$$\Delta u_1=-0.5d^w_0+0.25d^e_0-0.5d^e_1.$$

把“输入一个误差会影响哪些输出”排成表：

| 误差来源 | 对 $\Delta x_1$ 的系数 | 对 $\Delta x_2$ 的系数 | 对 $\Delta u_0$ 的系数 | 对 $\Delta u_1$ 的系数 |
|---|---:|---:|---:|---:|
| 实际运动扰动 $d^w_0$ | 1 | 0.5 | 0 | -0.5 |
| 实际运动扰动 $d^w_1$ | 0 | 1 | 0 | 0 |
| 实际观测误差 $d^e_0$ | -0.5 | -0.25 | -0.5 | 0.25 |
| 实际观测误差 $d^e_1$ | 0 | -0.5 | 0 | -0.5 |

前两行到状态的系数属于 $\Phi_{xw}$，前两行到输入的系数属于 $\Phi_{uw}$；后两行到状态属于 $\Phi_{xe}$，到输入属于 $\Phi_{ue}$。

这张表只截取相关时段的系数，不含原代码的完整初始与终端填充，不能直接当作第 9 节完整矩阵去验证所有恒等式。但四组响应的物理含义已经能从中读出来。

还可以看见因果性：第二步运动扰动 $d^w_1$ 发生在 $u_1$ 已经决定之后，不能影响 $u_1$；第二次观测误差不能影响更早的 $u_0$。这些零不是偶然，而是信息时序的要求。

### 19.5 第五步：不枚举所有噪声，也能算出最坏管道

由于每个归一化误差都在 $[-1,1]$，线性表达式的最大绝对值可以按各系数绝对值求和：

$$|\Delta x_1|\le0.02+0.02=0.04,$$
$$|\Delta x_2|\le0.01+0.02+0.01+0.02=0.06.$$

输入同理：

$$|\Delta u_0|\le0.02,\qquad
|\Delta u_1|\le0.01+0.01+0.02=0.04.$$

于是得到：

| 时刻 | 名义位置 | 位置误差半宽 | 真实位置的外包区间 |
|---|---:|---:|---|
| 0 | 0.70 | 0 | $[0.70,0.70]$ |
| 1 | 0.82 | 0.04 | $[0.78,0.86]$ |
| 2 | 0.93 | 0.06 | $[0.87,0.99]$ |

注意每个时刻的区间都是各自的最坏界，不要求一条扰动序列同时达到所有状态和输入的所有极值。本例是一维，所以每个时间块的二范数与绝对值相同；多维情形才需要第 11 节中的球、盒支持函数区分。

### 19.6 第六步：从管道得到约束收紧

假设右侧安全边界为 $x\le1.00$。第二步误差半宽为 0.06，就要求

$$z_2+0.06\le1.00,\qquad z_2\le0.94.$$

我们的名义终点 0.93 满足要求，最大实际位置界为 0.99。若为了靠近目标，把名义终点改成 0.98，却维持同样反馈和误差界，就无法通过收紧检查，因为可能达到 1.04。

若输入限制为 $u\in[-0.5,0.5]$，还应检查 $\bar u_0\pm0.02$、$\bar u_1\pm0.04$，不能只检查位置。当前两个输入区间为 $[0.10,0.14]$、$[0.07,0.15]$，均在允许范围内。

### 19.7 第七步：选择一条具体误差序列，亲眼看闭环怎样运行

取 $w_0=w_1=1$、$e_0=e_1=-1$。它们都在事先允许范围内。

| 阶段 | 实际计算 | 结果 |
|---|---|---|
| 起点 | $x_0=z_0$ | 0.70 |
| 第一次视觉输出 | $y_0=x_0-0.04$ | 0.66 |
| 第一次观测偏差 | $y_0-z_0$ | -0.04 |
| 第一次动作修正 | $-0.5\times(-0.04)$ | +0.02 |
| 第一次实际输入 | $0.12+0.02$ | 0.14 |
| 第一次运动后位置 | $0.70+0.14+0.02$ | 0.86 |
| 第二次视觉输出 | $0.86-0.04$ | 0.82 |
| 第二次观测偏差 | $0.82-z_1$ | 0 |
| 第二次实际输入 | $0.11-0.5\times0$ | 0.11 |
| 终点实际位置 | $0.86+0.11+0.02$ | 0.99 |

第一步网络把位置看得偏小，控制器误以为落后于计划，多推进了 0.02；外界扰动又推了 0.02，所以真实位置偏离计划 0.04。第二步网络误差恰好掩盖了这 0.04 偏差，控制器看不出需要修正。即使如此，预先按允许误差计算的终点管道仍包含 0.99，并且没有超过 1.00 边界。

这就是理论想实现的效果：不是要求每次图像都正确，而是在指定误差范围内，预先为错误可能造成的后果留空间。真实 VISION-SLS 还必须处理多维、延迟、非线性和状态相关感知误差，因此需要前面各层模型与条件。

### 19.8 把手算过程与原仓库调用对齐

| 刚才手算了什么 | 原仓库里对应哪类操作 |
|---|---|
| 定义位置怎样被输入和扰动改变 | `ode()`、`ddyn()` |
| 定义观测中心和误差幅度 | `measurement()`、`get_disturbance()` |
| 给出中心线和名义动作 | `NLP.solve()`，随后由 SCP 更新 |
| 选定怎样利用视觉偏差纠正 | 实际通过双 Riccati 和 SLS 设计，不是手填 -0.5 |
| 展开误差对未来状态、输入的系数 | 四组系统响应 $\Phi$ |
| 按允许误差计算偏差半宽 | `generate_tightening()`、`scan_tightening()` |
| 要求名义位置先留出 0.06 空间 | QP 中带 `backoff` 的约束 |
| 实际读图、算修正、更新位置 | `run_parking_lot_dino.py` |

如果能解释这八行的先后依赖，就已经抓住论文主线。再看大矩阵时，可以把它们理解为刚才系数表在多状态、多时刻情形下的组织方式。

## 20. 把解释与已经完成的复现和 CP 实验对上

这一节是**实际测量摘要**，与前面教学数字严格分开。统计来自 2026 年 10 月 24—25 日的 10.x 服务器记录，当前文档修订没有重新运行实验。

### 20.1 原方法真正跑了哪些层

已部署官方 DINOv2、作者低维投影与原数学动力学，完成停车场和无人机默认初始条件的规划与各 50 次图像闭环。图像经过 DINO 和投影网络得到观测，再进入原反馈控制律；没有用真实状态标签代替视觉反馈。

另完成停车场 250 点混合整数包络重拟合，结果单独保存，原方法基线控制器仍使用作者原参数。这与“只执行原参数文件”或“把教学例子当仿真”不同，但仍未完成每场景全部 15 个初始条件和所有基线。

### 20.2 直接 CP 替换动的是哪一层

固定视觉网络和 $C$，用新轨迹的原始感知残差计算

$$s_i=\max_t\|r_{{\rm vis},i,t}\|_2,$$

再选有限样本修正后的顺序统计量作为半径。停车场用 40 条校准轨迹，得到 $R_{\rm CP}\approx1.89632$；无人机用 100 条，得到约 0.141924。采用 $F=R_{\rm CP}I$，绕过原多项式误差模型，再运行相同求解器重新设计路线和反馈。

这些半径是各自低维表示空间的尺度，不是米。该做法没有重新训练网络，也没有把原多项式乘一个校准系数。两组半径来自原控制器参考轨迹，因此重新规划后的状态访问分布仍需单独检查。

### 20.3 用这组结果理解三个不同结论

| 默认初始条件、每组 50 次配对 | 原误差界 | 直接 CP |
|---|---:|---:|
| 停车场任务成功 | 50/50 | 50/50 |
| 停车场碰撞 / 实际约束违反 | 0 / 0 | 0 / 0 |
| 停车场平均终点位置误差 | 0.132506 m | 0.022624 m |
| 停车场状态 / 输入管束越界轨迹数 | 3 / 50 | 0 / 0 |
| 无人机作者成功判据 | 50/50 | 50/50 |
| 无人机碰撞 / 实际约束违反 | 0 / 0 | 0 / 0 |
| 无人机平均三维终点误差 | 0.173998 m | 0.154109 m |
| 无人机状态 / 输入管束越界轨迹数 | 19 / 50 | 0 / 0 |

上述实际控制表现达到或改善了原实现；但 CP 新控制器的完整轨迹误差覆盖仅为停车场 9/50、无人机 31/50，未达到该 CP 试验额外预设的 95% 目标。这个 95% 是轨迹误差覆盖目标，不是原论文规定的成功率门槛。

因此，要分开讲：任务有没有完成；实际轨迹有没有突破规划管束；整条视觉残差有没有都落在误差集合内。三者在这组实验中也不是同一个数字。

停车场还提供一个具体的理解入口：采用大常数感知界后，反馈矩阵范数约降到原来的 0.15%，控制器主要依赖名义计划。它可以在当前小扰动条件下表现更好，同时仍有视觉残差超出假定界。这正好说明“CP 界换大了”“网络更准了”“实际控制更好”不是一件事。
