# SafePVC 改进实验通俗进展

> 更新日期：2026-09-18
>
> 面向第一次接触强化学习、形式验证和安全证书的读者。所有术语都尽量用自动刹车的例子解释。

## 1. 这个实验到底在做什么

可以把整个项目想成一辆正在接近障碍物的车：

1. 摄像头看到前方画面。
2. 程序从图像中估计障碍物距离。
3. 控制器根据距离和车速决定刹车力度。
4. 车辆根据刹车动作进入下一状态。
5. 我们检查：即使摄像头把距离看错一些，车辆是否仍能安全减速。

最简单的例子：

~~~text
真实距离：10.0m
程序估计：10.3m
允许的感知范围：9.6m到10.4m
当前速度：2.5m/s
~~~

如果控制器只相信10.3m这一个数字，它可能认为空间还很充足，从而刹车过晚。最终需要检查的是：

> 对9.6m到10.4m之间的每一个可能感知值，控制器的刹车都不能小于保持下一状态安全所需的最低刹车。

## 2. 目前取得了什么结果

- 图像距离估计MAE为0.1004m。
- 状态相关感知误差区间在测试集上的coverage为97.5%。
- 最终standalone PPO在4种感知测试中均为100% success、0% unsafe、0% timeout。
- 连续域验证处理3624个cell，其中2002个可恢复cell全部证成，0个未决cell。
- 状态矩形域中85.53%是可恢复且已证区域，14.47%是物理不可恢复区域。
- 有限状态SBC返回“verified”，在给定条件下beta为0。

不能将这些结果误解为：

- 真实世界事故概率等于0。
- 97.5%单帧coverage等于97.5%整轨迹安全率。
- 85.53%是安全率。它是状态区域的面积比例。
- 真实车辆的动力学误差永远为0。当前只是现有模拟器数据没有提供额外残差。

## 3. 四种感知测试模式

假设真实距离为10m，契约允许误差为±0.4m。控制器可能看到9.6m到10.4m之间的值。

| 模式 | 代码实际做什么 | 白话理解 | 检查目的 |
|---|---|---|---|
| exact | 输入真实距离10m | 摄像头完全没看错 | 理想感知时能否完成任务 |
| uniform | 每一步从9.6m到10.4m均匀随机取值 | 区间内各种大小的误差都有可能出现 | 普通随机感知误差下是否稳定 |
| random-boundary | 每一步在9.6m和10.4m两个端点中随机选择 | 每次都错到允许边界，但偏大或偏小随机 | 频繁大误差下是否稳定 |
| worst-endpoint | 同时计算两个端点的动作，选择刹车更小的动作 | 每一步故意选择对安全更不利的契约端点 | 检查契约端点中的局部最坏情况 |

worst-endpoint不是现实世界所有可能因素的绝对最坏情况。它只在当前两个契约端点中选择让PPO刹车最小的那个。

## 4. 感知与误差术语

| 术语 | 通俗解释 | 本项目中的作用 |
|---|---|---|
| 真实状态 true state | 车辆实际的距离和速度 | 用s=(d,v)表示 |
| 观测 observation | 控制器实际看到的信息 | encoder估计的距离和当前速度 |
| 语义 semantic | 从图像中提取的、对控制有直接作用且人能理解的信息 | 本项目主要是障碍物距离 |
| 语义编码器 semantic encoder | 把图像变成距离数字的网络 | 为PPO提供距离输入 |
| 感知误差 | 估计距离减去真实距离 | 真实10m、估计10.3m时误差为+0.3m |
| 连续感知误差 | 误差不是只取几个点，而是区间内任意实数 | 验证时覆盖9.6m到10.4m内每一个值 |
| 训练集 train set | 用来调整网络参数的数据 | encoder从中学习图像与距离的关系 |
| 校准集 calibration set | 不参与训练，专门测量模型通常会错多少的数据 | 计算conformal误差半径 |
| 测试集 test set | 最后检查模型和契约的独立数据 | 不参与训练或校准 |
| conformal prediction | 根据校准误差为新样本生成预测区间的方法 | 将距离点估计变成误差区间 |
| 语义契约 semantic contract | 后续控制和验证承诺要覆盖的感知范围 | 不是法律合同，而是“必须考虑这些误差”的技术约定 |
| 契约半径 radius | 感知值可能向两边偏移多少 | 半径0.4m表示考虑±0.4m |
| 状态相关 state-conditional | 不同真实距离使用不同误差范围 | 近处与远处的识别难度可能不同 |
| 分箱 bin | 将距离范围分成几段 | 当前把5m到16m分成4段 |
| coverage | 测试样本中真实答案被预测区间覆盖的比例 | 当前97.5%是单帧测试覆盖率 |
| global contract | 所有状态使用同一误差规则 | 简单但可能忽略不同距离的差异 |
| Mondrian contract | 把样本分组后分别做conformal calibration | 当前实验的对照方法 |

## 5. 过程扰动和过程残差

感知误差和过程误差发生在不同位置：

~~~text
感知误差：
距离看错 -> PPO选择了不同刹车 -> 下一状态改变

过程误差：
PPO动作已经确定 -> 真实车辆运动与动力学公式预测不一致
~~~

| 术语 | 通俗解释 |
|---|---|
| 动力学 dynamics | 根据当前距离、速度和刹车计算下一状态的公式 |
| 过程扰动 process disturbance | 路面、制动性能或未建模阻力等额外变化 |
| 过程残差 process residual | 实际下一状态减去动力学公式预测的下一状态 |
| 零过程残差 | 当前模拟器数据没有显示动力学公式之外的转移差 |
| double counting | 同一误差被计算两次 |

早期代码曾把“看错距离后动作变化造成的状态差”又当成过程扰动。这等于把同一个感知误差计算两遍，会让验证过度保守。修正后，感知误差只在PPO输入端处理，过程残差只表示车辆运动模型本身的误差。

## 6. 控制器和训练术语

| 术语 | 通俗解释 | 本项目中的含义 |
|---|---|---|
| controller / policy | 根据当前输入决定动作的程序 | 输入距离和速度，输出刹车强度 |
| PPO | 通过环境奖励学习策略的一种强化学习算法 | 原控制器和最终student都使用PPO结构 |
| baseline | 用于比较的原始方法 | 改进前的原PPO |
| robust controller | 尝试在多种误差输入下都稳定的控制器 | mixture训练后反而变差，因此不采用 |
| safety filter | PPO刹车不足时，把动作提高到最低安全刹车的保护层 | 最终只作为离线教师 |
| anti-stall | 防止过度刹车让车辆长期停在目标区外 | 解决“没撞车但400步没完成”的问题 |
| teacher | 能提供希望动作的教师控制器 | anti-stall safety filter |
| student | 模仿teacher学习动作的策略 | 最终standalone PPO |
| distillation / 蒸馏 | 用teacher生成的标签训练student | 把filter的安全行为迁移进PPO |
| imitation loss | student动作与teacher动作的误差 | 越小表示模仿越接近 |
| retention | 修复新问题时保留原来已学会的行为 | 防止修好低速后忘掉高速边界 |

| checkpoint | 保存下来的网络参数文件 | result 14的zip是最终控制器 |
| epoch | 对训练数据完整学习一遍 | epoch更多不保证闭环一定更好 |

| counterexample replay | 把验证器找到的失败状态重新加入训练 | result 14联合回放高低速反例 |
| underbraking | 刹车小于安全所需的最低刹车 | 可能使下一状态离开可恢复集 |
| overbraking | 刹车过强 | 可能安全但停滞，最终timeout |

## 7. 用停车距离定义可恢复集

“可恢复”的意思是：

> 从当前距离和速度出发，如果立即使用允许的最大刹车，还来得及在进入危险前把速度降到安全阈值。

例子：

- 距离15m、速度2m/s，还有足够空间减速，属于可恢复状态。
- 距离6.1m、速度3m/s，即使立刻使用最大3m/s²刹车也可能来不及，属于物理不可恢复状态。

本项目使用离散停车距离，因为控制器每0.05s更新一次动作。连续公式假设动作能无限连续地变化，可能对离散控制系统过于乐观。

| 术语 | 通俗解释 |
|---|---|
| safety distance | 将距离6m设为危险边界 |
| target speed | 进入安全终止状态要求的低速阈值，当前为0.5m/s |
| stopping distance | 从当前速度降到目标速度所需的前进距离 |
| recoverable set R | 还有足够空间安全降速的所有状态 |
| unrecoverable set | 最大刹车也无法保证挽回的状态 |
| viability | 是否存在某种允许动作，让系统继续留在安全区域 |
| invariant set | 位于集合内并满足控制条件时，下一步仍在集合内或安全终止 |
| one-step closure | 当前在R内，一步后仍在R内或进入安全终止集T |
| initial set | 实验允许的起始状态范围 |
| goal set | 任务认为已成功到达的状态范围 |
| terminal set | 轨迹在此结束，不再检查下一步 |
| unsafe set | 定义为危险或碰撞的状态集合 |

14.47%的物理不可恢复区域不是验证器失败。这些状态在当前最大制动能力下本来就无法保证挽回。

## 8. split-IBP是什么

### 8.1 为什么采很多点仍然不够

若要检查9.6m到10.4m的所有输入，可以采9.6、9.7、9.8等很多点，但仍可能在9.731m处漏掉一个很窄的反例。

本项目实际遇到过这种情况：粗网格检查147,939个状态和感知组合时没有发现问题，局部加密后却找到了窄边界反例。

### 8.2 IBP的白话解释

IBP是Interval Bound Propagation，即“区间界传播”。

它不是只问几个采样点输出多少，而是计算：

> 对输入区间中的每一个实数，PPO可能输出的最小刹车是多少。

它将输入上下界逐层通过神经网络，得到最终动作的保守上下界。

### 8.3 为什么要split

一次处理很大的输入区间时，IBP给出的界可能太宽。split-IBP把大区间分成多个小区间分别计算。仍难以判断的状态cell还会继续被切小。

- semantic split=256：最终将连续感知区间细分为256段。
- state max depth=9：困难状态cell最多递归细分9层。
- sound：计算结果可能保守，但不会漏掉区间中的真实网络输出。

### 8.4 验证条件

对每个可恢复状态cell，比较：

~~~text
PPO在全部契约内感知值上的最小可能刹车
                         和
保持下一状态仍可恢复所需要的最低刹车
~~~

前者不小于后者时，整个cell通过。

| 术语 | 通俗解释 |
|---|---|
| grid | 把连续状态平面分成很多小格 |
| cell | 一个小状态矩形，不是一个单点 |
| sampled diagnostic | 在有限点上找问题；没找到也不等于连续证明 |
| dense sampling | 在关键局部采更多、更密的点 |
| formal verification | 用保守数学界覆盖指定连续集合 |
| certified cell | 已证明整个cell都满足要求 |
| unresolved cell | 当前数值界还无法判断，不一定真的不安全 |
| counterexample | 确实不满足要求的状态或感知输入 |
| action lower bound | PPO在整个输入区间内可能输出的最小刹车 |
| margin | 动作下界减去所需刹车；正数通过，负数失败 |
| local verification | 只验证一个关键局部范围 |
| full-domain verification | 验证完整指定运行域 |

## 9. SBC、barrier和LP

### 9.1 Barrier function

barrier function可以理解为一张“状态危险分数地图”：

- 初始安全区域的分数应该低。
- 危险区域的分数应该高。
- 系统每走一步，最坏情况下的分数不应向危险方向增加。

### 9.2 Neural SBC为什么失败

neural SBC用神经网络学习这张危险分数地图。它必须同时满足初始区低分、危险区高分、普通状态的一步下降，以及终止区和物理不可恢复边界的特殊规则。这些条件在边界附近容易冲突，因此增加epoch、增大loss权重和更换输出函数都没有得到完整证书。

### 9.3 最终有限状态SBC

最终将状态抽象为：

- R：可恢复状态。
- T：安全终止状态。
- U：危险或物理不可恢复状态。

result 16证明从R出发，下一步只会进入R或T。于是定义：

~~~text
B(R)=0
B(T)=0
B(U)=1
~~~

只要不会从R跳到U，barrier就不会从0变成1。

| 术语 | 通俗解释 |
|---|---|
| SBC | Stochastic Barrier Certificate，用barrier条件表达不确定系统安全性的证书 |
| neural SBC | 用神经网络表示并训练得到的barrier |
| decrease condition | 下一步barrier分数不高于当前分数 |
| epsilon | 强制每一步至少下降多少；epsilon=0表示只要求不增加 |
| violation | 某个状态不满足barrier条件 |
| LP | 线性规划，在一组线性不等式下寻找变量 |
| infeasible | 约束互相冲突，不存在同时满足的解 |
| supermartingale | 下一步期望值不高于当前值的过程 |
| beta | 从初始集到达U的证书上界；当前只在契约始终成立且过程残差为0的条件下 |
| constraint residual | LP解违反约束的数值误差；0表示没有检测到违反 |

## 11. 原方法五个问题的白话解释

### 11.1 感知链条过长

原思路类似“先根据状态生成模拟图像，再压缩或识别图像，最后控制”。每多经过一个学习模型就多一层误差。AEBS真正需要的是障碍物距离，因此新方法直接从真实图像估计距离。

### 11.2 感知误差和过程扰动混在一起

感知误差是“距离看错导致PPO动作变了”；过程扰动是“动作已经确定，但车辆真实运动和公式不同”。若把前者造成的状态变化再次当作后者，同一个误差会被惩罚两次。

### 11.3 训练与验证条件不一致

这像驾驶员只在摄像头完全准确时训练，考试时却要求他在距离误差最大时也安全。我们尝试把多种误差混入PPO训练，但性能反而下降，后来改用安全teacher生成明确动作标签。

### 11.4 自由neural SBC的约束互相冲突

可以把barrier想成地形图：初始区必须是低谷，危险区必须是高山，所有普通转移还要下山。但终止区不应继续强制下降，物理不可恢复区又不能假装可挽回。这些边界要求很难由一个任意神经函数同时满足。

### 11.5 仿真成功率不能代替连续证明

运行很多回合没撞车，只能说明被运行到的轨迹没出问题。状态和感知误差是连续实数，有无穷多种组合。项目中粗网格曾显示0个反例，局部加密后又找到反例，这说明“采样没发现”不等于“连续集合已证明”。

## 12. 实验是怎样一步步走到现在的

1. **简化感知：** semantic encoder的MAE为0.1004m，旧估计器MAE为2.8619m。
2. **建立契约：** 将距离分4段分别校准，test coverage为97.5%。
3. **尝试robust PPO：** uniform unsafe从1%升到21.5%，random-boundary从17%升到28%，路线不采用。
4. **拆分误差：** 修正感知误差和process residual的重复计算。
5. **尝试neural SBC：** 多种训练和区域修正均未获得完整证书，保留为负结果。
6. **建立安全teacher：** anti-stall filter使4种模式均达到100% success、0% unsafe、0% timeout。
7. **训练standalone PPO：** 第一版因低速过制动全部timeout，第二版四种模式全部成功。
8. **形式反例修复：** 粗网格通过后发现高速窄边界反例；联合回放高低速临界状态得到result 14。
9. **连续验证：** unresolved cells从703降到627、248、135，最终result 16降为0。
10. **有限状态SBC：** result 17得到B(R)=0、B(T)=0、B(U)=1、beta=0，LP残差为0。

## 13. 一句话说清当前证明了什么

> 对任意位于可恢复集内的初始状态，如果当前二维离散动力学正确、过程残差为0、每一步感知误差都位于已校准语义契约内，并且部署使用result 14 standalone PPO及相同动作裁剪，那么每一个非终止后继状态都会继续留在可恢复集内，或进入安全终止集，因此不会进入定义的unsafe set。

若要把它升级为整条任务轨迹的概率安全下界，还需要独立闭环轨迹数据上的trajectory-level calibration或有效的时间风险记账。
