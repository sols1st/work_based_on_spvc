# 把实验例子从 2 个扩到 4–5 个：低成本任务模板、三个候选与对比协议

更新：2026-11-05。**文档性质：设计 + 本地原型证据，不是新增训练结果。**本文没有训练 PPO、没有拟合 CP、没有构造或验证 SBC。原型只回答“新例子能不能便宜地搭起来、视觉观测是否可解码、动力学是否良定”。

配套原型在 [`work/task_zoo_prototype_20261105/`](../../work/task_zoo_prototype_20261105/README.md)，可复现命令见附录。研究和理论定位见[SPVC 改进路线](./SPVC改进路线_理论定位与实验设计_20261105.md)。

## 0. 先给结论

**现在缺的不是训练预算，而是“一个例子从想法到可验证”的工程模板。**AEBS 和停车场各是一条定制链路：动力学、渲染、标签、误差协议、观测器、验证对象都不同。每加一个场景都要重做一遍，所以只有两个。

建议新增 **3 个 L2 例子**，按成本排序：

| 顺序 | 例子 | 新在哪里 | 估算 | 主要回答 |
|---|---|---|---|---|
| A | 车道保持（2D） | 连续横向反馈、非制动动作、前视相机 | 1.5–2 周 | 换一个原论文同类任务，方法是否仍成立 |
| B | ACC 跟驰（3D） | 动态前车、相对速度、感知与过程扰动分离 | 再加 1.5–2 周 | 误差包络是否真的连接到闭环安全 |
| C | 视觉 Cart-Pole（4D） | 非车辆、不稳定、不能靠停车保安全 | 再加 2–3 周 | 跨系统适用性，而不只是“另一个车辆任务” |

这三个共用一套渲染/任务模板；A 最先做，B 复用 A 的公路渲染器，C 需要新的侧视渲染器。单人串行约 5–7 周，B 的数据准备可与 A 的验证部分并行。**不建议**先上 CARLA 车道保持、X-Plane 或人形机器人：它们把成本压在环境/采集上，不能更快回答核心问题。

如果只能做一个：论文要“跨系统”就做 C；要“原方法第二个基准”就做 A。B 是在 A 之上边际成本最低的扩展，不是必须最先做。

**最小行动（不写新环境也能开始）：**先在现有 AEBS 和停车场上补齐第 6 节的 O/S/I 三组对比。这不需要新任务，却能立刻回答“感知代价有多大、语义路径是否值得做”，也为新例子提供同一套评价脚本。

## 2. “多一个例子”分三层，不要混着数

| 层次 | 含义 | 论文里算不算新例子 | 成本 | 用途 |
|---|---|---|---|---|
| L1 场景族 | 同一动力学/安全集，换初态、曲率、光照、遮挡、相机位姿 | 不算；算“条件”或“压力测试” | 半天–2 天 | 鲁棒性、CP 校准、统计 |
| L2 新任务 | 新动力学 + 新观测语义 + 新安全集 | 算 | 1–3 周 | 跨任务适用性 |
| L3 新基准/真实系统 | CARLA、X-Plane、硬件 | 算，但另立协议 | 1–3 月 | 现实相关性 |

建议：**2–3 个 L2 + 每个任务 10–30 个 L1 条件**。把 L1 条件写成“新增例子”会被审稿人一眼看穿；反过来，只有 L2 而没有 L1，统计证据又太薄。

### A. 车道保持：最便宜的第三个例子

| 项目 | 定义 |
|---|---|
| 状态 | `(e, θ)`：相对车道中心的横向偏差、相对道路切线的航向偏差 |
| 动作 | 前轮转角 `φ ∈ [-0.45, 0.45] rad`，或转角速率 |
| 动力学 | `e' = e + vΔt sinθ`，`θ' = θ + (vΔt/L)tanφ - vΔt·κ`；`v=8 m/s`，`L=2.6 m`，`Δt=0.1 s` |
| 语义观测 | 图像 → `(ê, θ̂)`；语义控制器输入就是这两个量 |
| 图像 | 前视相机，256×256；车道线、路缘、灯杆；曲率 `κ`、亮度、遮挡可调 |
| 安全集 | `|e| ≤ 0.85 m`（车宽 1.8 m、车道 3.5 m 时整车不出线），`|θ| ≤ 0.30 rad` |
| 初态 | `|e| ≤ 0.25 m`，`|θ| ≤ 0.06 rad`；时域 80 步（8 s） |
| 复用 | AEBS 的 2D VT/SBC 训练与验证代码（需适配接口）、CP 代码、`Aebs` 适配器字段 |
| 新造 | 透视渲染器 + DINO 投影头 + 数据采集 |
| 验证难度 | 低（2D、无观测器、无记忆） |
| 回答什么 | 原论文的跑道跟踪没有本地资源时，能否用同类任务检验“视觉误差 → 横向控制 → 证书” |
| 风险 | 与 AEBS 同属 2D 车辆；若审稿人认为“只是换动作”，跨任务价值有限 |
| 估算 | 环境+渲染 2 天，数据+投影 2 天，CP+SBC+验证 4–5 天 |

**为什么先做它：**2D 状态意味着现有的 `VTVerifier` 和 AEBS 的 SBC 训练代码基本能直接跑；它把“新例子”的成本压到主要是渲染和数据，而不是重写验证器。它也是原论文跑道任务的合理替代，但**不能说成严格复现 X-Plane 实验**。

### B. ACC 跟驰：感知误差与过程扰动的分离

| 项目 | 定义 |
|---|---|
| 状态 | `(d, v, v_lead)`：保险杠间距、自车速度、前车速度 |
| 动作 | 自车加速度 `a ∈ [-6, 3] m/s²` |
| 动力学 | `d' = d + (v_lead - v)Δt`，`v' = v + aΔt`；前车在 `t=2 s` 后以 `-3 m/s²` 制动 |
| 语义观测 | 图像 → `d̂`（前车距离）；`v` 实测；`v_lead` 需要观测器或两帧差分。**注意：这一版的图像观测仍是一维，不回应“输入维数更多”；要回应需改成二维观测（距离+横向偏移，或两帧距离+相对速度）** |
| 图像 | **复用 A 的公路渲染器**，只加一辆前车；间距 6–25 m 的尺度变化明显。若目标是维数，需同时渲染前车横向位置或输出两帧 |
| 安全集 | `d ≥ 3 m`（碰撞）/ 更严格可用 `d ≥ 5 m`；`0 ≤ v, v_lead ≤ 30` |
| 初态 | `d ∈ [14, 20] m`，`v ∈ [10, 12] m/s`，`v_lead = v` |
| 复用 | A 的渲染器；参考 AEBS 的纵向动力学与制动约束、停车场观测器结构 |
| 新造 | 3D SBC/验证（维数从 2 到 3）、前车剖面、部分可观测策略 |
| 验证难度 | 中–高：3D 网格 + 观测器记忆会显著放大验证对象 |
| 回答什么 | 同一视觉误差下，过程扰动/前车行为如何改变安全结论；语义 vs 图像控制器的性能差是否来自感知 |
| 风险 | 若把 `v_lead` 当实测，任务退化成“只有距离有误差”；若完全靠两帧估计，又引入记忆维 |
| 估算 | 环境+数据 2–3 天，3D SBC/验证 1–1.5 周 |

**诚实边界：**“ACC + 视觉”已经有大量 CBF/安全滤波器工作；本项目的贡献不能是“又一个 ACC 安全控制器”，而应是“同一误差协议下，语义观测与图像观测的可验证性差异”。

### C. 视觉 Cart-Pole：真正的跨系统例子

| 项目 | 定义 |
|---|---|
| 状态 | `(x, ẋ, θ, θ̇)`；小车位置/速度、摆角/角速度 |
| 动作 | 水平力 `F ∈ [-10, 10] N` |
| 动力学 | 标准 cart-pole；`Δt=0.02 s`，250 步（5 s） |
| 语义观测 | 图像 → `(x̂, θ̂)`；速度实测或由观测器估计 |
| 图像 | 侧视 256×256：轨道、小车、摆杆；背景纹理、遮挡、相机偏移可调 |
| 安全集 | `|x| ≤ 2.0 m`，`|θ| ≤ 0.30 rad`；初态 `|x|≤0.2`，`|θ|≤0.05` |
| 复用 | 通用 SBC 训练代码；停车场观测器；CP 代码 |
| 新造 | 4D SBC、4D 区间验证、更难的策略学习、速度估计 |
| 验证难度 | 高：4D 状态 + 不稳定动力学；但观测只有 2D |
| 回答什么 | 方法是否只对“车辆 + 停车即安全”成立；持续反馈、不能靠不动保安全时还能不能合成证书 |
| 风险 | 图像任务可能被简单几何检测解决，DINO 未必必要；4D 验证可能大量 unknown |
| 估算 | 环境+渲染 2 天，数据+投影 3 天，SBC/验证 1.5–2 周 |

**为什么不是高度控制：**视觉高度保持也是 2D 非车辆任务，更便宜，但它和 AEBS 一样“输入少、停下就安全”，对“跨系统”的说服力弱。可以把高度作为 C 失败时的降级方案，而不是主推。

### 其他候选怎么排

| 候选 | 判断 |
|---|---|
| 停车场多地图/多障碍（L1） | 便宜，适合做场景族和鲁棒性；不算新任务 |
| Light-Dark 图像版 | 机制清楚，但“光照→误差”容易做成对方法有利的合成实验；适合做消融，不适合当主例子 |
| 移动障碍避让 | 需要时变安全集/额外障碍状态，验证难度跳档；排在 C 之后 |
| X-Plane 跑道 | 本地只有 taxi 模型，没有完整数据/运行链；先审计资源再决定 |
| 十维无人机/人形 | 验证维度过高，容易得到“只有轨迹成功、没有证书”；不作为第一批 |

## 4. 五个例子放在一起，覆盖了什么

| 例子 | 状态维 | 观测 | 环境 | 车辆 | 反馈 | 部分可观测 | 主要主张 |
|---|---|---|---|---|---|---|---|
| AEBS（已有） | 2 | 1D 距离 | 静态 | 是 | 单次制动 | 否 | 已有基线 |
| 车道保持（A） | 2 | 2D `(e,θ)` | 静态 | 是 | 连续横向 | 否 | 第二个基准 |
| ACC（B） | 3 | 1D 距离 + 速度 | 动态 | 是 | 连续纵向 | 是（`v_lead`） | 误差→闭环 |
| 停车场（已有） | 4+ | 3D 位姿 | 静态 | 是 | 参考+残差 | 是（延迟） | 多维/障碍 |
| Cart-Pole（C） | 4 | 2D `(x,θ)` | 静态 | 否 | 不稳定连续 | 是（速度） | 跨系统 |

这张表比“再加三个车辆场景”有用：它同时覆盖 2/3/4 维、静态/动态、车辆/非车辆、完全/部分可观测、停车即安全/必须持续作用。**做完 A+B+C 后，不建议再扩任务；边际收益低于把消融和统计做扎实。**

## 5. 怎么便宜地造：一个任务只填四个函数 + 一组边界

现有 `Aebs` 适配器已经包含新任务需要的全部字段：

```python
class Task:
    state_low, state_high          # 验证域
    initial_low, initial_high      # 初态集合
    action_low, action_high
    space_split, train_space_split # 网格
    unsafe_spaces                  # 不安全集
    noise_bounds                   # 观测/过程扰动盒
    def step(state, action, w)     # 动力学
    def unsafe(state)              # 安全判定
    def render(state) -> image     # 图像
    def label(state) -> y          # 语义标签（CP/投影用）
```

原型就是按这个接口写的：`zoo/tasks.py` 里三个任务、`zoo/scenes.py` 里两个渲染器、`zoo/camera.py` 是 200 行的针孔相机 + 画家算法。没有 PyBullet、没有 CARLA、没有新依赖，只用 numpy + Pillow。

### 5.1 一个例子的八步流水线

| 步 | 工作 | 复用 | 估算 |
|---|---|---|---|
| 1 | 写 `step/unsafe/label`，脚本控制器先跑通 | 数学定义 | 0.5 天 |
| 2 | 写渲染器（先顶视/前视简图，再加纹理） | 原型相机 | 1–2 天 |
| 3 | 状态网格 + 随机采样出图 | numpy | 0.5 天 |
| 4 | DINO 特征 + 线性/MLP 投影头 | `Aebs.dino_latent`、VISION-SLS `perception_utils` | 1–2 天 |
| 5 | 拟合误差包络 + split CP | AEBS/停车场 CP 代码 | 1–2 天 |
| 6 | PPO/语义策略训练 | AEBS PPO、停车场 PPO | 2–4 天 |
| 7 | SBC 训练 + 连续域验证 | 2D 适配后复用；3D/4D 需扩展或重写验证器 | 3–10 天 |
| 8 | 图像闭环测试 + 对比表 | 现有评估脚本 | 2–3 天 |

### 5.2 原型已经验证的部分

**(a) 动力学良定，脚本控制器能闭环**（20 个随机初态，不是学习策略）：

| 任务 | 成功 | 最差安全裕量 |
|---|---|---|
| 车道保持（直道） | 20/20 | 0.134 |
| 车道保持（曲率 0.01） | 20/20 | 0.135 |
| ACC（前车 2 s 后急刹） | 20/20 | 3.56 m（`d - 3`） |
| Cart-Pole | 20/20 | 0.248 |

**(b) DINO 特征确实能读出语义状态**（600 张随机 `(e,θ,κ)` 图，480 训练/120 测试，384 维 CLS）：

| 方法 | `e` MAE | `θ` MAE | `R²(e)` | `R²(θ)` |
|---|---|---|---|---|
| 均值基线 | 0.445 m | 0.152 rad | — | — |
| DINO + 岭回归 | 0.119 m | 0.028 rad | 0.918 | 0.960 |
| DINO + 小 MLP | 0.096 m | 0.039 rad | — | — |

![DINO 探针对比](../../work/task_zoo_prototype_20261105/preview/dino_probe.png)

**这不是“已经够用”，而是“值得继续”。**0.10 m 左右的横向误差相对 0.85 m 的安全边界不算小；但注意两点：

1. 误差随位置变化：中心附近 MAE 0.073 m，两侧 0.126–0.140 m。这正是状态相关 CP 应该捕捉的结构，而不是一个全局常数。
2. 这是**线性头 + 卡通渲染**的结果；加纹理、加数据、换 MLP/Transformer 头还有空间。反过来说，如果加完纹理仍大于任务容差 2 倍，就应该换渲染器（PyBullet/真实图），而不是硬训 SBC。

**(c) 渲染器本身不是瓶颈。**原型一天内完成三个场景；真正的成本在数据协议、CP 和验证，和现有文档的判断一致。

## 6. 语义控制器 vs 图像控制器：把比较做成三组，而不是两组

`比较.md` 里提到“语义控制器比较图像控制器”。建议明确区分三组，否则“语义”会被混成“用了 DINO 的隐变量”：

| 组 | 输入 | 作用 | 能否验证 |
|---|---|---|---|
| **O（Oracle）** | 真实低维状态 `(e,θ)` / `(d,v,v_lead)` / `(x,θ)` | 性能上界，不是部署方案 | 可以（无感知误差） |
| **S（Semantic）** | 图像 → 语义估计 `(ê,θ̂)` → 策略 | 主方法：观测可解释、误差可校准 | 可以（带 CP 包络） |
| **I（Image end-to-end）** | 图像 → 动作（CNN/PPO 直接输出） | 性能参照，通常分布内更强 | 通常不可验证 |

比较协议：

1. **同一批初态、同一时域、同一动作限幅、同一训练预算**；三种输入用相同随机种子配对。
2. 每组至少 3 个训练种子；报告均值与 95% 区间，不只报最好一次。
3. 指标分三层：
   - 任务：成功率、到达时间、平均速度/间距误差、动作平滑度；
   - 安全：越界率、最小安全裕量、最差情景；
   - 可验证性：CP 包络宽度、验证耗时、unknown 区间比例、可证域占声明域比例。
4. **O 是上界，不是竞争对手。**`S` 与 `O` 的差距是感知代价；`I` 比 `S` 好只说明“端到端拟合强”，不说明它更安全。
5. 若 `S` 接近 `O` 但 CP 很宽，问题在验证/误差建模；若 `S` 明显差于 `O`，问题在表示/数据；若 `I` 最好但无法验证，正好说明本项目的动机。

统计上不要写“语义 95% × 图像 95% = 联合 95%”；配对实验只报告配对差值的区间。CP 的覆盖是新样本边缘覆盖，不是每个初态都 95%，这一点在现有文档里已经反复强调，新例子沿用同一口径。

## 7. 场景族：把 3 个任务变成 30+ 个条件

每个 L2 任务配一组可复现的 L1 旋钮，按“场景 ID”分组划分训练/校准/测试，禁止按帧随机划分：

| 任务 | 旋钮 | 建议档位 | 用途 |
|---|---|---|---|
| 车道保持 | 曲率 `κ` | `{-0.01, 0, 0.01, 0.02}` | 前馈误差、CP 状态相关 |
| | 亮度/阴影 | 3 档 | 图像压力测试 |
| | 遮挡（路缘/车辆） | 0/1/2 个 | 感知失效定位 |
| | 相机横向/高度偏移 | 3 档 | 标定误差 |
| ACC | 前车减速度 | `{-2, -3, -5} m/s²` | 动态难度 |
| | 初始间距 | `{6, 10, 15, 20} m` | 安全边界 |
| | 切入/切出 | 有/无 | 部分可观测 |
| | 感知延迟 | 0/1/2 帧 | 观测器 |
| Cart-Pole | 初始摆角 | `{0, ±0.05, ±0.1}` | 恢复能力 |
| | 杆长/质量 | 3 档 | 模型误差 |
| | 力限幅 | `{10, 15} N` | 可行性边界 |
| | 相机偏移/遮挡 | 3 档 | 视觉鲁棒性 |

报告时写“**N 个条件、M 个独立场景组**”，不要写“N 个新任务”。条件数不是越多越好：每个条件都要有对应的训练/校准/测试划分，否则只是重复采样。

## 8. 推荐顺序与 go/no-go

| 阶段 | 工作 | 产物 | 通过条件 | 不通过怎么办 |
|---|---|---|---|---|
| 第 0 周（可并行） | 在现有 AEBS/停车场上补 O/S/I 三组对比 | 现有任务上的感知代价表 | 同初态、同预算、配对区间 | 先修评价协议，不急着开新任务 |
| 第 1 周 | A：渲染器 + 数据 + DINO 头 + CP | A 的误差包络与探针报告 | 探针误差 ≤ 任务容差；脚本闭环 100% | 加纹理/换 PyBullet；仍不行则换任务 |
| 第 2 周 | A：2D SBC + 连续域验证 | A 的通过/反例/unknown 分类 | 有明确分类，不以“没找到反例”当通过 | 缩域或改证书表达，不调容忍阈值 |
| 第 2–4 周 | B：ACC 数据 + 3D SBC（可与 A 的验证并行） | B 的 3D 验证报告 | unknown 比例可接受、有可行反例 | 退回 2D 距离保持，或先只做 O/S 行为对比 |
| 第 4–7 周 | C：Cart-Pole（或高度降级） | C 的 4D 验证报告 | 能给出通过/失败类型 | 作为“失败也是结果”报告，不硬凑证书 |
| 持续 | L1 场景族 + 多种子 | 条件表、压力测试 | 结论不只在单一条件成立 | 缩小声明范围 |

**明确的“先不要做”清单：**

- 不要在 A 的 DINO 误差还大于 2 倍任务容差时开始训 SBC；
- 不要把 3D/4D 验证的 unknown 当成通过；
- 不要为了“例子数量”把同一任务的 15 个初态说成 15 个例子；
- 不要在 B/C 还没有失败分类时启动 CARLA/X-Plane/人形。

## 9. 主要风险与反面情形

| 风险 | 具体表现 | 缓解 |
|---|---|---|
| 合成图像太干净 | DINO 误差小但 CP 包络也小，一换纹理就失效 | 训练时就混入纹理/亮度/遮挡；测试集按场景组留出 |
| 合成图像太卡通 | 探针误差 0.12 m，CP 太宽，任务变简单或不可证 | 先做 1 天探针；不达标换 PyBullet/真实图，不硬训 |
| 视觉捷径 | 灯杆位置/背景纹理泄露状态 | 随机化灯杆、背景、相机位姿；做遮挡消融 |
| 3D/4D 验证爆炸 | 网格 × 观测器记忆，unknown 占主导 | 先固定策略只验 SBC；用可达域限制；必要时降维 |
| 任务不可行 | 误差界内没有安全动作序列 | 先做“短期安全动作存在性”检查，再谈证书 |
| 把 L1 当 L2 | 审稿人认为只是换场景 | 明确任务/条件两级表 |
| DINO 不必要 | Cart-Pole 用几何检测就够 | 这本身是可报告结果；比较 DINO vs 小 CNN vs 几何基线 |
| 计算成本 | 每个任务 3 种子 × 多种子 SBC | 先 1 个种子打通，再补种子；记录总 GPU 时 |
