我按你正在改进的**原SPVC论文，以及当前项目衍生的几个PPO版本**来讲。

先抓住最重要的一点：

**PPO是一种训练控制器的方法，不是控制器前面或后面额外接的模块。训练结束后，真正根据输入给动作的是一个神经网络。原SPVC后续还会修改这个网络，但那一步已经不完全是PPO训练了。**

## 一、原论文中，PPO负责哪一部分

原论文整体分成两个阶段：

```
第一阶段：先学会完成控制任务

感知信息 → PPO控制器 → 动作 → 环境运动 → 奖励
               ↑                         │
               └──── 根据经历更新 ────────┘


第二阶段：再按照安全条件修正

已有控制器 → 学习SBC → 检查安全条件
               ↑             │
               └── 反例推动控制器和SBC交替调整
```

因此，不是从头到尾都拿SBC作为奖励运行PPO。

原论文第3.1节介绍PPO预训练；第3.2节介绍SBC指导的控制器调整。Algorithm 1也把二者明确分开：先得到初始策略，再交替调整屏障和策略。

## 二、原SPVC的PPO输入输出是什么

### 1. 论文描述的输入是感知得到的状态信息

对于车辆紧急制动任务，可以理解为：

```
前方图像
    ↓
感知网络估计距离
    ↓
估计距离 + 当前速度
    ↓
PPO控制器
    ↓
一个制动或加速动作
```

控制器不需要直接处理整张图像的所有像素，而是处理感知模块给出的低维信息。

这里需要补充一个很重要的实现区别：

**论文文字说用感知状态估计进行预训练；但当前仓库保留的 `Controller_train.py`，实际直接连接物理状态环境训练，没有在这个训练入口中运行cGAN和图像距离网络。**

该入口的训练输入实际是：

```
[归一化真实距离, 当前真实速度]
```

训练结束后，才将学到的动作网络与图像感知网络连接起来。

因此，应当区分：

- **论文方法描述**：控制器根据感知状态估计决策。
- **当前代码中的初始训练入口**：先在物理状态上学习，再接入感知链。

不能说原代码的初始PPO每一步都在看生成图片。

### 2. 输出是什么

输出是一个连续动作：

```
a ∈ [-3, 3]
```

在当前车辆模型中：

- `a > 0`：制动，速度下降。
- `a < 0`：加速，速度上升。
- 输出超过允许范围时，裁剪到边界。

车辆运动按以下规则计算：

\[ d_{t+1}=d_t-0.05v_t \]\[ v_{t+1}=\operatorname{clip}(v_t-0.05a_t,0,3) \]

例如，当前速度为2米/秒，执行制动动作1：

```
下一速度 = 2 − 0.05 × 1 = 1.95米/秒
```

PPO决定的是动作，不是直接决定下一距离和速度；下一状态由车辆运动规则计算。

## 三、PPO究竟怎样训练

下面这一过程，是不同PPO版本共有的基本训练方式。

### 第一步：随机设置车辆起点

当前初始PPO训练环境随机设置：

```
距离：5～16米
速度：0～3米/秒
```

注意，训练起点范围比较大；后面常用的任务评价起点则是：

```
距离：15～16米
速度：2.5～3米/秒
```

两者不是同一个范围。

### 第二步：构造控制器观测

对于原来的两维控制器：

```
观测 = [距离, 速度]
```

对于现在的latent控制器：

```
观测 = [32维latent, 速度]
```

环境知道的真实物理状态，与控制器实际看到的观测，不一定相同。

例如，图像训练回合中：

- 环境知道真实距离，用于计算运动和奖励。
- 控制器只看到图像latent和速度。
- 不会额外把真实距离直接塞给这个33维控制器。

### 第三步：随机尝试一个动作

训练时，PPO不是永远输出固定动作。

它会学习一个动作分布，可以简单理解为：

> 当前比较倾向于制动1，但训练时也尝试附近的其他动作。

动作网络给出均值，另有探索参数决定随机尝试的幅度。

因此，同一个观测在训练时可能产生不同动作。这样才能积累“多刹一点和少刹一点有什么后果”的经历。

评价时常采用确定性动作，即使用动作均值，不再额外随机探索。

### 第四步：执行动作，计算下一状态和奖励

当前项目的奖励实现主要为：

|情况|奖励或惩罚|目的|
|---|---|---|
|向目标靠近|距离减少量乘2|鼓励接近目标|
|每经过一步|扣0.001|避免无限拖延|
|在目标区域达到低速要求|加2并结束|鼓励正确完成任务|
|进入危险区域且速度过高|根据超速程度扣分并结束|惩罚危险行为|

这是**当前项目代码的奖励设置**，不是说论文正文逐项给出了相同公式。

PPO没有拿到“此时正确动作必须是1.2”的标签，而是通过执行动作以后的成绩学习。

### 第五步：收集一批经历

当前初始PPO每收集2048步后，进行一次批次训练。

记录包括：

```
当时看到什么
采取了什么动作
动作在旧策略下的概率密度
得到了多少奖励
回合是否结束
预计后续还能得到多少奖励
```

这些不是2048个独立回合，可能包含多个完整回合和部分回合。

### 第六步：判断动作表现比预期好还是差

PPO内部有两个主要部分：

|部分|做什么|
|---|---|
|动作网络 actor|根据观测给出动作分布|
|奖励价值网络 critic|估计从当前观测继续执行，大约能得到多少后续奖励|

如果实际后续成绩比critic预计的好，说明这次动作值得增加选择倾向；反之则倾向于减少。

这个“比预期好多少”，称为**优势估计**。

特别注意：

**critic估计的是奖励，不是碰撞概率，也不是SBC。**

### 第七步：小幅更新，而不是一下完全改变策略

PPO比较新旧策略对已采取动作的概率密度：

\[ r_t=\frac{\pi_{\text{新}}(a_t\mid o_t)} {\pi_{\text{旧}}(a_t\mid o_t)} \]

这个比例用于衡量：

> 更新之后，这个动作比以前更容易还是更不容易被选到？

PPO采用裁剪目标，限制单批数据推动策略变化的幅度，避免因为少量经历就把策略改得过大。它是稳定训练的机制，不是物理安全约束。

然后继续：

```
新策略采样 → 收集经历 → 更新策略 → 再采样
```

原论文采用的就是这类PPO预训练思想。

## 四、当前最初PPO用了什么配置

原论文明确给出学习率0.0003、batch size 64、训练20万步。

当前项目初始PPO的配置更完整：

|配置|数值|含义|
|---|---|---|
|学习率|0.0003|每次参数调整幅度|
|每批采样|2048步|收集多少交互后更新|
|更新小批|64条|每次优化使用多少记录|
|每批更新轮数|10|同一批记录重复优化10轮|
|奖励折扣|0.99|未来奖励逐渐折扣|
|GAE参数|0.95|优势估计的平滑设置|
|探索奖励系数|0.01|鼓励保留一定随机探索|
|请求训练量|200000步|环境交互次数|
|实际训练量|200704步|最后一批2048步收完整|

这里“20万步”不是20万张图片，也不是20万个回合。

## 五、换成latent后，几个PPO版本分别怎么做

这些版本大多使用相同PPO算法，**主要区别在控制器训练时看到什么输入**。

### 版本一：只用代理latent训练

```
真实距离 → q → 32维代理latent
                      +
                    速度
                      ↓
                     PPO
```

训练时完全不看图像latent。

优点是输入稳定、计算简单。问题是控制器只熟悉q产生的表示，真正换成图像表示时，哪怕差异不大，也可能不适应。

早期400图实验中：

- 代理路径评价：100%成功。
- 图像路径评价：仅9.5%成功，90.5%提前停在目标外。

说明**代理上学会了，不代表图像上也学会了**。

### 版本二：只用图像latent训练

```
训练图片 → DINO → 投影 → 32维图像latent
                                  +
                                速度
                                  ↓
                                 PPO
```

训练回合根据当前距离，在图片库里选对应的最近图片。

这次控制器熟悉的是图像表示，但不一定适应q表示。

早期对照中：

- 图像路径评价：100%成功。
- 代理路径评价：100%不安全。

两种输入都叫32维latent，不代表它们在控制器看来完全等价。

### 版本三：混合图像和代理训练

每个回合开始时选择：

```
约50%概率：整个回合用q代理latent
约50%概率：整个回合用图像latent
```

不是把两种latent相加，也不是训练两个独立控制器。

图像回合还会随机选天气和颜色，并在整个回合保持这个外观。

这样，同一个PPO既见过代理输入，也见过图像输入。

早期有限图片库对照中，两条路径均达到100%成功。这是后来继续采用混合训练的重要原因，但当时还不能说明新图片上的泛化已经解决。

### 版本四：扩充数据后的R1混合PPO

R1使用扩充后的多外观表示，仍按50%图像、50%代理训练，重新训练约20万步。

评价12种外观，每种400个起点：

```
4800个图像回合中，10次不安全。
```

主要失败出现在阴天部分外观。进一步分析发现既有表示差异，也有图片最近邻查找造成的位置错配，不能简单归因于“阴天不好识别”。

### 版本五：R1加经验残差扰动的PPO

这是一个额外尝试，输入比例改为：

```
50%：图像latent
25%：原始q latent
25%：q latent + 从训练数据提取的表示误差
```

“经验残差”就是：

```
同一图片的图像latent − 对应距离的q latent
```

目的类似给代理输入加入训练中观察到的感知差异，让控制器适应不那么理想的代理。

但我们对大残差做了训练集P95裁剪，所以它不是覆盖全部误差的安全契约。

部分尾部指标改善，例如训练精确单步检查中“图像独有下一步危险”由3个降至1个；并不是所有指标都改善，也没有因此得到保证。

### 版本六：R2表示下重新训练的混合PPO

R2先加强同距离不同外观的表示对齐，然后**重新训练一个PPO**，而不是直接沿用R1控制器。

依旧：

```
50%代理回合 + 50%图像回合
约20万步
```

这一版第09步完整PPO的结果是：

|评价条件|回合数|成功|
|---|---|---|
|q代理路径|400|400|
|12种图像外观|4800|4800|

合计5200回合全部成功。

但要准确理解：

- 是同一组400个起点在不同输入条件下重复评价。
- 图像闭环使用训练图片库回放。
- 不代表5200个独立新场景。
- 不代表未触碰测试集已经成功。

这些版本的记录及适用范围，整理在完整实验报告中。

当前混合PPO的训练入口也明确规定了“按回合50%代理、50%训练图像”以及表示冻结。

## 六、接入原SPVC以后，还在训练PPO吗

**严格说，原SPVC后续更新的是PPO训练出来的动作网络，不是在继续运行完整PPO算法。**

它从完整PPO中取出：

```
输入处理后的动作网络 + 动作输出层
```

不把奖励价值网络和随机探索机制一起用于原SBC更新。

在latent版本中，分析路径是：

```
物理距离 → q latent + 速度 → 动作网络 → 动力学 → SBC值
```

调整动作网络时，原论文的目标主要包含三部分：

1. 动作造成的下一状态，尽量满足SBC的期望下降条件。
2. 控制器不要对输入变化过于敏感。
3. 不要过度偏离原先PPO学到的动作。

第三项确实使用参考：

> 以最初预训练策略的动作作为参考，惩罚偏离过大。

所以你前面问“是不是不用参考”，准确答案是：

- **初始PPO**：不用专家正确动作标签。
- **原SPVC后续调整**：会参考初始PPO动作。

这一阶段可以通过“动作→动力学→下一状态→屏障”的计算链调整动作网络。它和根据奖励、动作概率比更新的PPO，不是同一个优化过程。

因此还必须区分：

- 第09步完整PPO：5200回合评价成功。
- 原SPVC更新后的最终控制器：另做108回合评价成功。

不能直接把前一个模型的5200回合成绩算给后一个模型。

## 七、最近“PPO加NBC”的版本又有什么不同

这个分支重新使用完整PPO采样和更新，但增加一个安全训练信号。

```
图像latent + 速度
        ↓
PPO随机动作
        ↓
环境得到下一状态
        ├→ 任务奖励：是否有利于完成任务
        └→ NBC违规分数：是否满足屏障转移条件
                    ↓
           一起影响PPO的更新
```

它与原SPVC后处理有两点区别：

- 使用当前策略真正采到的连续回合。
- 安全反馈通过动作概率比影响策略，不要求对车辆动力学直接求导。

又分成三个候选：

|候选|主要变化|
|---|---|
|单步NBC反馈|看当前到下一步的条件违反|
|单步反馈加保留机制|更新NBC时回放旧数据，退回损害旧约束的候选|
|五步反馈加保留机制|看短期最多五步，尝试提前发现风险|

还有一个**普通PPO对照**：同样继续训练，但关闭安全反馈。

它们仍是33维输入、一个连续动作输出；变化主要在训练目标，不是又换了一套感知前端。

当前这些短实验每组8192步，学习率0.00001。结果没有显示安全优势：确定性108回合都成功，但固定屏障下的验证动态违反没有降低，五步候选也没有优于普通PPO，因此没有替换保留模型。

## 八、最后把所有版本串起来

你可以这样理解当前主要发展过程：

```
原两维PPO
输入距离、速度，先学控制
        ↓
改成33维latent输入
        ↓
只训练代理：不适应图像
只训练图像：不适应代理
        ↓
图像与代理混合训练
        ↓
扩充数据，改进表示：R1 → R2
        ↓
R2重新训练完整PPO：有限回放表现好
        ↓
原SPVC用SBC调整动作网络
        ↓
保留最终控制器与SBC
        │
        └→ 另开研究分支：完整PPO加NBC安全反馈
                         目前尚无安全改善
```

**因此，目前最明确的成果是：新的latent输入已经能训练出完成当前任务的PPO；尚未完成的是，证明它在真实图像误差影响下仍满足所要求的安全条件。PPO表现好、SBC检查通过、真实图像闭环有保证，是三个不同层面的结论。**
