# VISION-SLS停车场三维视觉前端与SPVC后端实验报告

数据截至2026年10月25日。本文单独介绍近期与VISION-SLS有关的工作，重点是停车场的三维视觉前端、PPO控制及原SPVC后端接入。此前在AEBS上借鉴误差包络的尝试另作说明，不与停车场结果混用。

阅读顺序：第1节先看结论；第2至5节理解框架和输入；第6至10节看实验及失败原因；第11节单列早期包络尝试；第12节看当前结论和计划；第13节查代码、数据和命令；第14节查术语。

## 1 当前在做什么 已经做到哪里

当前方案可以概括为：**借用VISION-SLS的停车场场景及三维视觉观测设计，保留自己的PPO控制器，并接入原SPVC的SBC训练方法。** 不采用VISION-SLS的SLS控制器，也不在停车场训练32维latent。

希望完成的事情是：小车根据摄像头图像绕开障碍，到达指定停车区域；除了观察仿真表现，还要进一步建立能够说明安全性的数学证书。

目前已经完成三个层次的工作，但完成程度不同：

| 层次 | 已取得的结果 | 当前限制 |
|---|---|---|
| 图像理解 | 在同192张保留区域图像上，只适配小投影后，反算位置平均误差26.82→6.62厘米 | 这是平均精度，不是逐点误差上界；旧误差包络仅覆盖54.69% |
| 控制闭环 | 实际图像→DINO→三维观测→PPO→下一状态已跑通；最新候选成功5/15 | 仍有3个任务出界，其他任务也未全部完成停车 |
| 安全训练 | 原SPVC的屏障训练和actor更新已实际执行，模块、动作与梯度接口通过检查 | SBC初始区与危险区没有分开，完整连续状态验证未运行，尚无安全证书 |

因此，当前准确结论是：**感知适配有明确的配对改善，三维前端与SPVC训练模块已经接通，但还没有得到合格的全任务控制器和SBC。**

以下按照“为什么这样设计→数据怎样流动→怎样训练→每轮结果意味着什么”介绍。

## 2 为什么参考VISION-SLS 与原SPVC是什么关系

### 2.1 两篇工作的分工

VISION-SLS研究有视觉误差、部分状态无法直接观察时的机器人控制。与本项目最相关的设计是：不直接把整张图像送进高成本的安全分析，而是先把图像转成一个较小的观测，并建立能够从物理状态计算的对应模型。

其观测关系可以写为：

\[
y_{\mathrm{img}}=p_\theta(\psi_{\mathrm{DINO}}(I))
=C\bar x+F(x)e.
\]

这里：

- I是图像，DINO是预训练视觉特征提取器。
- 小网络p把DINO特征转换成控制使用的观测。
- x是车辆物理状态；\(\bar x\)表示按原场景坐标规则平移后的状态。
- C是状态到观测的矩阵；\(C\bar x\)是没有视觉偏差时的参考观测。
- \(F(x)e\)描述图像观测相对参考观测可能偏多少。

VISION-SLS原后端使用SLS来设计轨迹和基于历史观测的反馈，并根据允许误差为约束预留余量。换成PPO后，这套约束处理不会自动跟着前端一起保留下来。

SPVC则提供另一部分思路：先得到一个可以计算和验证的闭环模型，再训练控制器和随机屏障证书SBC，并检查相应安全条件。本文沿用项目习惯称SPVC，原论文正文框架名为SafePVC。因此，换后端后需要重新完成安全分析，而不是同时继承两篇工作的保证。

**本方案借VISION-SLS做前端及场景，借SPVC做控制器与证书训练后端；不是完整复现任何一篇论文。**

### 2.2 哪些沿用 哪些是本项目新增

| 部分 | 来源与当前处理 |
|---|---|
| 小车状态、动力学、15个任务、规划障碍、相机与遮挡板 | 复用VISION-SLS停车场示例 |
| DINO-G/14、1536维特征、三维投影结构、固定C | 复用VISION-SLS前端；在当前截图上只适配小投影 |
| 状态相关误差范围的思路 | 参考VISION-SLS；当前停车场尚未得到新的可靠误差包络 |
| 三帧观测、两次动作、目标与时钟输入的PPO | 本项目为停车场实现，不是VISION-SLS原控制器 |
| PPO学习阶段的奖励 | 本项目设计，不是论文原规划代价 |
| SBC网络、屏障损失、actor安全更新 | 直接复用本项目原SPVC后端函数，新增停车场接口 |
| 完整连续状态验证和图像误差的安全连接 | 尚未完成 |

这里“复用原后端”指本项目已有仓库版本。原文件在实验前后未变，并不等于所有作者代码版本都完全相同，也不意味着修改场景后自动继承原证书。

### 2.3 与以前AEBS和32维方案的区别

以前AEBS的物理任务主要是距离、速度与制动。停车场需要处理平面位置、朝向、速度以及两维控制，不能直接沿用原权重和成功率。

当前前端不再是32维自由表示和一个复杂的q代理，而是每张图像输出3个数，代理路径使用固定线性模型C。这让两条路径的对应关系更明确，但**维数更少本身不等于更准确或更安全**。

本报告中的26.82→6.62厘米，比较的是停车场同一批图像上的原投影与适配投影，不是与cGAN比较。旧AEBS成功率、旧CP速度残差、当前停车场位置误差也不是同一口径，不能直接排成性能排名。

## 3 整体框架与训练运行的区别

### 3.1 运行时的闭环

```text
车辆在当前状态运动
       ↓
按原一拍延迟取得摄像头RGB
       ↓
冻结DINO提取1536维特征
       ↓
冻结小投影输出3维观测
       ↓
整理最近观测、已执行动作、目标命令和时钟
       ↓
PPO的actor输出转向角速度和加速度
       ↓
原停车场动力学推进下一状态，再重复
```

闭环的意思是，车辆下一次看到的图像由它前面的动作决定，不是在一批固定图片上反复预测。因此，一次较小的感知偏差也可能改变后续路线，产生新的图像和动作偏差。

SBC不串联在运行时动作后面。它不是一个“发现危险就替PPO刹车”的过滤器，而是训练和验证阶段使用的安全评价函数。

### 3.2 为什么还保留一条Cx代理路径

图像路径需要DINO，运行较贵，也不适合直接进入当前SPVC验证器。因此另保留：

```text
对应拍摄时刻的物理状态 → 固定C矩阵 → 3维参考观测
                                          ↓
                             同样的历史整理与同一个actor
```

图像输出和Cx必须处于同一个坐标空间。若图像输出与Cx接近，才有理由研究代理闭环能否代表实际图像闭环；这种接近仍需用数据和误差分析说明。

代理路径用于训练和分析，不代表真实车辆运行时就知道准确位置。它也不是另一套偷偷读取真实状态的控制器：两条路径最后使用相同actor和相同输入组织方式。

### 3.3 训练分成三个阶段

| 阶段 | 输入与目标 | 更新什么 | 固定什么 |
|---|---|---|---|
| 感知适配 | 图像输出尽量接近固定Cx | 小投影网络 | DINO、C、场景 |
| PPO预训练 | 在停车场交互，争取完成任务 | PPO的actor、critic等训练参数 | 三维前端、动力学与任务规则 |
| SPVC安全更新 | 训练屏障及改善屏障条件，同时约束动作偏离 | SBC网络，然后actor | DINO、小投影、C；actor阶段不更新SBC参数 |

当前不是把DINO、投影、PPO、SBC一次性端到端全部训练。分别固定模块，才能判断误差和性能变化来自哪里。

actor是实际产生动作的网络。critic是在PPO训练时估计未来累计奖励的辅助网络。后面的SPVC阶段直接更新actor，不再执行一次完整的PPO策略梯度训练，也没有在这一阶段重训critic。

## 4 停车场任务具体是什么

### 4.1 状态 动作 时间与图像

车辆物理状态包含4个数：

\[
x=[p_x,p_y,\theta,v].
\]

前两个是平面位置，单位米；theta是朝向，单位弧度；v是速度，单位米/秒。动作是转向角速度和加速度，不是AEBS的单个制动量。

| 设置 | 当前采用值 |
|---|---|
| 两维动作范围 | 角速度±π弧度/秒；加速度±4米/秒² |
| 位置范围 | x为[-3.5,0.5]米；y为[-2,1.9]米 |
| 朝向与速度范围 | 朝向[-2π,2π]；速度[-1,2]米/秒，允许倒车 |
| 任务 | 原15个起点及各自目标，不新增起点抖动 |
| 每次动作持续时间 | 0.15秒 |
| 每回合 | 固定30步，即4.5秒 |
| RGB | 原512×512俯视相机，保留原遮挡板 |
| 过程扰动 | 本轮使用0；没有另外假设图像误差均匀或独立 |

动力学是原小车运动方程，使用RK4进行数值积分。可以理解为用更精细的步内计算推进车辆，而不是直接把动作当作位置偏移。

**车辆状态由这个解析动力学推进，PyBullet负责摆放模型和生成图像。** 本实验不是依靠PyBullet车轮接触、打滑、摩擦等完整车辆物理来行驶。因此，它也没有验证真实车辆的轮胎模型误差。

### 4.2 遮挡与坐标处理

黑色遮挡板是原场景的一部分，不是截图损坏。当前保留其位置和0.97透明度参数，不为了让结果更好而删除遮挡状态。

原动力学坐标和渲染坐标相差一个固定平移，截图前要给x方向加3米。Cx也必须使用同样的平移：

\[
\bar x=x+[3,0,0,0]^T.
\]

否则图片和参考观测描述的就不是同一个位置。相关坐标检查已经通过。

三个圆障碍沿用原规划和碰撞检测几何；原渲染脚本没有把它们逐一画成圆柱，本项目也没有新增这些可见物体改变图像。轨迹图中的灰色圆是规划约束示意，不是声称相机画面里一定能看见同样的圆。

### 4.3 怎样才算完成任务

本项目完整成功判定是：整段回合没有碰撞或出界，并且第30步状态进入对应目标区域，满足原目标中的速度等范围。原目标允许终点速度[-1,1]米/秒，不要求严格等于0，因此这里的停车任务成功不能解释为真实车辆已经完全静止。中间经过目标不算最终完成；曾经出界也不能因后来回来而抹掉。

“碰撞”仍采用原离散时刻车中心与圆形规划障碍的判定，不是对整个车身、整个运动过程中扫掠碰撞的连续保证。动作裁剪在原上限内，但不把位置、速度硬裁剪回安全区；否则会隐藏控制器真实的出界。

原示例演示还有一个较窄口径：结束时XY位置到目标且没有碰撞。它不等于上述完整成功。例如最新小步更新候选的代理路径，窄口径7/15，完整口径5/15；另外2个不能自动算成安全成功。

## 5 三维观测表示什么 为什么还需要历史

### 5.1 三维不是把图像压成三个任意数

DINO先将图像转换成1536个特征，小投影为1536→512→512→3，隐藏层使用GELU。输出训练目标是固定矩阵C对物理状态的线性变换。

例如第一个参考观测分量近似为：

\[
y_1=0.976(p_x+3)+0.132p_y-0.172\theta.
\]

它混合了位置和朝向，**不是第一个数就是x、第二个数就是y、第三个数就是速度**。三个数共同编码当前可由图像观察的位姿。

当前C的速度列为0。相同位置、朝向而速度不同，静态渲染可以产生完全相同的图像；仅把输出维数扩大，也不能自动从单帧中获得不存在的信息。

### 5.2 怎样量化感知误差

对同一张图像及准确拍摄状态，计算：

\[
r=y_{\mathrm{img}}-C\bar x,\qquad
e_\infty=\max(|r_1|,|r_2|,|r_3|).
\]

每张图得到一个最大分量绝对误差，再统计均值、95分位和最大值。95分位表示这批样本约95%的误差不超过该数，不是未来95%安全保证。表示误差使用C坐标的数值尺度，不能直接标成米。

为了让结果更直观，另利用C中可逆的位姿部分反算位置和朝向，再与真实标签比较。报告中的6.62厘米是这种**离线反算位置的平均欧氏偏差**，不是某个额外距离头的误差，也不是PPO已经取得的定位安全上界。实际actor仍读取三维观测，不读取这套评价用反算坐标。

### 5.3 PPO为什么看到16个数

为了利用运动变化信息，当前策略输入保留：

| 输入 | 数量 | 通俗解释 |
|---|---:|---|
| 最近三次三维观测 | 9 | 比较前后变化，帮助判断运动状态 |
| 最近两次执行动作 | 4 | 知道刚刚怎样转向、加减速 |
| 指定目标中心 | 2 | 同一个起点也可能要求停到不同地方 |
| 当前步数/30 | 1 | 知道还剩多少任务时间 |

这16个数不是新的16维图像latent。每帧仍是3维，额外部分是历史和已知任务信息。

一拍延迟是：时刻0看状态0；时刻1仍看状态0；时刻2才看状态1。初始时历史用初始观测重复填充，动作历史填0，不编造过去图像。当前没有额外给策略准确位置或真实速度；奖励和诊断可以读取模拟器真实状态，但actor和critic的观测中没有这些额外标签。

### 5.4 F和e怎样理解 当前是否已经实现

可以把F理解为误差范围的大小和形状，e表示范围内可能的方向与幅度。例如仅为说明，假设F=0.1倍三维单位矩阵，e的各分量允许在[-1,1]，则三个观测误差都允许在±0.1内。这是表示坐标的示意数，不是本实验拟合出的误差参数。

这个集合不告诉我们各种误差出现的概率，所以不能自动把e看成独立、均匀或高斯随机数。运行时小车也不知道准确真实状态，不能直接拿真实残差算出e再控制；真实标签只在离线评价和校准中可用。

当前已经计算真实图像相对Cx的残差，并检查作者旧包络；尚未为适配前端得到一个新的可靠F。因此当前实现拥有三维前端和残差测量，还没有完成原公式中误差模型与安全后端的完整连接。

## 6 实验一 先接通场景 再核对视觉迁移

### 6.1 场景接线完成 不等于控制器成功

第一步在原15起点各运行30步固定测试动作，共450次转移、465条含初始状态的记录，不使用PPO或SLS。

实际摆放坐标误差为0，相同状态重复截图像素差为0，仅变速度时截图差为0；原动力学函数体也做了数值对照。固定动作下15个任务均未完整通过，只说明这组开环测试动作不能完成停车，不是新PPO失败。

### 6.2 发现TinyRenderer不适合直接测视觉精度

同147个状态、同DINO和原投影，只改变渲染路径：

| 指标 | TinyRenderer | OpenGL路径 |
|---|---:|---:|
| 平均表示误差 | 4.405239 | 0.343284 |
| 最大表示误差 | 10.437701 | 1.304122 |
| 反算位置平均偏差 | 4.160488米 | 0.232834米 |
| 旧包络覆盖 | 0/147 | 44/147，29.93% |

TinyRenderer中还发现不同状态得到完全相同RGB、却要求不同Cx的有限样本证据。这种情况下，任何确定性单帧网络都无法同时给出不同答案，不能只靠继续训练解决。

因此后续精度和图像闭环改用原OpenGL路径，经Xvfb虚拟显示和Mesa驱动在服务器运行；TinyRenderer仅作预览对照。没有调整相机、移走遮挡板或删掉难例。Mesa仍不保证与作者显卡逐像素相同。

### 6.3 原作者特征准确 重新截图却有迁移误差

作者保存的5000条特征上，原投影反算位置平均误差约1.91厘米。但这不能直接代表当前重新截图的效果。

进一步抽取作者保存数据中的同128个准确状态，配对比较：

| 指标 | 作者保存特征 | 当前同状态OpenGL截图重新提取特征 |
|---|---:|---:|
| 平均表示误差 | 0.025024 | 0.271305 |
| 反算位置平均偏差 | 1.73厘米 | 18.04厘米 |
| 旧包络覆盖 | 126/128，98.44% | 39/128，30.47% |

DINO特征平均余弦相似度达到0.997475，但同一投影输出仍明显不同。余弦相似度描述高维特征方向接近，不能当成“预测准确率99.75%”。这轮没有运行PPO，所以不能把这种偏差归因于PPO训练。

证据表明当前截图分布与原视觉权重存在迁移问题；尚不能把全部原因锁定为某一个驱动或DINO本体。下一步因此只适配投影，而不是同时改控制器。

## 7 实验二 只适配小投影 得到明确的感知改善

### 7.1 数据怎样采集与划分

新采集1024张OpenGL图像，每张与准确状态标签配对。范围为世界x∈[-3,0]米、y∈[-1.5,1.5]米、朝向∈[-3π/4,3π/4]，速度0。静态图像不区分速度，因此这一步不用于学习速度估计器。

位置划为8×8共64个区域，每区域16张，整块区域划分：

| 集合 | 区域 | 图片 | 用途 |
|---|---:|---:|---|
| 训练 | 40 | 640 | 更新小投影 |
| 验证 | 12 | 192 | 选择模型轮次 |
| 测试 | 12 | 192 | 模型保存后评估 |

三个集合位置区域不重叠，跨集合重复RGB为0。这里“未见区域”是指本轮微调未使用，不保证作者历史预训练从未接触这些位置。

### 7.2 怎样训练与选模型

冻结DINO和C，只更新小投影，训练目标为固定Cx。Adam学习率0.0001，120轮，每批128。另从原保存特征中回放512条，且必须来自本轮训练区域，不能混入验证和测试区域。

```text
训练损失 = 新OpenGL图像特征的观测均方误差
         + 0.25 × 原训练区域历史特征的观测均方误差
```

回放用于减少对旧数据的遗忘。C固定，不能通过把C和输出一起缩小制造“误差变小”。训练参数不包含DINO和C。

验证集选择第73轮，而非最后第120轮。保存模型时测试特征编码数为0，之后才编码并评估192张测试图像；没有依据测试结果改选另一轮。

## 8 实验三 训练停车场PPO并切换真实图像闭环

### 8.1 PPO怎样学习

先冻结适配后的感知前端，在Cx代理路径上训练PPO。每回合从原15任务中选择一个，输出两维动作，环境推进车辆，再反馈奖励。选择代理训练是为了先把任务学习与图像误差分开，也避免每个训练步都运行大DINO。

因此，这一步是“代理观测上训练、真实图像上测试”，不是已经进行了真实图像端到端强化学习。两条路径中传给actor的观测格式完全一致。

奖励鼓励向目标靠近、减少终点距离，惩罚碰撞、状态出界、靠障碍太近及过大动作。具体为：

```text
单步奖励
= 10 × 本步缩短的目标距离
− 0.2 × 当前目标距离
− 0.02 × 归一化动作平方和
− 2 × 距障碍圆周不足0.15米的幅度之和
− 20 × 本时刻碰撞标记
− 5 × 各状态越过边界的幅度之和

回合结束：完整成功加30，否则减去10 × 最终目标距离。
```

奖励使用准确物理状态作为模拟训练反馈，类似用标签监督学习；部署策略没有因此获得准确物理状态输入。动作只按原动作范围处理，不硬裁剪物理速度、位置来掩盖失败。

### 8.2 主要配置

| 项目 | 设置 |
|---|---|
| 框架 | SB3 2.4.1、Gymnasium 1.0.0、PyTorch 2.3.1 |
| 训练环境 | 8个CPU环境，单线程；固定种子7 |
| actor与critic | 各两层128单元、Tanh隐藏层 |
| 采样与更新 | 每环境256步；每批256；每次优化10轮 |
| 学习率 | 0.0003 |
| 折扣与GAE | 0.99、0.95 |
| 熵系数 | 0.005，用于保留探索 |
| 首轮实际步数 | 301056 |
| 第二轮 | 在首轮基础上新增700416，累计1001472步 |

两轮之间只增加训练量，没有同时更改奖励、目标、网络、图片或成功标准。实际步数与计划略有差异，是因为程序要补齐完整采样批次。

### 8.3 怎样进行图像闭环测试

每个原任务运行一次确定性actor，固定30步，分别使用Cx和真实图像输入。图像路径的每张图都按实际闭环状态重新渲染，再经过DINO和小投影；没有找一张距离最近的历史图片代替。

同一个PPO分别跑两条路径后，路线可以不同，所以这是同任务、同起点、同控制器的闭环对照，不是每一步物理状态仍然完全相同的静态配对实验。

每条图像回合实际计算30个不同时间索引的观测。时刻0和1因延迟重复初始图像时复用结果；最后动作之后的状态用于最终判定，不再为不存在的下一动作额外算一帧。两轮都覆盖15任务，不挑成功案例。

### 8.5 失败主要集中在哪里

目标为[0,0]的7个任务，第二轮Cx成功5个，图像成功4个；上方目标的07至10号、下方目标的11至13号均未成功。因此，控制器尚未学会所有目标的绕行和入位，不能把所有失败都归因于图像。

例如代理第00号速度峰值2.093888米/秒，第01号2.001459米/秒，超过原2米/秒上限及1e-3判定容差；第05号y达到1.964281米，超过1.9米。为了保持口径，这些没有被改成通过。

另一方面，图像确实会增加差异。基准第14号Cx成功，图像未入位，其终点距离0.249097米，且观测没有超出感知适配区域；扩大采图范围不能单独解释这个问题。第10号图像路径还出现较大偏离。

第二轮450帧中104帧超出了投影适配的空间或朝向范围。静态适配范围比完整运动域窄，例如原起点的y可达到±1.75米，而适配数据只覆盖[-1.5,1.5]米。当前没有把运动状态裁剪回训练区。

这些证据提示需要分别处理控制任务学习、实际观测误差和运动域覆盖。它们不支持“继续多采图就一定解决”，也不支持“换成更多维就一定解决”。

## 9 实验四 接入原SPVC的屏障和控制器更新

### 9.1 SBC到底是什么

SBC可以通俗理解为一个学习出来的风险刻度B：希望从允许起点出发时数值低，在危险处数值高，并且闭环按相应条件演化时，风险在期望意义下不会失控。

这个数**不是未经证明就能叫作碰撞概率**。只有区域要求、下降要求及模型假设等条件一起成立，才能根据相应定理解释安全界。网络文件叫 `sbc.pt`，也不代表它已经是一份有效证书。

本轮原训练尺度采用B非负、初始B≤1、危险B≥20，并使用epsilon=0.1的下降裕量。20来自原训练目标参数0.95对应的尺度选择；设置0.95不等于训练后自然得到95%安全。

原SPVC的核心下降条件针对规定区域和指定扰动模型下的期望，不是要求每一次随机扰动、每个任意位置都严格下降。本轮过程噪声取0，期望计算退化到名义下一状态；这不表示真实图像与Cx的差也变成0。

### 9.2 为什么SBC记录20维

只看当前物理状态还不能唯一决定历史PPO动作：相同当前位置，策略记住的图像和前两次动作不同，输出也可能不同。因此当前实现将这些记忆一起记入分析状态：

```text
SBC增广状态 = 当前物理状态4维 + 原PPO输入16维 = 20维
```

其中4维物理状态供动力学和离线SBC计算，PPO仍只读取后16维。这里的20维不是新视觉表示，更不是给车辆额外安装了真实状态传感器。

这种记录使本轮模型能够明确执行历史移位、动作更新和延迟观测。它也增加连续状态验证难度，不能照搬原AEBS的二维100×100网格。短历史是否足以支持最终图像随机闭环的完整模型，仍需另外分析，不能只凭接口正确就宣布已经解决部分可观测性。

### 9.3 原代码复用到了哪一步

屏障采用原 `Aebs.VT.utils.MLP`，输入改为20维，隐藏层仍16、8，输出1个非负值；当前原实现中非负输出是Softplus，不是名字中“square”所暗示的直接平方。

本轮直接继承、调用原 `VTLearner.train_step_l`、`train_step_p`、`train_epoch`，没有重写屏障损失；区域采样和可微动力学则按停车场适配。原 `train.py`、`verify.py`、`loop.py`、`utils.py` 在实验前后哈希均未改变。

验证部分只调用了原 `VTVerifier.compute_expected_l` 做点值诊断，没有完成原 `Loop.run` 的连续全域训练验证循环，也没有给20维系统伪造一个全覆盖网格。这是训练模块接通，尚不是完整证书验证器迁移完成。

### 9.4 训练数据与配置

使用累计约100万步的PPO作共同基准。每个任务记录30个决策节点，共450个20维代理样本；另存15个准确起点。

每轮先训练屏障100个epoch，再更新actor 1个epoch，批量256，分别为200次和2次优化。使用记录节点、不做网格抖动；这450个点不是独立测试集，也不是全域采样。

保留原屏障学习率0.003、屏障Lipschitz目标4、actor目标2、下降系数1、epsilon=0.1、训练概率参数0.95及本步Lipschitz权重0.001。Lipschitz约束意在限制网络对输入的敏感程度，当前记录的正则值不等于全域形式界已经证明。

危险采样一半在原障碍圆内，一半在原状态边界外。它们与记录历史组合成训练覆盖点，不保证每个历史组合都实际可达。1024个另行采样的危险点均检查为碰撞或出界；这验证采样标签，不验证连续危险域已被覆盖。

### 9.5 两轮只改变actor学习率

第一轮沿用原actor学习率0.05。第二轮从同一基准PPO重新开始，只改为0.0003，屏障和其余配置不变，不从第一轮坏控制器继续训练。

| Cx路径碰撞任务 | 0/15 | 6/15 | 0/15 |
| 图像路径碰撞任务 | 0/15 | 6/15 | 0/15 |

| 图像路径出界任务 | 3/15 | 15/15 | 3/15 |

## 10 为什么SBC下降改善了 仍不能算成功

### 10.1 三类条件必须一起看

450个基准轨迹点上的检查：

| 检查项 | 随机屏障 | 训练屏障后 | 小步actor更新后 |
|---|---:|---:|---:|
| 下一B未减小的节点 | 231/450 | 7/450 | 6/450 |
| 不满足0.1下降裕量的节点 | 450/450 | 197/450 | 183/450 |
| 初始最大B，目标≤1 | 0.772056 | 4.026962 | 4.026962 |
| 初始目标违反 | 0/15 | 15/15 | 15/15 |
| 危险样本最小B，目标≥20 | 0.671269 | 0.355073 | 0.355073 |
| 危险目标违反 | 1024/1024 | 1024/1024 | 1024/1024 |

网络确实学到更明显的沿轨迹下降，但初始位置的数值升高，危险处仍很低。它没有形成所需的“初始低、危险高”的风险刻度，不能拿下降一项代替全部证书条件。

B的数值可以作尺度变换，原验证还涉及归一化；上表检查的是本轮登记的训练目标，不是说所有有效证书的原始输出都必须恰好采用这个尺度。当前更关键的是所查危险样本最小值低于初始最大值，且完整验证没有完成。训练目标未达标也不是证明任何可行证书都不存在。

第一轮大步actor在旧节点上的未下降点甚至只有1个，但真实闭环已经6个任务碰撞、15个出界。它说明**对旧节点优化某个屏障指标，不等于新控制器实际走出的路线更安全**。

所以还检查了小步候选自己新走出的450个代理节点：6个未减小，200个不满足0.1裕量，最差下降差值-0.022807。这里200与上表183来自不同轨迹集合，不能混写。

### 10.2 为什么不能强迫整段轨迹每步都下降0.1

假设起点B≤1，B始终非负，又强迫连续30次每次至少下降0.1，那么最后需要：

\[
B_{30}\le1-30\times0.1=-2.
\]

这与非负要求矛盾。这个例子不是说原SPVC定理错误，而是说明：不能把具有特定适用区域的条件，改读成所有轨迹、所有时刻都必须同样下降。

神经网络还可能偏重时间信息，学到一个沿轨迹变小的“倒计时”，却没有真正区分危险位置。这是需要检查的解释，不是已经证明当前网络只看时钟。危险区域测试正是为了防止只看漂亮的下降曲线。

当前表格的全轨迹严格下降比例是诊断，不是原SPVC危险近带上的完整验证结果，也没有使用原代码≤0.1%阈值宣布本停车场证书通过。

### 10.3 哪些安全前提尚未补齐

目前缺少三条关键证据：

1. **证书函数本身合格。** 当前初始与危险区域目标没有满足，不能先跳过这一步。
2. **图像误差确实被模型覆盖。** 实际图像输出不同于Cx；本轮零过程噪声并没有把这份差异纳入保证，旧包络也不能继承。
3. **规定连续状态域的条件得到可信验证。** 点值检查不覆盖点与点之间，也没有验证所有允许的历史状态组合。

此外，当前实验是原30步停车任务。最终若追求原SPVC式无限时域概率安全，需要明确并验证30步之后的控制与目标保持行为，不能用4.5秒的成功率替代无限时域保证。

因此，当前结果文件中的证书概率为null，意思是“没有给出有效概率界”，不是0%安全，也不是默认100%安全。

## 11 与VISION-SLS有关的另一项工作 状态相关软误差包络

这一节是此前AEBS上的相关尝试，**不是停车场三维前端已经完成的误差建模步骤**。单列是为了说明借鉴了VISION-SLS的哪些方法。

### 11.1 为什么用状态相关半径

以前将所有状态共用一个全局误差半径，容易把某些位置的少数大误差施加到每个位置。VISION-SLS启发我们改为按状态计算误差范围：容易观察的地方用较小半径，遮挡或困难区域允许较大半径。

软包络拟合允许少数样本超出拟合曲线，但给超出量加惩罚。所谓松弛变量，就是记录“这条样本还差多少才被包住”的非负量；它是在**拟合误差范围**时作权衡，不是允许安全证明随意忽略违规。

AEBS这一轮固定DINO、q、PPO和SBC，只拟合图像与代理两条路径的下一速度差，单位米/秒。停车场原论文拟合的是观测空间误差，两者不是同一个物理量。

### 11.2 已运行的结果

复用459条旧同步轨迹，按整条记录分成183条拟合、183条CP参考校准、93条开发评估。拟合使用9个多项式系数的凸软包络，再进行CP参考尺度修正：

| 方法 | 每轨迹等权平均半径 | 93条记录全部帧被覆盖 |
|---|---:|---:|
| 同批公平全局CP参考 | 0.076974511米/秒 | 92/93 |
| 只做软包络拟合 | 0.015752391米/秒 | 7/93 |
| 状态包络加CP参考修正 | 0.047820977米/秒 | 91/93 |

修正后平均半径减小37.87%，但整轨迹覆盖少1条，尾部仍存在损失，不能说无代价改善。只看软拟合的平均半径很小更会误导，因为它只有7条完整记录被包住。

数据已经多次参与开发，采集策略也不是本轮新策略，所以这些是参考计算，不是新部署模型的正式CP契约。183条参考校准即使假设独立同分布，也不满足同时99%覆盖、99%置信的要求；更不能由误差盒推出每步误差独立均匀。

### 11.3 这与当前停车场是什么关系

两项工作都体现“误差随状态变化”的思路，但当前停车场没有新拟合可靠F(x)，没有将这份AEBS速度包络搬进停车场SBC，也没有启用CP。

误差集合告诉我们“允许哪些误差”，概率分布还要告诉我们“各误差多常出现”。有一个包络并不自动得到SPVC期望条件需要的条件分布；覆盖旧记录也不等于所有未来误差序列都不会导致事故。

相关原始指标保存在 `results/state_residual_envelope_20261023_v1`，逐步说明见[状态相关包络实验](CP与SBC安全余量实验_逐步说明.md#十九-状态相关误差包络替换全局半径)。

## 12 当前取得的成果 与不能声称的结论

### 12.1 可以明确汇报的成果

1. 原停车场动力学、渲染、任务、延迟和评价接口已经迁移到当前项目。
2. 完成官方DINO-G/14真实截图推理，发现并隔离了渲染路径差异及视觉迁移误差。
3. 在固定DINO和C的情况下，仅适配小投影，就使同测试图像的位置平均偏差26.82→6.62厘米，均值和尾部同时改善。
4. 完成不额外读取真实速度和位置的历史PPO，实际图像闭环可运行，并有部分任务成功。
5. 三维前端已连接原SPVC的屏障与actor训练函数，发现原actor步长在本次移植中会导致严重退化，小步更新能保留表现并增加一个图像成功任务。
6. 保存了正负实验、源模型哈希、完整轨迹与复算检查，旧AEBS流程和原模型没有被候选覆盖。

### 12.2 暂时不能这样汇报

- 不能说“完整复现VISION-SLS安全控制”，因为没有使用其完整SLS后端。
- 不能说“已证明比cGAN或旧32维方案更好”，因为本轮不是同场景同口径的这组对照。
- 不能说“位置误差最多6.62厘米”，它是平均值。
- 不能说“旧包络覆盖提升就可以拿来认证”，54.69%仍不足，而且只是有限样本覆盖。
- 不能说“PPO已经合格”，当前仅5/15完整成功，仍3个任务出界。
- 不能说“原SBC已通过”，区域条件失败，完整验证未完成。
- 不能说“图像闭环已有95%或无限时域安全保证”，训练目标参数与实际证书不是一回事。

### 12.3 下一步按什么顺序

| 顺序 | 只解决的主要问题 | 进入下一步的依据 |
|---|---|---|
| 1 | SBC区域目标与原下降适用域匹配 | 初始与危险能区分，不再只看旧轨迹下降比例 |
| 2 | 小步控制更新与任务表现 | 固定任务的碰撞/出界不增加，停车表现改善；保留失败候选 |
| 3 | 最终控制器对应的图像—Cx误差模型 | 独立检查适用域、尾部、闭环分布与所需概率假设 |
| 4 | 连续状态及历史闭环验证 | 正确覆盖规定域，而不把450个记录节点当作全域证明 |
| 5 | 对应条件下报告安全界 | 说明概率、时域、初始集、扰动及模型误差覆盖范围 |

这是后续路线，不是上述条件已经成立。当前优先第1步；不再同时更换前端维数、奖励、控制算法和证书规则来试图解释改善。

## 14 术语对照与常见疑问

| 术语 | 在本报告中的通俗解释 |
|---|---|
| 物理状态 | 车辆真正的位置、朝向和速度，仿真器知道，图像策略不直接知道 |
| 观测 | 车辆收到的信息，不等于完整真实状态 |
| latent或低维表示 | 用少量数字代替图像；当前每帧3维，含义受Cx目标约束 |
| DINO | 预训练图像特征提取器；本轮冻结，不从头训练 |
| 投影网络 | 把1536维DINO特征转成3维观测的小网络 |
| Cx代理 | 用已知物理标签计算同坐标观测，供模拟训练和分析 |
| 感知残差 | 图像观测减对应Cx，说明两条前端差多少 |
| 过程扰动 | 动力学受到的额外影响；与感知误差不是同一项 |
| F(x) | 随状态变化的误差范围模型；当前停车场尚未重新可靠校准 |
| 包络 | 尝试包住残差的上界曲线或范围，不自动是概率分布 |
| 松弛变量 | 拟合中给暂时未包住的样本记录超出量，并加惩罚 |
| 凸包络拟合 | 在选定函数形式下求解一个较易处理的优化问题；拟合求解正确不等于未来残差必被覆盖 |
| CP | 利用校准数据给评分阈值的统计方法；本停车场训练未启用 |
| 覆盖率 | 数据中残差落入范围的比例，不等于车辆安全率 |
| 闭环 | 动作改变下一状态和下一图像，策略再据此行动 |
| 一拍延迟 | 现在收到的图像来自前一时刻 |
| PPO | 强化学习算法；先通过任务奖励训练动作策略 |
| actor与critic | actor产生动作；critic在PPO训练中估计未来奖励 |
| SBC或屏障 | 用于安全分析的函数，满足全部条件后才可解释为证书 |
| 期望下降 | 对指定随机模型平均后满足条件，不要求每种随机结果都下降 |
| epsilon | 要求多大下降裕量；必须结合尺度、适用域和终止条件解释 |
| 增广状态 | 把影响未来动作的历史、动作、任务信息也记录进分析状态 |
| sampled诊断 | 只检验记录点，尚未覆盖连续点之间及所有允许情况 |
| checkpoint | 某次保存的模型；保存成功不代表认证成功 |
| holdout或保留集 | 本轮不用于训练或选模型的数据；其隔离范围必须说明 |
| RMSE | 平方误差平均后开根号，对大误差更敏感 |
| 95分位与最大值 | 前者描述多数样本尾部，后者描述本批最坏点，都不是未来全域界 |
| SLS与SPVC | 前者是参考论文的控制设计路线；后者是当前接入的证书训练路线 |

**为什么用三维，却不是直接把三个数送给PPO？** 因为当前保留延迟且单帧不包含速度，使用短历史和动作信息帮助控制。三维说的是单帧前端输出。

**为什么有PPO还需要SBC？** PPO的奖励优化不自动给出安全证明。SBC希望补充条件明确的安全分析，但当前尚未成功。

**为什么SBC不在部署时替PPO纠错？** 本方案没有安全过滤器。SBC通过训练和验证影响控制器是否可接受，不是运行时额外动作层。

**现在能否说原方法不能迁移？** 不能。已证明模块能接，首轮数值和区域训练尚不合格；这既不是成功认证，也不是不存在任何可行SBC的证明。

> 我们把VISION-SLS的停车场及三维视觉观测设计接入现有项目。首先核对了渲染和图像迁移，固定DINO与状态映射C，仅适配小投影，使同测试区域的位置平均偏差从26.82厘米降到6.62厘米。随后训练不额外读取真实速度、位置的历史PPO，并接上原SPVC的屏障与actor训练函数。大步更新出现明显退化，改成小步后保留代理表现，真实图像任务成功由4/15到5/15。但当前仍有出界，屏障也没有满足初始与危险区域分离，完整连续验证和视觉误差安全覆盖尚未完成。因此，本阶段取得了感知改善与新闭环训练接口的实测进展，还没有取得SBC证书；下一步集中解决证书区域与下降条件的匹配。
