# 车道 PPO 的训练流程、约束与 CP 误差说明

更新日期：2026-11-16。

本文解释当前车道非线性观察实验所沿用的旧 PPO：它怎么训练，输入输出是什么，奖励和约束有哪些，CP 误差在哪一步使用，以及最后的安全保证来自哪里。本文是对已有代码和模型记录的说明，没有重新启动训练或修改控制器。

**核心结论：这个 PPO 使用带随机观察误差的车辆仿真训练。误差集合影响训练时的观察，但 PPO 本身没有强制执行 CP 覆盖条件或 SBC 安全条件。后续的新轨迹校准和连续域 SBC 验证，才把候选控制器与条件安全保证连接起来。**

## 1. 本文说的是哪个 PPO

车道实验保留过多个控制器，名称容易混淆：

| 版本 | 主要含义 | 是否为本文对象 |
|---|---|---|
| `ppo_semantic` | 使用归一化真实状态训练的 PPO | 否 |
| `ppo_image` | 使用带随机误差的状态观察训练的 PPO | 是 |
| `ppo_residual` 等 | 在基础控制律上学习残差的另一条实验分支 | 否 |

当前非线性观察实验沿用的 actor，与旧 `ppo_image/actor.pt` 的 SHA-256 相同：

```text
b412c6ed5298540cefb532b1e8e47b046f06fd37df1353b406a04d0957028de2
```

因此它确实复用了那个旧控制器，没有在非线性前端训练完成后重新做 PPO。新的运行时系统在旧 actor 前面增加了非线性解码器，这会改变从图像到动作的完整映射，但不改变 actor 的权重。

证据：[旧 PPO 训练记录](../../artical-F122/results/lane_keeping_20261105/ppo_image/metrics.json)、[旧 PPO 完整模型](../../artical-F122/results/lane_keeping_20261105/ppo_image/ppo_model.zip)、[非线性实验冻结协议](../../artical-F122/results/lane_nonlinear_trajectory_20261115_v1/protocol.json)。

## 2. 车辆任务是什么

物理状态为两个量：

\[
s=(e,\theta).
\]

e 是车辆相对车道中心的横向偏差，单位米；θ 是相对道路切线的航向误差，单位弧度。车辆速度固定，策略只控制前轮转角。

| 项目 | 当前任务设定 |
|---|---|
| 速度 | 4 m/s |
| 仿真步长 | 0.1 s |
| 轴距 | 2.6 m |
| 前轮转角上限 | ±0.45 rad，约 ±25.8° |
| 横向安全边界 | ±0.85 m |
| 航向安全边界 | ±0.30 rad，约 ±17.2° |
| 默认初始横向范围 | ±0.25 m |
| 默认初始航向范围 | ±0.06 rad |
| 道路曲率 | −0.01、0、0.01，每回合选择后固定 |
| 每回合时长 | 最多 80 步，即 8 s |

车辆离散更新为：

\[
e_{t+1}=e_t+4\times0.1\sin\theta_t,
\]

\[
\theta_{t+1}=\theta_t+\frac{4\times0.1}{2.6}\tan\phi_t
-4\times0.1\kappa.
\]

κ 表示道路曲率。这里没有纵向速度控制，也没有把轮胎侧滑、执行器时延或额外过程噪声加入当前保证模型。

上述初始范围是当前环境默认值。训练入口支持显式扩大训练初始范围，但旧 `metrics.json` 没有完整保存这类命令行配置，不能仅凭今天的默认值断言当时所有参数都完全按默认执行。当前正式校准和验证协议的初始范围则有单独记录。

来源：[车辆模型与任务定义](../../artical-F122/Aebs/lane_keeping/core.py)。

## 3. PPO 训练时每一步实际做什么

### 3.1 先把物理状态归一化

定义网络状态坐标：

\[
x=(e/0.85,\theta/0.30).
\]

归一化让两个量都在安全边界附近达到 ±1，避免把米与弧度按原始数值直接混在一起。

### 3.2 给观察加随机误差

训练使用 `NoisyLaneEnv`，控制器实际收到：

\[
o_t=(x_{t,1}+\delta_{t,1},\ x_{t,2}+\delta_{t,2},\ \kappa/0.01),
\]

其中每次观察生成时，从盒子里抽取：

\[
\delta_{t,1},\delta_{t,2}\sim\operatorname{Uniform}[-r,r].
\]

例如真实 e=0.17 m，对应 x₁=0.2；若抽到 δ₁=−0.03，策略收到的第一维就是 0.17，相当于认为横向偏差为 0.1445 m。这个例子只是解释归一化误差的作用，不代表旧训练半径已经确认为 0.03。

加误差的是观察，车辆动力学仍从真实仿真状态更新。不能把它理解为每一步直接把车辆位置随机移动了一段距离。

### 3.3 策略输出转向动作

策略网络接收上述三个数，输出一个归一化动作 a。实际执行前裁剪到 [−1,1]，再转换成转角：

\[
\phi=0.45\operatorname{clip}(a,-1,1).
\]

因此即使网络原始输出超过范围，车辆模型也不会执行超过 ±0.45 rad 的转角。部署和验证使用导出的确定性动作均值，不采样 PPO 的随机动作分布。

### 3.4 更新车辆，计算奖励和失败状态

车辆根据当前真实状态、执行转角和曲率更新，环境计算居中表现、转向代价，并检查是否越界。PPO 利用交互得到的观察、动作、奖励等数据反复更新策略。

| 步骤 | 输入 | 输出 |
|---|---|---|
| 归一化 | 真实仿真 e、θ 和已知 κ | 网络坐标 |
| 注入误差 | 网络坐标、训练误差盒 | 带误差的观察 o |
| 决策 | o、策略参数 | 归一化动作 |
| 动作限制 | 原始动作 | 合法转角 φ |
| 车辆更新 | 真实状态、φ、κ | 下一真实状态 |
| 训练反馈 | 下一状态和动作 | 奖励、越界标记、交互数据 |
| PPO 更新 | 收集的交互数据 | 新策略参数 |

这段训练没有逐步生成道路图像、运行 DINO 或计算新的视觉投影。`ppo_image` 的名字表示为带视觉误差的观察设计，并不表示当时每个 PPO 训练步都直接接收图像。

来源：[环境与噪声模型](../../artical-F122/Aebs/lane_keeping/env.py)、[PPO 训练入口](../../artical-F122/Aebs/lane_keeping/train_ppo.py)。

## 4. 奖励里给了哪些要求

当前代码的每步奖励为：

\[
R_t=1
-0.5(e_{t+1}/0.85)^2
-0.2(\theta_{t+1}/0.30)^2
-0.02(\phi_t/0.45)^2.
\]

| 奖励项 | 含义 |
|---|---|
| +1 | 鼓励持续保持运行 |
| 横向误差平方惩罚 | 鼓励靠近车道中心 |
| 航向误差平方惩罚 | 鼓励朝向与道路一致 |
| 转角平方惩罚 | 抑制过大的转向 |

如果更新后的状态满足 |e|>0.85 m 或 |θ|>0.30 rad，再额外扣 10 分并结束回合。

这里惩罚的是转角幅值，没有显式惩罚相邻时刻转角变化率。因此可以说鼓励较小转向，不能直接写成已经施加转向速率约束或严格平顺性约束。

“成功”是 80 步内没有越界。代码没有要求最后必须满足某个更小的居中阈值，也没有证明无限时间收敛。车辆即便始终保持一个较小偏差，只要不越界，也可计为这一评价中的成功。

来源：[奖励函数](../../artical-F122/Aebs/lane_keeping/core.py)、[终止与成功条件](../../artical-F122/Aebs/lane_keeping/env.py)。

## 5. 硬限制、软惩罚和证明条件有什么区别

| 项目 | 在 PPO 初训中的实现 | 是否自动保证 |
|---|---|---|
| 最大转角 | 实际执行前裁剪 | 保证执行转角不超过限制 |
| 横向与航向边界 | 越界后惩罚并终止 | 训练可以越界，不保证策略永远安全 |
| 车道居中 | 奖励中的平方惩罚 | 鼓励，未形成逐状态硬条件 |
| 转向幅值较小 | 奖励中的动作惩罚 | 鼓励，最大值另由动作裁剪限制 |
| 所有允许观察误差下安全 | 随机采样误差进行训练 | 单靠抽样训练不能保证 |
| SBC 初始、危险和漂移条件 | 初训 PPO 目标中没有这些项 | 需要后续训练与验证 SBC |

初训没有在线 CBF/QP 过滤器，也没有在每次 PPO 更新后调用验证器强制检查安全。动作盒只限制车辆能打多大方向，并不保证这个方向一定安全。

PPO 配置中的 `clip_range=0.2` 约束策略优化中的概率比变化，不能解释成横向偏差限制 0.2 m、转角限制 0.2 rad，或安全概率 80%。

## 6. 有无使用 CP 误差：准确答案与历史缺口

### 6.1 使用的是误差盒，不是 CP 定理本身

训练代码读取 `--cp` 指定文件中的 `error_model.radius`，据此创建均匀盒噪声模型。它不在 PPO 损失中计算 CP 分位数，不在每次更新时重新校准，也没有通过读取文件就证明每一步真实视觉误差满足该盒。

因此准确表述是：**训练使用了外部给定的观察误差范围，来提高候选策略对观察扰动的适应能力。这个范围若来自校准，需要另行说明校准来源和有效性。**

CP 约束的是覆盖概率，不规定误差在盒内均匀分布。均匀采样是训练策略，并不是 CP 推导出来的误差分布。

### 6.2 旧 PPO 的具体训练半径尚不能完全追溯

保存的训练记录指向：

```text
/tmp/lane_cp_cons.json
```

本次核对时该临时文件不存在，训练报告也没有内嵌其内容或哈希。因此能确认 `mode=noisy` 且使用了外部误差盒，但不能从这一记录完整还原训练半径和该文件来源。

归档保留的 [cp_conservative.json](../../artical-F122/results/lane_keeping_20261105/cp/cp_conservative.json) 半径为 0.30，文件自己注明是保守经验包络，并非新的 95% 分割 CP 分位数。它可能有助于理解当时实验背景，但缺少与临时文件的绑定证据，不能直接认定两者完全相同。

这里是记录完整性的限制，不等于当前 actor 无效。当前 actor 权重仍能被固定、重新采集轨迹和重新验证；只是不能声称已经逐项复原当年的训练过程。

### 6.3 三类半径不能混为一谈

| 半径用途 | 当前可确认的内容 |
|---|---|
| PPO 训练噪声半径 | 来自旧临时文件；具体值尚未完全追溯 |
| 早期 SBC 验证半径 0.08 | 是后续声明的验证包络，不足以反推出 PPO 训练用的 r |
| 非线性版本新轨迹 CP 半径 0.0875379788 | 在冻结新观察模型、旧 actor 与新解码接口之后，重新采集轨迹得到 |

新轨迹 q 并没有在时间上“倒过来”用于当年的 PPO 训练。PPO 训练半径与最终验证半径可以不同，是否合法取决于最终系统在最终集合下是否真的完成有效验证。

### 6.4 为什么随机误差训练不能代替鲁棒验证

即使训练随机抽到许多盒内误差，也可能没有抽到某个危险状态与某个极端误差的组合。平均回报较高，也允许少量严重失败被其他高奖励轨迹抵消。

而后续当前 SBC 的逐后继检查要求：对适用域中的全部允许误差，后继都满足指定条件。这个“全部”与训练时“随机见到一些”是本质不同的要求。

## 8. 原 PPO 如何接入现在的非线性观察系统

非线性版本的实际数据流为：

```text
真实道路图像
    ↓ 冻结 DINO + 已联合训练的视觉投影
低维观察 y
    ↓ 已训练的非线性代理 h 的显式逆映射
解码观察 h⁻¹(y)
    ↓ 加入已知道路曲率
原 PPO 的确定性 actor
    ↓ 动作裁剪与角度换算
车辆动力学
```

旧 actor 仍接受两个估计状态坐标和曲率，所以可以通过解码接口复用。它没有读取真实位置来代替图像估计。

新的原始代理误差是 y−h(x)。非线性版本的轨迹 CP 使用：

\[
s_j=\max_{t<80}\|h^{-1}(y_{j,t})-x_{j,t}\|_\infty.
\]

相应低维误差集合为：

\[
\mathcal E_y(x)=\{h(x+\delta)-h(x):\|\delta\|_\infty\le q\}.
\]

利用显式可逆性，若实际误差属于这个集合，就有 h⁻¹(h(x)+ε)=x+δ。因此后续验证器可以检查原 actor 在所有归一化观察误差 δ 下的后继，不必假设新代理仍是线性 Cx。

完整步骤见 [车道非线性神经代理实验](车道非线性神经代理_联合训练与完整验证_20261115.md)。

## 9. 最后安全保证从哪里来

| 环节 | 负责什么 | 单独不能推出什么 |
|---|---|---|
| PPO | 获得能完成控制任务的候选策略 | 所有误差下都安全 |
| 轨迹 CP | 在对应假设下校准一条新轨迹的全程误差覆盖 | 该控制器在集合内一定安全 |
| 神经 SBC 与连续域验证 | 检查允许后继是否满足安全条件 | 实际视觉误差必定在集合内 |

当前逐后继证书检查的关键关系是：初始 B≤1，危险处 B≥20，沿全部允许活跃后继 B 不增。如果一条实际轨迹满足误差集合前提，则 B 从不超过 1 出发，不可能进入要求 B≥20 的危险集。验证需要包含可能的首次越界后继，并明确证明域和时域。

非线性版本记录为：199 条校准、q=0.0875379788；100 条独立留出中 96 条全程在集合内，100 条均未越界；三个曲率下的新条件 SBC 数值审计通过。

其中 4 条留出轨迹的误差曾超出集合，所以虽然实际未越界，也不能称为这份误差前提下的逐轨迹保证。CP 的边际概率结论还依赖冻结模型、注册采样分布及轨迹分数可交换性等条件；不能由这一次 96/100 直接证明任意场景的安全概率。

如果只在校准后证书通过时发布系统，发布选择的条件概率也需要单独分析。当前连续域数值检查没有向外舍入的全浮点实现证明，因此不称为整个运行栈的严格形式化保证。

结果来源：[新闭环报告](../../artical-F122/results/lane_nonlinear_trajectory_20261115_v1/report.json)、[新 SBC 审计](../../artical-F122/results/lane_nonlinear_trajectory_20261115_v1/verification/certificate.json)。

## 10. 这个控制器与实验有哪些限制

1. **训练观察是随机盒噪声。**没有完整模拟真实视觉的偏差、长尾、时间相关性和状态相关性。后续真实图像闭环校准因此非常必要。
2. **曲率作为已知量。**它不负责从图像估计曲率，也没有覆盖任意连续变化道路。
3. **固定速度与简化动力学。**提高速度、加入侧滑或延迟后，必须重新核对训练、校准和证明。
4. **有限时域与初始范围。**当前保证针对注册的 80 步和初始分布，不自动扩展到无限时间、任意初始状态。
5. **部署动作是确定性的。**重新启用随机动作采样会改变被验证系统，不能直接套用原确定性 actor 的证书。
6. **成功定义偏重不越界。**若要研究严格居中、转向平顺或到达目标，需要增加相应指标，必要时修改训练目标并重新评价。
7. **训练来源存在历史缺口。**权重可追溯，但临时误差合同未完整归档，具体训练半径尚不能完全恢复。
8. **新前端适配不等于新策略综合。**目前证明新前端与旧策略可以衔接，还没有证明重新针对非线性观察训练的策略能否更好。

## 11. 如果要重新训练，合理顺序是什么

这部分仅说明后续研究流程，不表示本文已经执行了重训。

1. 冻结视觉前端和非线性代理，确定控制器实际接收的观察与运行时解码。
2. 使用训练／开发数据确定训练误差模型。可以结合误差盒训练和真实图像闭环评价；训练噪声不必冒充最后的正式 CP。
3. 按相同 PPO 方法和明确预算训练新控制器，保存完整配置、源码、噪声合同与哈希。
4. 为新控制器训练神经非负 SBC，利用开发验证发现的反例继续改进。
5. 控制器与前端最终冻结后，重新采集独立完整轨迹，做正式轨迹 CP。
6. 用最终 CP 集合完成对应神经 SBC 的连续域审计，再做独立留出评价。

如果反例反馈修改了控制器，实际访问状态和误差分布可能变化，旧控制器的轨迹校准不能直接视为新系统的正式校准。新一轮正式校准前应结束开发选择；看过最终留出再调模型后，需要另设未使用的最终评价。

为了比较收益，线性与非线性前端都应有相同策略训练和 SBC 综合预算的版本，同时保留旧控制器固定时的前端对照。
